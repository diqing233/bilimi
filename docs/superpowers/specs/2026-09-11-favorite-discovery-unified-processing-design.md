# 收藏夹发现统一处理弹窗设计

日期：2026-09-11

## 目标

将 B 站收藏夹发现中的“疑似 bilimi 收藏夹”与“已绑定收藏夹名称变更”统一收敛为一个可处理弹窗。备册和查看详情使用同一份待处理列表，但职责严格分开：查看详情只处理已选条目；备册在处理完成后继续现有备册流程。

本设计覆盖需求账本 `docs/requirement-ledgers/2026-09-11-one-click-backup-unbound-notice-order.md` 的 R019-R027。

## 入口

### 查看详情

右侧收藏夹区域保留精简发现摘要及“查看详情”“暂不提醒”。移除列表下方原有的长提示（“检测到 B 站中有…疑似 bilimi 工作夹…”）。点击“查看详情”打开统一弹窗。

- 标题：`发现待处理的 bilimi 收藏夹`
- 主按钮：`开始处理`
- 处理后不启动备册。
- 右上角 `×` 只关闭弹窗。

### 备册预检

当用户点击原有备册入口、且发现存在需要处理的疑似项或已绑定名称变更时，显示同一统一弹窗。

- 标题和列表布局与查看详情入口一致。
- 主按钮：`确认处理并继续备册`
- 处理成功后继续原有备册请求、精确 ID 绑定和最终核验。
- 右上角 `×` 完整取消本次备册：不生成草稿、不改名、不启动备册。

## 弹窗布局与文案

正文固定说明：

> 发现以下 B 站收藏夹需要你确认处理。疑似收藏夹将生成本地草稿；已绑定收藏夹的名称变更将同步修改到 B 站。不会自动绑定或创建收藏夹。

查看详情入口追加：`处理不会启动备册。`

备册预检入口追加：`确认处理后将继续执行备册。`

顶部选择区为：`☑ 全选（共 N 项）`。

弹窗打开时，所有可处理条目默认选中。全选跨全部可见组生效；部分勾选时使用不确定态。用户可取消勾选任意条目。

条目按类型分组：

1. `疑似 bilimi 收藏夹（N）`：条目展示远端名称和视频数量。
2. `已绑定收藏夹名称变更（N）`：条目展示 `旧名称 → 新名称` 和视频数量。

两类同时存在时，疑似项在上、改名项在下，两组之间用一条水平分隔线隔开。只有一类时，不渲染另一组或分隔线。

底部不显示“取消”按钮；仅显示该入口对应的唯一主按钮。放弃本次操作一律点击右上角 `×`。

## 处理语义

单次点击主按钮按已勾选条目类型分别处理：

- 疑似项：只生成对应的本地草稿；不自动绑定、不创建 B 站收藏夹、不开始备册。
- 已绑定名称变更：只将该已绑定 B 站收藏夹改为本地工作夹所要求的名称；不重新绑定、不创建收藏夹、不处理视频同步。

未勾选条目不产生任何本地或 B 站副作用。

查看详情入口完成处理后保持在详情上下文，显示处理结果，不触发备册。备册预检入口只有在本次处理达到可继续的终态时才继续既有备册；该后续流程保持现有的创建、精确 ID 登记和最终核验规则。

## 状态、失败与保护边界

- 处理期间主按钮禁用并显示进行状态，关闭操作遵循既有破坏性操作锁，避免重复提交。
- 处理结果按疑似草稿创建成功/失败与改名成功/失败分别反馈；失败项不得伪装为完成。
- 备册入口若存在不能安全继续的处理失败，停止后续备册并保留失败说明与重试入口；具体反馈复用当前备册失败规则，不扩大 B 站写入范围。
- 发现提示的账号级持久化与“暂不提醒”规则不变；处理动作只更新成功处理所需的本地发现/工作夹状态。
- 维持精确 ID 绑定原则：名称识别的疑似项生成草稿，但不因本弹窗直接成为正式绑定。
- 不改变新建、重命名、删除、刷新、备册后的只读发现触发链路。

## 回归验证

自动化覆盖：

1. 查看详情与备册预检均打开同一弹窗，且主按钮文案和关闭语义正确。
2. 两类同时存在时默认全选、全选跨组、部分选中、上下分组和分隔线正确；单类时无空组与分隔线。
3. 查看详情的“开始处理”仅生成已选草稿并改名已选绑定项，不调用备册。
4. 备册的“确认处理并继续备册”先处理已选项，再沿用原有备册调用；右上角 `×` 完整取消且无副作用。
5. 未选项不生成草稿、不改名、不进入备册目标。
6. 处理失败时不触发不安全的后续备册，失败项与成功项反馈准确。
7. 原有“暂不提醒”、跨网页显示、刷新发现、备册进度和精确 ID 绑定测试持续通过。

真实 Electron 验收：

1. 在同一账号下分别制造仅疑似、仅改名、两类同时存在的发现结果，检查弹窗文字、默认勾选、分组、分隔线、全选和唯一主按钮。
2. 从查看详情处理两类项目，确认仅创建草稿/改名，不启动备册。
3. 从备册入口处理两类项目，确认处理后继续备册；点击 `×` 确认无任何处理或备册发生。
4. 确认右侧长提示已移除，精简摘要、查看详情、暂不提醒和跨网页持久化仍正常。
