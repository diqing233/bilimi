# 运行状态模型摘要设计

## 目标

在不改变 DeepSeek、转写队列和 GPU 探测行为的前提下，压缩全局后台任务详情，并让转写状态明确显示所用模型与可信的 GPU 就绪状态。

## 显示规则

- DeepSeek 运行详情第一行显示 `模型：<模型> · 已开启：<功能简称>`。
- DeepSeek 只列出已开启功能，简称固定为“趣评、总结、宠物、批阅、整理”；没有开启项时显示“已开启：无”。
- DeepSeek 第二部分另起一行显示 `执行任务：`，随后逐行显示活动任务；不再重复“DeepSeek 工作中”，也不显示功能长说明。
- 转写后台详情和转写状态灯悬浮提示均显示 `模型：<模型显示名>`。
- 正在运行的任务优先使用任务入队时保存的 `transcriptionModelId`，否则使用当前账户选择的模型。
- GPU 探测结果为 `available` 且对应当前模型时，模型行追加 `GPU 已就绪`。
- 正在运行的任务实际设备为 CUDA 时，即使探测状态尚未返回，也追加 `GPU 已就绪`；不因仅选择 faster-whisper 模型就声称 GPU 已就绪。
- 红框内的状态灯短标签保持现状，避免窄侧栏被模型名称撑宽。

## 范围

只修改全局状态文本的构造与对应测试，不改设置页、任务调度、模型选择、GPU 探测、转写执行和 DeepSeek 功能开关。

## 验收

- DeepSeek 活动状态详情为两段：精简模型/开启功能、执行任务。
- 转写运行、排队、完成、失败和空闲状态的详情均包含模型。
- 状态灯悬浮提示复用同一详情，因此能看到模型；GPU 确认可用或实际使用 CUDA 时能看到“GPU 已就绪”。
- 未确认 GPU 可用时不显示“GPU 已就绪”。
