# bilimi v1.0.0 Release Design

## Goal

Publish the current project as bilimi `v1.0.0` for Windows x64, using the supplied square Xiaomiao artwork as the application icon, with a comprehensive README that documents every user-facing page and workflow.

## Release Scope

- Set the application and lockfile version to `1.0.0`.
- Preserve the supplied artwork as the canonical icon source under `electron/assets/`.
- Generate matching runtime, taskbar, executable, installer, tray, and build icons from that source.
- Rewrite `README.md` as the primary user manual rather than a short project overview.
- Build and install the Windows NSIS package.
- Validate development, production preview, and installed-package forms against `docs/release-checklist.md`.
- Push the completed release commit to GitHub `main`.
- Create GitHub Release `v1.0.0` and attach the Windows installer so it appears in the repository Releases list.

## Icon Pipeline

The supplied image is square and already includes its intended rounded visual background. It will be stored as `electron/assets/bilimi-icon-source.png` and processed by `scripts/generate-app-icon.mjs` without an additional portrait crop. The generator remains the single source of truth and produces:

- `electron/assets/bilimi-avatar.png` for non-Windows runtime surfaces.
- `electron/assets/bilimi.ico` for Electron-local Windows use.
- `build/icon.png` for build metadata and inspection.
- `build/icon.ico` for Windows executable, taskbar, tray, and NSIS packaging.

The ICO retains the full size ladder: 16, 24, 32, 48, 64, 128, and 256 pixels.

## README Information Architecture

`README.md` will be a detailed Chinese user manual with a navigable table of contents. It will cover:

1. Product positioning, system requirements, download, installation, first launch, upgrade, and uninstall.
2. Main browser window, address/navigation controls, Bilibili login, multi-tab behavior, refresh, and page-state limitations.
3. Assistant workspace shell and each top-level page: `批阅`, `札记`, `掌库`, and `设置`.
4. `批阅`: current-video context, like, coin/triple action, favorite, danmaku/comment draft, progress, success, failure, and account-side confirmation.
5. `札记`: manual transcript, local audio transcription, note generation, copy/save behavior, queue states, cancellation, retry, and archive entry.
6. `档案库`: browsing saved records, versions, reopening, copying, deletion, and recovery behavior after interrupted transcription.
7. `掌库`: ledger creation, draft saving, synchronization, classification types, target-count rules, old-favorite scanning, preview, manual correction, DeepSeek review, confirmation, protection, and reorganization.
8. `设置`: diagnostics, DeepSeek, classification strategy, pet behavior, review actions, close behavior, persistence, reset, and security notes.
9. Xiaomiao floating window: wake/drag/open-assistant/shortcut behavior, visual states, fullscreen handling, and troubleshooting.
10. Local media toolchain and transcription dependencies included in the installer.
11. Privacy, credential handling, automation boundaries, known limitations, troubleshooting, developer commands, packaging, security reporting, and license.

Each page section will state where to enter, what is visible, the normal operation sequence, feedback states, persisted data, prerequisites, and known failure paths. Claims will be derived from the current code and tests; undocumented or uncertain behavior will not be invented.

## Version And Release Metadata

- `package.json` and the root package entry in `package-lock.json` use `1.0.0`.
- README download links point to tag `v1.0.0` and the generated installer filename.
- GitHub Release tag: `v1.0.0`.
- GitHub Release title: `bilimi 1.0.0`.
- Release notes summarize the complete current product rather than implying every capability was added in one commit.

## Verification

Automated verification includes icon-generator tests, packaging-configuration tests, the complete test suite, production build, and package inspection. Release verification follows `docs/release-checklist.md` in this order:

1. Development form: launch with `npm run dev` and exercise the critical path.
2. Preview form: build, launch with `npm run preview`, and repeat the critical path.
3. Installed form: build the NSIS installer, install it, launch the installed application, and repeat the critical path.

The installed package must expose the preload API and contain `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`, the whisper runtime, and `ggml-small.bin`. Any step that requires a real Bilibili login, external account mutation, a valid DeepSeek key, or subjective visual confirmation will be reported explicitly rather than represented as automatically verified.

## Git And Publication

All files for this requirement will be staged and committed together once, in accordance with the repository instructions. The resulting commit will be pushed to `origin/main`. Only after the push succeeds will the `v1.0.0` GitHub Release be created and the verified installer uploaded.

No force push, history rewrite, or unrelated cleanup is in scope.
