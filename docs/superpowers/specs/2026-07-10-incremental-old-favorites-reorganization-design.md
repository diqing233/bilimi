# 二次整理旧藏的增量保护与重新整理设计

## 背景

当前“整理旧藏”会重新扫描全部来源收藏夹，并重新计算每条视频的分类。系统能够避免把视频重复加入同一个目标收藏夹，但不能识别“这条视频已经由用户确认整理过”。当分类规则、收藏夹配置或 DeepSeek 判断发生变化时，旧视频仍可能进入新的整理计划，导致二次整理对既有结果产生不必要的影响。

本设计把普通二次整理改为增量整理：已成功整理的视频默认受到保护，只处理新增、待分类和上次失败的视频。同时提供显式的“重新整理这些收藏”入口，让用户可以临时把当前来源范围内的已整理视频重新纳入本轮，并按照后台的单目标、最多双目标或最多三目标设置收敛 Bilimi 收藏夹归档。

## 目标

- 普通二次扫描不重新判断已成功整理的视频。
- 新增收藏、未成功完成整理的收藏和待分类收藏继续进入本轮整理。
- 扫描概览明确展示已保护并跳过的数量，不新增独立的冻结列表。
- 用户可以仅针对当前勾选的来源收藏夹，临时重新整理其中已保护的视频。
- 重新整理严格遵守 `favoriteArchiveMultiMode` 的目标数量限制。
- 单目标模式下，一条视频最终只能保留在一个 Bilimi 收藏夹中。
- 重新整理只收敛 Bilimi 管理的收藏夹，不删除、移动或取消用户原有普通收藏夹中的视频。
- 执行采用“先加入、后移出”，避免中途失败导致视频失去 Bilimi 归档。

## 非目标

- 不因为后台设置变化自动重排所有历史收藏。
- 不提供永久解除全部保护的总开关。
- 不把已保护视频长期展示在归档预览中。
- 不自动恢复用户从 B 站手动移除的历史 Bilimi 归档。
- 不支持把视频的最终 Bilimi 目标清空；没有选定真实目标时，本轮不执行该视频。
- 不删除用户创建的普通 B 站收藏夹，也不改变视频在普通收藏夹中的成员关系。

## 用户可见术语

内部可以使用“保护记录”或“冻结记录”，但界面不使用“冻结”作为主要文案，避免让用户误以为 B 站收藏夹被锁定。

界面统一使用：

- `已整理跳过`：之前已确认整理，本轮保持原归档。
- `重新整理这些收藏`：把当前勾选来源中的已整理视频临时加入本轮。
- `恢复保护`：在执行前撤销本轮临时重新纳入。

说明文案：

> 之前已经确认整理的收藏，本轮不会重新判断，也不会改变原来的归档。

## 身份与数据模型

### 视频身份

同一个视频可能同时存在于多个来源收藏夹。保护、分类和执行以 B 站账号与视频 `aid` 作为逻辑身份：

```text
protectionKey = accountMid + ":" + aid
```

一次扫描内，同一 `aid` 只生成一个逻辑整理项，同时保留它出现过的来源收藏夹 ID 和标题，供来源筛选、计数和界面展示使用。不能继续使用 `sourceFolderTitle + aid` 作为保护身份，因为收藏夹可以改名，同一视频也可能出现在多个来源中。

### 保护记录

新增本地持久化记录，建议共享类型为 `FavoriteArchiveProtectionRecord`：

```ts
type FavoriteArchiveProtectionRecord = {
  accountMid: string
  aid: number
  targetLedgerIds: string[]
  targetFolderIds: string[]
  completedAt: string
}
```

约束：

- 只在一次视频整理任务完整成功后写入或更新记录。
- 待分类、未勾选、失败、暂停和部分成功不写入新的成功记录。
- 记录按 `accountMid` 隔离，切换 B 站账号不能复用另一账号的保护状态。
- 保护判断以“存在成功记录”为准，不因当前关键词、分类结果或后台多目标设置变化自动失效。
- 用户在 B 站手动移除历史归档后，成功记录仍然保留；普通二次扫描继续跳过，尊重用户的手动操作。
- 用户主动重新整理并完整成功后，用新的最终目标集合覆盖旧记录。

### 旧版本升级

升级前没有保护记录。为避免升级后的第一次扫描重新扰动全部历史收藏，采用保守初始化：

- 视频已存在于至少一个非“待分类”的 Bilimi 管理收藏夹时，视为已整理并建立保护记录。
- 视频只存在于 `Bilimi·待分类` 时，不建立保护记录，继续参与后续整理。
- 视频没有任何 Bilimi 管理归档时，作为本轮待整理项。
- Bilimi 管理收藏夹通过既有 Bilimi 前缀规则识别，而不是只依赖当前启用的收藏夹配置。

保守初始化可能把用户手动放入 Bilimi 收藏夹的视频也视为已整理，但这比自动重新分类更安全；用户仍可通过“重新整理这些收藏”显式纳入。

## 扫描与分区

### 扫描数据

扫描仍需要读取：

- 当前账号 ID。
- 用户来源收藏夹及其视频。
- 全部 Bilimi 管理收藏夹及其视频成员关系。
- 当前启用的收藏夹规则和 `favoriteArchiveMultiMode`。

扫描完成后先按 `aid` 合并重复来源，再分成：

1. `protectedItems`：存在保护记录，或符合旧版本保守初始化条件。
2. `activeItems`：没有成功保护记录的新增、待分类、失败或未完成项。

只有 `activeItems` 进入本地分类、候选收藏夹统计、DeepSeek 请求和归档预览。`protectedItems` 只用于来源范围计数，不参与候选统计，避免历史数据继续主导第二轮推荐。

### 扫描完整性

保护判断和重新整理收敛都依赖 Bilimi 收藏夹的真实成员关系，因此失败必须区分：

- 普通用户来源收藏夹读取失败：继续沿用现有“跳过来源”提示，其内容不进入本轮。
- 任一 Bilimi 管理收藏夹成员读取失败：本轮扫描视为不完整，不生成可执行计划，提示用户重试。

不能在 Bilimi 成员关系不完整时把不确定的视频当作新增项，也不能执行可能错误的移出操作。

## 扫描概览交互

扫描概览顶部摘要建议为：

```text
共扫描 250 条旧藏，其中 12 条进入本轮整理，238 条之前已整理，本轮保持原归档。
```

基础数据至少展示：

```text
共扫描        250
本轮待整理     12
可自动归档      8
需复核          2
待分类          2
已整理跳过    238
跳过来源        0
```

`已整理跳过`附近提供次级按钮：

```text
已整理跳过 238    [重新整理这些收藏]
```

按钮数量和作用范围只包含点击时已勾选的来源收藏夹中的保护项。内部按来源收藏夹 ID 计算，标题仅用于显示。

### 临时重新纳入

点击“重新整理这些收藏”后先显示确认：

> 将把当前来源中已整理的 238 条重新加入本轮判断，并按后台收藏夹数量设置重新收敛 Bilimi 归档。用户原有普通收藏不会改变。是否继续？

确认后：

- 仅把点击确认时勾选来源范围内的保护项加入 `activeItems`。
- 这些视频开始参与本轮候选统计、归档预览和可选 DeepSeek 整理。
- 扫描概览显示 `已重新纳入 238` 和 `恢复保护`。
- `恢复保护`只在执行前可用，恢复后移除这些视频产生的本轮分类和候选统计。
- 关闭本轮、重新扫描或完成本轮后，临时重新纳入状态自动清除。
- 用户确认后又勾选新的来源收藏夹时，新勾选来源中的保护项不会自动解开；用户需要再次点击入口并确认新的数量。

未被临时重新纳入的保护项不进入后续“推荐收藏夹”和“归档预览”。

## 目标数量与归档收敛

### 目标上限

重新整理使用当前后台设置：

- `off`：最终恰好一个已选择的 Bilimi 目标。
- `two`：最终最多两个已选择的 Bilimi 目标。
- `three`：最终最多三个已选择的 Bilimi 目标。

本地分类、DeepSeek 返回、用户手动选择和最终执行都必须遵守同一上限。执行前再次校验设置；如果设置在预览期间变化，不静默裁剪目标，而是要求用户刷新预览后重新确认。

### 对账模型

对于主动重新整理的视频，以当前真实 Bilimi 成员关系和本轮最终目标做集合对账：

```text
需要加入 = 本轮目标 - 当前 Bilimi 归档
需要移出 = 当前 Bilimi 归档 - 本轮目标
```

`当前 Bilimi 归档`包含通过 Bilimi 前缀识别的管理收藏夹，包括已停用或已从当前配置移除但仍存在于 B 站的旧 Bilimi 收藏夹。普通用户收藏夹不进入集合对账。

示例：视频当前位于 `Bilimi·游戏`，本轮目标是 `Bilimi·知识`，后台为单目标模式：

```text
加入：Bilimi·知识
移出：Bilimi·游戏
用户原始收藏夹：保持不变
```

普通增量整理中的新增视频通常只有“加入”；只有用户主动重新整理保护项时，才允许根据集合差异移出多余的 Bilimi 归档。

### 无目标处理

如果视频处于待分类、用户取消全部目标或没有真实目标收藏夹：

- 不执行加入。
- 不移出已有 Bilimi 归档。
- 不更新保护记录。

清空全部 Bilimi 归档不属于本功能范围，避免“未分类”被误解为删除命令。

## 执行顺序与失败处理

每条视频独立执行，顺序固定为：

1. 校验目标数量和目标收藏夹有效性。
2. 加入全部缺少的新目标。
3. 只有全部加入成功后，才移出所有多余的 Bilimi 目标。
4. 再次确认最终目标集合满足后台设置。
5. 完整成功后更新保护记录和纠错记录。

失败规则：

- 任一加入失败：不执行移出，保留原 Bilimi 归档，标记本条失败。
- 加入成功但移出部分失败：保留已经加入的新目标，标记为部分失败，不更新成功保护记录。
- 下次扫描时，部分失败项继续进入本轮；已经成功加入的目标会通过集合差异自然跳过，只重试剩余操作。
- 任一普通用户收藏夹绝不出现在 `del_media_ids` 中。
- 暂停或应用退出时，不把尚未完整对账的项目标记为已整理。

执行结果应区分成功、失败和部分失败，并在完成摘要中给出数量。

## 归档预览

普通增量项继续显示现有目标选择。临时重新整理的保护项额外展示当前 Bilimi 归档与本轮差异：

```text
将加入：Bilimi·知识
将移出：Bilimi·游戏
普通收藏：保持不变
```

要求：

- 只有真实发生变化的加入和移出才显示。
- 没有变化时显示 `保持当前 Bilimi 归档`。
- 单目标模式的交互只能选中一个目标；选择新目标会替换旧目标。
- 双目标、三目标模式达到上限后，继续选择必须先取消已有目标或明确替换，不能静默丢弃。
- 最终确认页汇总“将加入多少项、将移出多少项、保持多少项”。

## 状态流转

```text
扫描
  -> 合并重复 aid
  -> 读取保护记录和当前 Bilimi 成员关系
  -> 已保护跳过 / 本轮待整理
  -> 可选：当前来源保护项临时重新纳入
  -> 分类与归档预览
  -> 用户确认
  -> 先加入、后移出
  -> 完整成功后写入保护记录
```

一次视频任务的结果状态：

- `pending`：进入本轮但尚未执行。
- `succeeded`：目标集合完整对账，写入保护记录。
- `failed`：未完成，下一轮继续参与。
- `partial`：部分操作成功但未收敛，下一轮继续参与。

持久化层只需要保存成功保护记录；其他状态用于本轮执行反馈，不作为冻结依据。

## 兼容性与迁移

- 新字段缺失时按空记录处理，并执行旧版本保守初始化。
- 读取本地记录时过滤无效 `aid`、空账号和无效目标数组，不能因单条坏数据阻断应用启动。
- 当前纠错记录不能替代保护记录：纠错记录可能关闭、删除，也不覆盖所有成功整理行为。
- 现有“不会删除用户原收藏”的承诺继续成立，但需在 README 中明确：主动重新整理时可能从旧 Bilimi 收藏夹移出，以满足后台目标数量设置。

## 测试设计

### 数据与扫描

- 已有成功记录的视频进入 `已整理跳过`，不参与分类和候选统计。
- 新增、待分类、失败和部分失败视频进入本轮。
- 同一 `aid` 出现在多个来源时只产生一个逻辑整理项，来源筛选和计数正确。
- 不同 `accountMid` 的同一 `aid` 不共享保护记录。
- 旧版本无记录但已位于非待分类 Bilimi 收藏夹的视频完成保守初始化。
- 只位于 `Bilimi·待分类` 的视频不会被初始化为保护项。
- Bilimi 管理收藏夹成员读取失败时不生成可执行计划。

### 临时重新整理

- 按钮只计算当前勾选来源内的保护项。
- 确认后只临时纳入确认时的来源范围。
- 新勾选来源不会未经确认自动解开。
- `恢复保护`、重新扫描和关闭本轮会清除临时状态。
- 保护项重新纳入后才参与候选统计和 DeepSeek 请求。

### 目标限制

- `off` 模式最多选择一个目标，并在执行后只保留一个 Bilimi 归档。
- `two` 和 `three` 分别遵守两个、三个目标上限。
- 预览期间后台设置变化会阻止静默执行并要求刷新。
- 无目标时不加入、不移出、不更新保护记录。

### 执行安全

- 新目标全部加入成功后才发送旧 Bilimi 收藏夹的移出操作。
- 加入失败时 `del_media_ids` 为空。
- 移出部分失败时结果为 `partial`，不更新保护记录。
- 普通用户收藏夹 ID 永远不会进入移出列表。
- 重试部分失败项时，只执行仍有差异的操作。
- 完整成功后更新最终目标保护记录和纠错记录。

### 界面

- 扫描概览展示共扫描、本轮待整理和已整理跳过数量。
- “重新整理这些收藏”有范围和风险确认。
- 临时纳入后显示数量与“恢复保护”。
- 归档预览展示将加入、将移出和保持不变。
- 确认页汇总加入、移出和保持数量。

## 验收标准

- 用户新增少量收藏后二次扫描，旧的成功整理视频不再进入分类、候选统计、DeepSeek 请求或执行计划。
- 用户能在扫描概览看到已整理跳过数量，并能仅重新整理当前勾选来源中的保护项。
- 单目标设置下，主动重新整理完成后，每条成功视频最多位于一个 Bilimi 管理收藏夹。
- 多目标设置下，最终 Bilimi 归档数量不超过后台上限。
- 任一新目标加入失败时，旧 Bilimi 归档不被移出。
- 用户普通收藏夹中的成员关系在所有路径下保持不变。
- 旧版本升级后的第一次扫描不会把已经位于非待分类 Bilimi 收藏夹的视频全量重新整理。

实现完成后运行相关单元测试，并手动验收 dev 与 preview 的整理旧藏关键路径。若准备打包或发布 Windows 安装包，必须按 `docs/release-checklist.md` 完成 dev、preview、安装包三种形态的关键路径验收。
