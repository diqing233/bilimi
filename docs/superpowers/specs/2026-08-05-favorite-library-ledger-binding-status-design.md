# 收藏库备册绑定状态设计

## 目标

收藏库应准确区分可信 bilimi 工作夹、待保存的 bilimi 草稿和普通 B 站收藏夹；删除工作夹后不得遗留错误绑定或失去归属的视频；界面统一把本地收件箱称为“暂存”。

## 状态模型

- `已备册`：当前文件夹是 `bilimi-logical`，且 `syncState` 为 `bound`。
- `未备册`：当前文件夹是已有规则对应的 `bilimi-logical`，但没有可信 physical shard 绑定。
- `已生成草稿`：B 站镜像文件夹名称符合 bilimi 命名格式，但没有可信 physical shard；主进程仅生成本地逻辑草稿，不授予远端删除权限。
- 普通 B 站收藏夹不显示备册状态。
- `local:inbox` 始终显示为“暂存”，位于 bilimi 工作夹分组，不显示“未匹配分类”。

## 交互

状态显示在当前收藏夹标题右侧。`已备册`只作状态说明；`未备册`和`已生成草稿`提供“去掌库收藏夹设置保存后绑定”的入口。入口通过现有 assistant workspace request 打开掌库，并定位相应规则；不会自动写入或删除 B 站收藏夹。

## 删除与数据一致性

删除受管工作夹时，同时移除 logical folder、physical shards 和相关成员归属。受影响视频若删除后没有其他 bilimi logical 归属，则加入 `local:inbox`，同时更新 position 的本地期望归属。默认备册规则保留但清空远端 ID；自建规则删除。远端删除返回 `result-unknown` 或失败时停止后续批量删除并进入对账，不能继续假定成功。

## 安全边界

名称匹配只允许生成本地草稿和展示在 bilimi 工作夹区域，不构成可信远端绑定，也不能开放远端删除。只有 physical shard 的唯一可信绑定才允许远端删除。

## 验证

以单元/组件测试覆盖投影、删除后暂存归属、规则回写、标题状态、掌库跳转、批量删除中止和空工作夹删除；再运行收藏库、掌库、同步服务保护测试，并在 Electron 开发版检查点击、滚动、缩放、最小化、关闭及鼠标响应。
