# 备册完成后的状态刷新设计

## 目标

同步到 B 站完成后，掌库和浮窗快照必须立即反映正式绑定结果，不能因为 30 秒状态缓存继续显示“未备册”。

## 根因

`readFavoriteLedgerStatus` 的缓存命中只按账号和时间判断，未使用已计算的规则签名；普通 `saveFavoriteLedgers` 成功路径只广播快照变化，没有统一失效状态缓存。因此刷新事件可能重新读取旧的 `missingLedgerIds`，而 `FavoriteLedgerOverview` 会优先将该旧 ID显示为“未备册”。

## 方案

在 `saveFavoriteLedgers` 处理完本地偏好与正式绑定后，对当前账号状态缓存执行一次失效；成功或部分结果含有新绑定投影时，下一次快照读取强制走 `readFavoriteLedgerStatus(accountMid, { force: true })`。强制读取只发生在备册/绑定操作完成后，不放入勾选事件或渲染过程。仓库中的正式 `physicalShards` 绑定仍是远端清单短暂延迟时的权威来源；不按名称或数量推断绑定。

## 验证

- 为普通备册成功路径增加回归：旧状态缓存含目标 `missingLedgerIds`，保存返回已绑定分册后，刷新必须执行一次强制状态读取并清除旧缺口。
- 保留并运行上一轮投影、仓库和勾选响应回归，确认没有重复分类/历史调用。
- Electron 仅做只读观察，不点击创建、绑定、删除或视频写入按钮；真实 B 站副作用留待人工验收。
