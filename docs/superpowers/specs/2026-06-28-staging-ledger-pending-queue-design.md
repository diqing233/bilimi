# Bilimi 暂存册与待分类队列设计

- 日期：2026-06-28
- 范围：掌库、旧藏整理、新收藏归档、默认 `inbox` 册目语义
- 状态：待用户复核

## 背景

当前 `inbox` 默认册目显示为 `Bilimi·待分类`。它同时承担两个职责：

1. 作为 B 站上的真实收藏夹，接住分类不确定的新收藏。
2. 作为旧藏整理后的未决内容列表。

这两个职责混在一起会导致体验问题：旧藏整理结束后，用户想继续处理未分类内容时，需要重新扫描旧藏才能看到上下文；同时，旧藏里本来已经存在于用户原收藏夹的视频，如果再批量追加到 `Bilimi·待分类`，会造成重复归档但没有真正整理。

本设计将二者拆开：

- `Bilimi·暂存`：B 站真实收藏夹，只负责接住新收藏时暂时无法判断目标的视频。
- `待分类队列`：Bilimi 本地持久化任务队列，负责保存旧藏整理和新收藏产生的未决条目，让用户之后无需重新扫描即可继续分拣。

## 目标

1. 将默认 `inbox` 册目的显示名从 `Bilimi·待分类` 调整为 `Bilimi·暂存`。
2. 引入本地持久化的 `待分类队列`，作为掌库里的固定工作区。
3. 旧藏整理时，不再把分类不确定的视频默认追加到暂存收藏夹；这些视频进入本地队列。
4. 新收藏、赏、赐等即时归档动作仍然需要兜底；分类失败时收藏到 `Bilimi·暂存`，并写入待分类队列。
5. 兼容历史 `Bilimi·待分类` 收藏夹，不自动删除、移动或重命名用户 B 站收藏夹。
6. 用户重新打开掌库时，可以直接看到待分类队列，无需重新扫描旧藏。

## 不做内容

1. 不自动清空、迁移或删除旧的 `Bilimi·待分类` 收藏夹。
2. 不自动把旧藏中的不确定视频追加到 `Bilimi·暂存`。
3. 不从用户原收藏夹移除视频。
4. 不为所有待分类项强制生成新收藏夹；系统只推荐，最终由用户确认。
5. 不把本地队列当作 B 站真实收藏状态的唯一来源；需要执行归档时仍以 B 站接口结果为准。

## 核心语义

### `Bilimi·暂存`

`Bilimi·暂存` 是 `inbox` 默认册目的新显示名。它是一个 B 站真实收藏夹，用于新收藏时的兜底落点。

使用场景：

1. 用户对当前视频执行收藏类动作。
2. Bilimi 无法高置信度匹配任何启用册目。
3. 系统仍需要保证视频被收藏到 Bilimi 管理体系内。

此时视频进入 `Bilimi·暂存`，同时写入本地待分类队列。

### 待分类队列

待分类队列是 Bilimi 本地状态，不是 B 站收藏夹。它保存所有仍需整理的视频快照。

队列项至少保存：

```ts
type PendingFavoriteQueueItem = {
  aid: number
  title: string
  source: 'old-favorite-scan' | 'new-favorite'
  sourceFolderTitle?: string
  originalTargetLedgerId?: string
  suggestedLedgerIds: string[]
  candidateLedgerNames: string[]
  reason: string
  createdAt: string
  updatedAt: string
  status: 'pending' | 'archived' | 'dismissed'
}
```

说明：

1. `source = 'old-favorite-scan'` 表示来自旧藏整理扫描，视频仍保留在用户原收藏夹中。
2. `source = 'new-favorite'` 表示来自新收藏兜底，视频已经尝试进入 `Bilimi·暂存`。
3. `suggestedLedgerIds` 指向已有 Bilimi 册目建议。
4. `candidateLedgerNames` 保存可新建专题收藏夹建议。
5. `status` 让队列可持续维护，而不是每次打开都重新扫描。

## 旧藏整理流程

旧藏整理继续保持“扫描、预览、确认执行”的安全边界。

扫描后分类结果分为三类：

1. 明确命中已有 Bilimi 册目：进入归档预览，用户确认后追加到目标册目。
2. 可通过聚类推荐新册目：进入待分类队列，并在队列中显示推荐新建的专题收藏夹。
3. 仍无法判断：进入待分类队列，显示原因和来源收藏夹。

确认整理时，只执行明确分类且被用户勾选的视频追加操作。待分类队列项只写入本地状态，不触发 B 站收藏写入。

这样旧藏里的不确定项不会被重复塞进暂存收藏夹，但用户仍然能在掌库中继续处理它们。

## 新收藏流程

当前视频触发收藏类动作时：

1. 先匹配用户自定义册目。
2. 再匹配默认分类册目。
3. 如果没有明确命中，则使用 `inbox` 册目，即 `Bilimi·暂存`。
4. 如果暂存写入成功，同时创建或更新对应待分类队列项。
5. 如果暂存写入失败，动作结果需要明确提示用户，不应悄悄只写本地队列。

新收藏流程仍需要真实收藏夹兜底，因为视频可能尚未存在于任何用户收藏夹中。

## 掌库界面

掌库需要固定显示待分类队列入口，优先级高于普通册目列表。

建议呈现：

- `待分类队列 N 条`
- `可归入已有册目 X 条`
- `建议新建专题 Y 个`
- `仍需暂存 Z 条`

点入队列后，用户可以对队列项执行：

1. 归入已有 Bilimi 册目。
2. 勾选推荐专题并新建册目。
3. 保持暂存。
4. 忽略该项，将状态标记为 `dismissed`。

当队列项成功归档到某个 Bilimi 册目后，状态更新为 `archived`。默认视图只展示 `pending` 项。

## 历史兼容与迁移

`inbox` 的稳定 ID 不变，只调整默认显示名和语义。

兼容规则：

1. 新建默认册目时，`inbox` 显示为 `Bilimi·暂存`。
2. 如果用户本地已有 `inbox` 册目且显示名为 `Bilimi·待分类`，继续识别为同一个 `inbox`。
3. 如果 B 站远程已有 `Bilimi·待分类`，不要自动删除或重命名。
4. 可以在掌库中提示用户将旧名称改为 `Bilimi·暂存`，但必须由用户确认后执行。
5. 分类规则和归档规划仍通过稳定 ID `inbox` 工作，避免仅依赖显示名。

## 错误处理

1. 旧藏扫描失败时，不清空已有待分类队列。
2. 本地队列保存失败时，旧藏整理确认按钮应阻止执行，避免用户以为未决项已被保留。
3. 新收藏暂存写入失败时，不应只写本地队列；需要提示真实收藏失败。
4. 队列项引用的目标册目被停用或删除时，保留队列项，并重新计算建议。
5. 队列项对应视频在 B 站不可访问时，标记为需复核，不自动删除。

## 测试要求

需要覆盖以下行为：

1. 默认 `inbox` 册目名称为 `Bilimi·暂存`。
2. 旧 `Bilimi·待分类` 仍被识别为 `inbox`，不会生成重复默认册目。
3. 旧藏整理中未明确分类的条目进入本地待分类队列。
4. 旧藏整理确认执行时，不把未明确分类的条目追加到 `Bilimi·暂存`。
5. 新收藏分类失败时，视频追加到 `Bilimi·暂存`，并写入待分类队列。
6. 掌库重新打开后，无需重新扫描即可显示待分类队列。
7. 队列项成功归档后状态变为 `archived`，默认不再显示在待处理列表。
8. 暂存写入失败时，不创建误导性的“已收藏”队列项。

## 验收标准

1. 用户能在掌库中直接看到待分类队列数量和待处理内容。
2. 旧藏整理结束后，未分类内容不会丢失，也不需要重新扫描才能继续处理。
3. 新收藏没有明确分类时，仍有 `Bilimi·暂存` 作为安全落点。
4. 历史 `Bilimi·待分类` 用户不会被破坏性迁移。
5. `暂存` 和 `待分类队列` 在界面和代码语义上保持分离。
