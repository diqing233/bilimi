# 推荐收藏夹扫描投影重做设计

## 1. 背景与目标

本设计对应需求账本 `docs/requirement-ledgers/2026-09-06-recommended-favorites-redesign-discussion.md` 的 R001–R009。

现有推荐收藏夹已经能够根据整理扫描生成候选，但推荐候选、账号规则、上方收藏夹、B 站绑定、删除记录和恢复投影被组合成了一个特殊生命周期。历史修复继续增加稳定推荐身份、删除墓碑、远端覆盖集和观察恢复约束，导致推荐规则不能稳定复用普通收藏夹能力，并出现异名远端绑定、删除后不能再次推荐、草稿复活和勾选失配。

本轮保留现有推荐区域、入口和扫描推荐能力，重新划分内部职责：推荐是扫描数据的纯派生投影；用户采用推荐后得到的是一条普通本地收藏夹规则。推荐本身不拥有远端绑定、墓碑、认领或恢复生命周期。

## 2. 已确认范围

### 2.1 推荐来源

现有推荐计算只保留两类自动候选：

- `author`：专属 UP 追更；
- `tag`：高频标签。

推荐输入仅为本轮扫描范围内可用视频的 AID、UP 身份和已知标签。上方普通收藏夹、账号规则目录、B 站远端收藏夹、历史删除记录和绑定记录均不得成为“是否生成推荐候选”的输入。

旧的 `series` 或其他自动生成候选不再由扫描推荐计算器产生。用户主动新建收藏夹、普通规则编辑和 DeepSeek 分类不是自动推荐来源，继续保留。

### 2.2 DeepSeek 边界

DeepSeek 当前只能在已有且启用的规则中返回目标规则 ID，并可提供关键词建议；提示协议明确禁止创建收藏夹。本轮不改变该能力，也不把 DeepSeek 加入推荐候选生成器。

### 2.3 受保护子系统

本轮不改变：

- 普通自建收藏夹的新建、编辑、启用、停用和删除契约；
- 备册、确认并同步到 B 站、视频同步、远端收藏夹删除与绑定确认；
- 扫描分页、标签补取、DeepSeek 分类、人工分类和归档预览的产品入口；
- 页面尺寸、缩放、滚动、启动、最小化、恢复和关闭行为；
- 收藏库成员、档案、转写和操作反馈。

允许为接入推荐纯投影而复用普通规则事务、调整推荐协调代码和删除已无调用者的推荐专用分支；不得借机重写受保护子系统。

## 3. 核心数据模型

### 3.1 扫描推荐候选

推荐计算器输出轻量候选：

```ts
type ScanRecommendation = {
  candidateKey: string
  kind: 'author' | 'tag'
  sourceName: string
  defaultDisplayName: string
  ruleType: 'author' | 'tag'
  keywords: string[]
  matchedAidsBySegment: Record<string, number[]>
  count: number
  reason: string
}
```

`candidateKey` 只标识同一工作区扫描事实中的候选，用于渲染、恢复扫描草稿和匹配缓存；它不是账号收藏夹规则 ID、B 站 folder ID 或可被删除墓碑长期抑制的业务身份。

候选集合必须由当前扫描索引重建。若候选不再满足阈值则从投影消失；若之后再次满足则重新出现。历史上是否删除过同名规则不影响候选生成。

### 3.2 普通收藏夹规则

采用推荐后创建的对象与用户点击“新建收藏夹”保存后的对象使用同一规则模型、同一账号级持久化事务和同一后续编辑/备册/同步入口。

规则不再依赖 `ruleOrigin: 'recommendation-draft'` 获得特殊删除、绑定或恢复行为。若字段因兼容旧数据暂时保留，运行时也只把它当迁移来源标记，不得据此改变普通规则事务。

### 3.3 预计算联动索引

主进程或现有权威工作区协调层维护轻量索引：

```ts
type RecommendationLink = {
  candidateKey: string
  matchingLedgerId?: string
  workspaceVersion: number
  rulesVersion: number
}
```

候选与规则仅在以下规范化语义全部一致时匹配：

1. 显示名称一致；
2. 规则类型一致；
3. 规范化后的关键词集合一致。

名称执行 NFKC、空白折叠和项目既有大小写规范化；规则关键词使用既有规则解析与规范化能力。不能只按名称、候选旧 ID、远端 folder ID或视频数量匹配。

同一候选若出现多个完全一致的规则，索引不得任意选择，也不得再创建第三条规则。索引将其标记为歧义；点击时保持未勾选并提示用户先处理重复收藏夹。正常情况下账号规则规范化会按稳定规则 ID去重，但名称与语义重复的历史规则仍必须失败关闭，不能静默绑定其中一个。

## 4. 生命周期与交互

### 4.1 推荐生成

扫描开始、分页追加、标签结果变化、工作区恢复和批次切换继续使用现有异步、有界推荐计算路径。推荐计算只根据扫描索引生成 `author` 和 `tag` 候选。

生成候选不创建账号规则、不创建本地逻辑工作夹、不访问 B 站、不自动勾选。

### 4.2 一键采用

点击未勾选推荐时只读取已经发布且版本匹配的联动索引：

- 有唯一同名且规则一致的普通规则：复用该规则，设置其当前参与/启用状态，并使上下同时显示勾选；
- 没有唯一匹配：以候选默认名称、类型和关键词调用普通收藏夹“新建并保存”事务，保存成功后将新规则加入本轮参与集并使上下同时勾选。

点击处理器不得同步遍历扫描视频、账号全部规则或仓库目录。若匹配索引版本已过期，按钮进入短暂处理中并等待后台索引更新，而不是在点击栈内计算。

只有普通规则持久化、工作区参与状态和受影响分类投影都成功发布后，UI 才显示采用成功。失败时保持此前权威状态，不出现半成品上方卡片，不写删除记录、绑定或 B 站状态。

### 4.3 取消勾选

下方取消勾选只改变当前规则的参与/启用状态和本轮分类投影，不删除扫描候选，也不删除普通规则。

取消后再次点击：

- 预计算索引仍找到同名且规则一致规则时，复用并重新勾选；
- 上方规则已改名、改类型、改关键词或删除，索引无匹配时，新建一条普通规则并保存勾选。

### 4.4 上方编辑

普通规则改名、修改类型或关键词后，规则版本递增并异步重建联动索引。名称或规则语义任一不一致，推荐立即失去联动，不再随该上方规则勾选变化。

若用户之后把规则编辑回与推荐完全一致，新的索引版本可重新建立联动。

### 4.5 删除

推荐对应上方对象既然是普通收藏夹规则，其详情删除与删除模式继续复用普通规则既有删除流程及其远端确认边界。本轮只规定删除完成后的推荐投影：

- 普通规则从账号目录移除；
- 当前工作区参与状态和分类引用移除；
- 下方候选显示为未勾选；
- 不写“禁止再次推荐”的推荐黑名单或候选墓碑；
- 后续扫描仍满足条件时，候选照常生成。

普通规则若已经由用户显式备册，其远端删除仍严格由现有确认流程决定；推荐逻辑不得自动删除或保留 B 站实体。

## 5. 实时更新与并发边界

联动索引在以下权威事件后异步重算：

- 推荐候选集合版本变化；
- 普通规则新增、保存、改名、类型/关键词变化、启用状态变化或删除；
- 当前工作区恢复、重新扫描或切换有效账号；
- 推荐采用或取消事务完成。

每次计算携带账号 ID、工作区 ID、推荐版本和规则版本。发布时四者必须仍匹配；过期结果直接丢弃。缓存只保存候选到规则 ID 的匹配，不复制视频列表、绑定数据或远端目录。

推荐候选重算可以更新 `matchedAidsBySegment` 和归档统计，但必须沿用现有主进程有界队列及权威快照发布，不得在 renderer 点击、focus、滚动或绘制路径做全量工作。

## 6. 旧逻辑移除与兼容

### 6.1 移除的推荐专用行为

在确认没有受保护功能调用后，以下行为退出推荐路径：

- 自动 `series` 候选生成；
- 通过已保存上方规则反向补出或长期保留扫描候选；
- 以稳定规则 ID强行关联改名后的上方规则；
- 推荐专用 `ruleOrigin` 分流；
- 推荐删除墓碑、远端覆盖集和观察草稿恢复抑制；
- 推荐采用时的绑定、认领、旧远端夹恢复或按名称寻找 B 站收藏夹；
- 删除推荐后永久阻止同一扫描事实重新出现。

远端收藏夹观察草稿和普通规则远端删除可能仍需要各自已有的精确远端删除记录。本轮不能删除这些通用机制，只移除“推荐候选/推荐来源规则”对它们的特殊依赖。

### 6.2 旧数据迁移

现存 `ruleOrigin: 'recommendation-draft'` 账号规则按普通已保存规则读取：

- 保留名称、类型、关键词、启用状态和真实远端绑定事实；
- 不再把来源字段用于候选生成、上下联动、取消或删除分流；
- 后续用户保存或规范化时可迁移为普通规则来源；迁移不得丢失真实 B 站 folder ID、成员或备册状态；
- 旧推荐删除记录不再抑制扫描候选，但若其中包含已确认远端删除事实，仍按通用远端观察保护保留，不能复活已确认删除的同一精确远端 ID。

这一区分确保“推荐可以再次出现”不等于“已确认删除的同一个 B 站 folder ID可以作为观察草稿复活”。

### 6.3 项目书替代关系

实施时必须同步迭代 `docs/项目功能项目书.md`：

- 第 5.5 节保留扫描推荐、分类与归档快照一致性要求，但以本设计替代推荐专用草稿、稳定来源身份和 ID 强关联语义；
- 第 9.6–9.9 节中有关推荐来源永久身份、推荐删除墓碑、账号远端覆盖集和改名后稳定 ID 联动的内容，标记为被本设计明确替代；
- 普通收藏夹删除确认、备册、远端精确 ID保护和 B 站副作用边界继续有效。

不能静默删除旧项目书原文；应保留历史章节并注明替代依据和当前生效章节。

## 7. 错误处理

- 推荐计算失败：保留上一份仍匹配当前工作区版本的候选；若没有有效旧版本，显示推荐暂不可用，不伪造空扫描成功。
- 联动索引过期：阻止采用提交并等待最新索引，不在点击路径补算。
- 联动索引存在多个完全匹配规则：保持未勾选并提示先处理重复收藏夹，不任意复用也不新建第三条。
- 普通规则保存失败：不勾选推荐、不增加上方卡片、不改变分类。
- 参与状态或分类发布失败：恢复事务前权威规则与勾选状态；不得只成功一半。
- 账号或工作区切换：所有旧计算结果和在途采用响应失效。
- B 站不可用：不影响候选生成、普通本地规则采用与取消；只有用户进入既有远端操作时显示对应错误。

## 8. 测试与验收

### 8.1 自动化测试

必须先建立能复现当前错误结构的失败回归：

1. 扫描推荐只生成 `author` 和 `tag`，不生成 `series`；
2. 上方规则不能凭自身存在生成扫描候选；
3. 删除普通规则后候选取消勾选，下一次相同扫描仍重新出现；
4. 同名且类型/关键词一致时预计算唯一匹配并复用规则；
5. 同名但类型或关键词不同不联动；
6. 上方改名后索引失效，再点击推荐创建普通新规则；
7. 下方取消后再次点击，有匹配则复用，无匹配则创建；
8. 点击处理器不调用扫描遍历、标签遍历、远端目录读取或 B 站写入；
9. 保存、参与或分类任一步失败均不留下半成品；
10. 旧 `recommendation-draft` 规则按普通规则迁移，并保留真实备册/绑定事实；
11. 推荐删除记录不再抑制扫描候选，但通用的已确认远端 ID删除保护仍有效；
12. DeepSeek 仍只能选择已有规则，不创建收藏夹。

同时运行普通收藏夹、备册、同步、远端删除、扫描恢复、标签补取、DeepSeek、归档预览和样式/缩放相关既有测试。

### 8.2 Electron 真实验收

在清洁测试账号与包含历史推荐规则的迁移账号分别验收：

- 扫描出现两类现有推荐；
- 一键采用后上下同时勾选，且没有 B 站请求；
- 取消再点击的复用与新建两条路径；
- 改名、修改规则、删除后联动状态即时更新；
- 删除后重新扫描仍可再次推荐；
- 显式备册和确认同步保持既有行为；
- 连续移动鼠标、点击、滚动、缩放、最小化、恢复和关闭无明显阻塞；
- 页面大小、字号、间距和布局无本轮引入的变化。

诊断截图、日志与测试输出统一放入 `.codex-artifacts/`。

## 9. Git 与实施隔离

根目录 `main` 当前含其他主题未提交改动。实施不得直接把本轮改动混入该工作树。用户已要求以当前根目录 `main` 为基线，因此实施阶段应从当前 `main` HEAD 创建 `codex/` 前缀的独立分支和 worktree，保留根目录未提交文件原状。

实施允许修改的范围为：推荐计算、推荐/规则协调、相关共享类型、必要的普通规则复用接线、对应测试、项目书、本需求账本、设计和实施计划。若发现必须修改受保护子系统内部实现，必须先回到用户确认，不得自行扩大范围。
