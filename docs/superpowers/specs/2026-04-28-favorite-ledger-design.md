# Bilimi 掌库与册目设计规格

- 日期：2026-04-28
- 状态：已实现，作为当前掌库行为说明维护
- 范围：首次使用收藏夹初始化、掌库入口、推荐主分类、自定义册目、旧藏整理
- 产品语境：掌库保留少量宫廷语境词，例如“备册”“册目”，但主要交互文字优先清楚直接。

## 1. 背景

Bilimi 现有 MVP 已具备助手面板、视频分类判断、收藏动作自动化和 B 站收藏接口兜底。当前缺口是：用户第一次使用时可能还没有 Bilimi 专用收藏夹，系统需要给出温和提示，并提供一个专门的收藏管理入口，让用户创建、删除、整理 Bilimi 管理的收藏夹。

本规格将该入口命名为 **掌库**。掌库负责管理 Bilimi 自己的收藏夹体系。用户原有收藏夹是只读来源，Bilimi 整理旧藏时只能追加到 Bilimi 册目，不能移动、删除或取消用户原有收藏。

## 2. 目标

1. 首次打开助手时，如果 Bilimi 专用册目未备齐，显示轻提示，引导用户进入掌库备册。
2. 在助手工作区中提供 **掌库** 页签，作为收藏管理主入口。
3. 提供一套推荐主分类 Bilimi 册目，覆盖常见 B 站视频类型。
4. 允许用户新增、改名、停用、删除 Bilimi 册目。
5. 新增册目支持系统推荐名称，也支持用户完全自定义。
6. 自定义册目保存关键词和规则，以后遇到合适内容时自动整理到该册目。
7. 整理用户原有收藏时先扫描预览，用户确认后才执行追加。
8. 整理旧藏时不改变用户原收藏位置。

## 3. 不做内容

1. 不自动清空、迁移或重排用户原有收藏夹。
2. 不对用户原有收藏夹执行删除、重命名或取消收藏操作。
3. 不在用户未确认预览前批量写入 B 站收藏夹。
4. 不把广告、争议、标题党等内容单独建成默认收藏夹；这类信号只在预览中提示复核。
5. 不实现复杂撤销历史。旧藏整理执行前用预览和确认降低误操作风险。

## 4. 术语

- **掌库**：Bilimi 收藏管理入口，负责创建、管理和整理 Bilimi 专用收藏夹。
- **册目**：Bilimi 管理的一个收藏夹配置。它对应一个 B 站收藏夹，同时带有本地规则。
- **备册**：从旧藏扫描入口开始，帮助用户生成或勾选更适合自己的 Bilimi 册目。
- **整理旧藏**：扫描用户已有收藏夹，将适合的视频追加进 Bilimi 册目。
- **用户原收藏夹**：用户在 B 站已有的非 Bilimi 收藏夹。Bilimi 只读取和追加归档，不改动原位置。

## 6. 自定义册目

用户在掌库中点击 **新增册目** 时，可以选择两条路径：

1. **推荐名称**：用户输入主题，例如“摄影”“编程”“历史”。Bilimi 推荐 3 个典雅名称，用户可直接采用或继续修改。
2. **自定义名称**：用户直接输入收藏夹名称。系统建议保留 `Bilimi·` 前缀，但允许用户确认后使用完整自定义名称。

每个自定义册目保存以下字段：

```ts
type FavoriteLedger = {
  id: string
  displayName: string
  keywords: string[]
  enabled: boolean
  priority: number
  bilibiliFolderId?: string
  isDefault: boolean
}
```

规则要求：

1. `id` 是本地稳定 ID，改名后不变。
2. `displayName` 是当前 B 站收藏夹名称。
3. `keywords` 用于当前视频收藏和旧藏整理。
4. `enabled = false` 时，该册目不参与自动分类，但不删除 B 站收藏夹。
5. 自定义册目优先级高于默认册目。
6. 删除只允许删除 Bilimi 管理的自定义册目；默认册目和非 Bilimi 前缀的个人册目不能从掌库删除。

## 7. 首次使用体验

助手首次打开时读取本地册目配置和 B 站收藏夹列表。如果默认启用册目缺失，助手面板显示轻提示：

> Bilimi 专用册目尚未备齐，可请掌库先行备册。

提示提供 **请掌库** 操作。用户点击后打开掌库面板。系统不会在首次打开时自动创建收藏夹，必须由用户主动执行备册。

助手工作区常驻 **掌库** 页签，用户以后也可以随时进入。批阅动作区不另设重复的 **打开掌库** 按钮。

## 8. 掌库面板

掌库面板提供以下动作：

1. **备册**：先弹出确认区域，用户选择扫描旧藏后生成基础数据和专属收藏夹候选。
2. **推荐主分类收藏夹**：用左侧名称按钮选择正在编辑的册目；名称按钮本身不改变同步状态。
3. **同步开关**：每个分类右侧的 `+` / `✓` 小按钮直接加入或移出同步，不再弹二次确认。
4. **同步**：保存当前启用状态、自定义册目、候选册目和删除结果，并创建缺失的启用远程收藏夹。
5. **新增册目**：推荐名称或自定义名称，保存关键词规则。推荐名称来自 `suggestFavoriteLedgerNames`。
6. **快捷新增**：推荐主分类列表中 `纪录片` 后方有一个 `+` 按钮，点击后聚焦到新增册目表单。
7. **改册**：修改显示名、关键词、启用状态。
8. **删除**：只从草稿中删除 Bilimi 前缀的自定义册目；点击 **同步** 后才会删除对应的 Bilimi 远程收藏夹。默认册目和非 Bilimi 前缀的个人册目不可删除。
9. **整理旧藏**：扫描用户原收藏夹，生成预览，用户勾选条目后点击 **确认整理** 才追加到 Bilimi 册目。

面板文案保持少量宫廷语境，但功能文字要清楚。例如按钮可使用“备册”“同步”“新增册目”“整理旧藏”，避免过度戏谑影响理解。

## 9. 整理旧藏流程

整理旧藏是两阶段流程。

第一阶段：扫描预览。

1. 读取用户 B 站收藏夹列表。
2. 排除 Bilimi 管理的册目。
3. 读取用户原收藏夹中的视频条目。
4. 对视频标题、简介、标签等信息执行本地分类。
5. 生成预览清单，展示来源收藏夹、建议目标册目、是否已存在于目标册目、是否需要复核。

第二阶段：确认执行。

1. 用户确认预览后才开始写入。
2. 对已存在于目标册目的视频跳过。
3. 对需复核但用户未选择目标的视频跳过。
4. 对确认的视频调用 B 站收藏追加接口，加入目标 Bilimi 册目。请求必须把 `del_media_ids` 置空。
5. 执行完成后展示报告：成功数、跳过数、失败数和失败原因。

硬约束：

1. 不从用户原收藏夹删除视频。
2. 不移动视频。
3. 不取消收藏。
4. 不调用带有删除目标收藏夹语义的接口。
5. 同一视频同时存在于用户原收藏夹和 Bilimi 册目是正确结果。

## 10. 自动化与接口边界

收藏夹配置应集中在共享模型里，供 UI、DOM 自动化和 B 站 API 兜底共同使用，避免名称散落。

允许的接口行为：

1. 读取收藏夹列表。
2. 读取收藏夹内容。
3. 创建 Bilimi 册目。
4. 将视频追加到 Bilimi 册目。
5. 删除被用户从草稿中移除的 Bilimi 自定义册目，前提是它不是默认册目、具有远程收藏夹 ID，且远程标题或本地名称以 `Bilimi` 开头。

禁止的接口行为：

1. 删除用户原收藏夹。
2. 从用户原收藏夹移除视频。
3. 为了整理而取消收藏。
4. 在没有预览确认的情况下批量追加旧藏。

如果接口失败，用户应看到可读原因，例如登录凭证缺失、B 站接口失败、收藏夹 ID 缺失、目标册目不存在、视频已存在、用户取消等。

## 11. 测试要求

需要覆盖以下行为：

1. 首次提示：默认启用册目缺失时显示备册提示，齐全时不显示。
2. 备册：只创建缺失册目，不重复创建已有册目。
3. 推荐主分类：默认册目的 ID、名称、顺序和关键词配置稳定。
4. 自定义册目：新增、改名、停用、删除流程正确。
5. 自定义优先级：用户自定义关键词命中时优先于默认分类。
6. 改名稳定性：册目改名后稳定 ID 和分类规则不丢。
7. 旧藏扫描：排除 Bilimi 册目，只扫描用户原收藏夹。
8. 预览确认：确认前不调用追加接口。
9. 追加安全：执行时只追加到 Bilimi 册目，不传删除收藏夹 ID。
10. 跳过逻辑：已存在目标册目、需复核未选择目标、停用册目都应跳过。
11. 删除限制：只能删除 Bilimi 管理的自定义册目，不能删除默认册目或用户原收藏夹。
12. 错误报告：接口失败和登录状态缺失时给出可读反馈。

## 12. 验收标准

1. 新用户第一次打开助手时能看到掌库备册提示。
2. 用户可以通过掌库页签创建默认 Bilimi 册目。
3. 用户可以新增自定义册目，并让后续当前视频收藏和旧藏整理使用该规则。
4. 整理旧藏必须先显示预览，确认后才执行。
5. 执行整理后，视频保留在用户原收藏夹，同时出现在目标 Bilimi 册目。
6. 用户可以停用或删除 Bilimi 自定义册目，但不能误操作默认册目或用户原收藏夹。
7. 分类名称、规则和 B 站收藏夹 ID 由共享配置统一管理。
