# 全局提示、小咪反馈与启动响应设计

## 目标

落实需求账本 R001/R002：修复全局提示悬浮展开的完整文案与点击区域、无备册赏/藏/赐的小咪反馈语义，以及小咪启动阶段对主窗口鼠标输入的瞬间干扰；收藏夹、备册、同步和删除业务保持不变。

## 设计

### 全局提示

`FloatingAssistantApp` 保留现有两行摘要测量，仅用于收起且未悬浮状态。悬浮或展开时，续文与摘要一起渲染在同一个 `button.floating-assistant-global-status__feedback-toggle` 内，续文使用 `font: inherit` 的 inline 文本，不再渲染按钮外的 tooltip sibling。展开态取消 line clamp，完整续文后再渲染后台任务和最近提示；菜单滚动区域边界不变。

### 无备册动作反馈

扩展 `AssistantAutomationResult` 的可选 `petHint` 字段。动作执行层在 `favoriteProvisioned === false` 且动作成功时，根据赏/藏/赐生成与实际动作一致的中文提示，并由 `FloatingAssistantApp` 优先展示该结构化提示；其他成功、失败、重试和远端副作用路径保持原逻辑。这样不会依赖长结果文案匹配，也不会让助手重复写入反馈。

### 启动调度

保留主窗口交互就绪与 B 站首页收束 gate。将主进程小咪调度器改为可取消的事件循环让路任务：优先使用 `setImmediate` 让出当前输入轮，再使用 `setTimeout(0)` 作为兼容兜底，避免固定 250ms 猜测首帧；每次只执行一个阶段。创建小咪前不做 DWM/PowerShell、边界锁定或鼠标轮询；renderer 完成后先 `showInactive()`，其余原生修补继续放在后续可取消任务。

## 错误与边界

- 无备册提示只描述本地预分类事实，不声称 B 站写入成功。
- 调度任务取消或小咪创建失败时，主窗口继续可操作；显式唤醒仍可按原流程创建。
- 任何历史收藏夹规则、勾选状态、同步计划、窗口控制和数据持久化均不改写。

## 验证

- 单测覆盖完整续文位于同一按钮、无备册三种动作 `petHint`、以及调度器无固定短延时和可取消让路。
- 运行全量 `npm test`、`npm run build`、`npm run preview` 关键路径和 `npm run dist:win`；开发版、预览版、安装版分别进行真实悬浮、动作反馈和鼠标响应验收。
