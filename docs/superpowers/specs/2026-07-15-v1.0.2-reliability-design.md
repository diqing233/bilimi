# bilimi v1.0.2 发布前可靠性整改设计

## 目标

以 `8e5b8aa8` 的旧收藏扫描主链路为稳定骨架，在不覆盖当前工作树整体整改的前提下做外科式减法；修复扫描与标签门禁、归档预览原子撤销、孤儿 `custom-*` 目标和超长名称卡片，并保持只追加、不破坏原收藏的安全边界。

## 扫描批次

- 每批最多纳入 3000 个去重 aid，只在完整分页后推进批次游标。
- 完整批次游标跨应用重启保存；不保存半页或基础扫描的任意中间 Promise。
- 普通来源 failed/partial 只进入 diagnostics，不进入 totals、标签队列、预览或执行。
- bilimi managed folder 不完整时阻断预览和执行。
- 批次开始即建立唯一 runId/revision；取消 abort 当前请求，旧 revision 不得覆盖新批次。
- 同时只允许一个活动批次；必须完成或明确放弃当前预览后才能继续下一批。

## 标签门禁

- 基础扫描后自动补取本批标签。
- 标签未到终态前，后续步骤按钮可点击，但只显示原用途说明和“请等待扫描结束”，不显示业务内容。
- 标签队列全部成功或终态失败后解锁；单视频终态失败按无标签处理并普通提示。
- 登录、HTML、风控等全局错误阻断标签阶段。
- 处理中只合并轻量进度；完成时只读取一次完整快照并生成稳定预览。
- 删除自动刷新预览、“有新标签可用”和“按最新标签重新计算”链路。

## UI 扫描状态减法

- UI 只保留 scanGeneration、currentRunId、latestFullSnapshot 和必要的批次/进度状态。
- progress 采用串行 `await -> validate -> merge -> setTimeout`，天然 single-flight。
- 删除 previousRunId/activeRunId/awaitingNewRun、request owner、effect owner、in-flight owner、completion flags 和理论 handoff signature。
- 步骤切换是纯导航，不读标签、不同步候选、不重算预览。

## 归档预览原子事务

- 将 plan、selectedCandidateKeys、draftLedgers 和每次变更的来源位置作为同一事务快照。
- 单条、整组、1 条和 326 条操作都从同一 before 计算完整 after，一次发布、一次 history。
- 每个视频变更后记录来源位置；取消候选目录时相关视频恢复来源位置，并删除候选选择和目录定义。
- restore 使用 snapshot 自带的 ledgers 重建 preview，不读取旧闭包。
- `custom-*` 不得作为用户显示名；执行前任何无法解析的非 inbox/unclassified 目标都明确报错并阻止整批执行。

## UI 与安全边界

- 保持现有视觉风格和结构，只增加必要等待状态并做局部 CSS 修复。
- 收藏夹名称最多两行省略，按钮固定高度；原值、title、aria-label 和编辑器保留完整名称。
- 不移动、不删除、不取消任何原视频或原收藏；执行只向目标 bilimi 收藏夹追加。
- 不执行任何真实 B 站写操作作为自动验证。

## 发布

- TDD：每个行为先看到聚焦测试因缺失行为而失败，再实现最小修复。
- 完成后按 `docs/release-checklist.md` 验证 test、build、dev、preview 和真实安装包。
- 更新 v1.0.2 发布说明和验收记录；整个整改只创建一次 git commit。
