# 整理旧藏草稿与 AID 索引设计

## 目标

恢复收藏夹与“整理旧藏”区域的即时交互，同时让最多数万条收藏也能安全地分批整理、保存和后续同步。

本设计用持久草稿、收藏夹匹配 AID 索引和事务历史替代“勾选或进入归档预览时重新分类全部条目”。用户普通操作只应用差量；只有新建或修改收藏夹规则并点击“保存”时才分析已有扫描数据。分析可见、可取消、可续算，但不得冻结鼠标、切页、最小化或关闭窗口。

## 已确认的业务边界

- 改造只发生在“整理旧藏”工作流和其保存到收藏库的本地计划中。
- 扫描 B 站和写入 B 站不得并行；扫描期间可以本地整理已扫描批次，但确认后的远端计划只能排队等待。
- 每个活动批次最多承载 2000 条详细数据。数万条收藏由多个批次组成，不能作为一个完整 React 状态、IPC 快照或一次性渲染列表存在。
- 用户可以在已扫描批次上先整理和保存到收藏库；未扫描批次以后自动套用当时有效的收藏夹规则。
- 批次保存到收藏库后冻结其规则版本和归档结果。后续规则修改默认只影响当前未保存批次和未来批次；修改已保存批次必须从收藏库显式打开并创建新修订。
- 最终同步可以稍后从收藏库执行，也可以等全部扫描完成后统一执行，但始终按冻结批次串行、限速处理。
- 安装版、发布流程、LocalData、转写和其他应用页面不在本次范围内。

## 核心模型

### 整理任务

一个整理任务只保存全局摘要和批次索引：

```text
任务
├─ 扫描状态与远端请求调度状态
├─ 收藏夹草稿与规则版本
├─ 批次 1：已保存到收藏库
├─ 批次 2：当前整理中
├─ 批次 3：已扫描待整理
└─ 后续批次：尚未扫描
```

内存中只常驻当前活动批次、收藏夹规则摘要、事务游标和少量进度状态。已保存批次卸载详细卡片和活动历史，只保留冻结版本、数量和后续同步状态。

### 收藏夹草稿

收藏夹在本轮整理期间是草稿实体，不立即修改账户长期配置：

```ts
type DraftLedger = {
  id: string
  origin: 'existing' | 'recommended' | 'created'
  status: 'active' | 'inactive' | 'deleted'
  displayName: string
  keywords: string[]
  ruleVersion: number
  analyzedRuleVersion?: number
  matchedAidCount: number
}
```

- `inactive` 用于推荐收藏夹取消勾选，索引仍保留。
- `deleted` 是软删除，界面隐藏但规则、索引和历史保留到本轮结束。
- 新建、修改、删除和推荐采用都只改变草稿；批次冻结或任务最终确认时才生成账户配置变更计划。

### 匹配索引

每个收藏夹按批次保存匹配 AID，而不是只保存数量：

```text
ledger-id + rule-version
  batch-1 -> [aid...]
  batch-2 -> [aid...]
  ...
```

推荐收藏夹在生成候选时同时建立 `matchedAids`，显示数量直接来自索引长度。采用、取消或删除推荐收藏夹不得重新分析视频元数据。

用户自建或修改收藏夹时，在点击“保存”后为当前已扫描批次建立新规则版本的索引。保存后到达的新扫描批次在入库时顺便应用所有有效规则，不回头读取旧批次。

### 分类结果层级

最终显示结果由以下优先级合并：

```text
用户手动调整 > DeepSeek 调整 > 用户自建规则 > 已采用推荐规则 > 原有基础规则
```

同层多个规则冲突时使用稳定的收藏夹顺序裁决。系统分析不得覆盖人工或 DeepSeek 结果。后台旧版本结果不得覆盖新规则版本、更新的手动结果或更新的 DeepSeek 结果。

## 收藏夹保存与分析

### 未点击保存

名称和关键词只存在于编辑控件中：

- 不分析条目；
- 不更新分类；
- 不新增撤销事务；
- 继续使用上一个已成功分析的规则版本。

### 点击保存

保存触发一次可取消的本地分析事务：

1. 冻结编辑内容并生成新的规则版本和分析任务 ID。
2. 立即把收藏夹显示为“分析中”，锁定整理区内会改变草稿的操作。
3. 按已扫描批次和受控小批量读取本地元数据，建立临时 `matchedAids` 索引。
4. 对 `旧 matchedAids ∪ 新 matchedAids` 计算系统分类差量，跳过人工和 DeepSeek 条目。
5. 分批发布汇总进度，不向渲染器回传完整 AID 列表或完整任务快照。
6. 所有批次成功后，原子替换规则版本、索引和分类差量，并追加一条完整事务历史。
7. 分析失败或被取消时，正式草稿保持保存前状态。

分析期间可以锁定：

- 收藏夹新建、编辑、删除和勾选；
- 手动移动、批量移动和 DeepSeek 整理；
- 批次保存和最终确认。

分析期间不得锁定：

- 鼠标移动和页面滚动；
- 应用页签切换；
- 最小化和关闭窗口；
- 只读查看当前正式草稿；
- 后台扫描调度本身。

### 取消与恢复

- “取消分析”立即作废当前任务 ID，并在当前小批完成后停止安排下一批。
- 已计算结果只写入临时检查点，不得部分生效。
- 新建收藏夹取消后保留未保存编辑内容；修改已有收藏夹取消后继续使用旧规则和旧索引。
- 同一规则版本再次保存可从有效检查点继续。
- 名称、关键词、输入数据版本或扫描批次内容变化后，旧检查点作废。
- 关闭应用视为暂停；重新进入任务后可从有效检查点继续。明确点击取消则回到编辑状态。
- 同一时间只允许一个收藏夹规则分析任务。

## 推荐收藏夹操作

推荐生成阶段必须保存具体匹配 AID，而不是只保存 `count`。

- 勾选：立即将草稿状态设为 `active`，用现有索引重新裁决受影响 AID。
- 取消勾选：立即设为 `inactive`，用同一索引移除其影响。
- 删除：设为 `deleted`，索引继续保留以支持撤销和后续恢复。
- 重新勾选或撤销删除：复用索引，禁止重新扫描或重新分析全部条目。
- 进入归档预览：只读取当前正式草稿，不触发推荐保存、规则分析或全量分类。

若推荐候选产生于尚未完成的扫描任务，其索引可随新批次继续追加；界面数量标记为扫描中的暂定值，扫描结束后转为完整值。

## 归档预览中的编辑

归档预览是可编辑草稿页，不是分析入口：

- 手动移动只更新被操作 AID；批量移动只更新选中的 AID。
- DeepSeek 只处理用户选择的当前范围，返回 AID 分类差量。
- DeepSeek 运行期间用户结果优先；结果返回时逐项验证条目版本、目标收藏夹状态和任务 ID。
- DeepSeek 目标已删除、条目已被人工修改或结果已过期时，相关差量作废。
- 查看、滚动、切换已扫描批次和窗口控制不得因后台任务被禁用。
- 最终确认只允许使用所有必要分析均完成、没有悬空目标且版本一致的草稿。

## 事务撤销与恢复

现有只记录分类变化的历史不足以覆盖收藏夹操作。新历史以一次用户业务动作作为原子事务：

```ts
type DraftTransaction = {
  id: string
  kind:
    | 'create-ledger'
    | 'update-ledger-rule'
    | 'delete-ledger'
    | 'adopt-recommendation'
    | 'remove-recommendation'
    | 'manual-classification'
    | 'deepseek-classification'
  before: DraftDelta
  after: DraftDelta
}
```

事务只保存必要差量和索引版本引用，不保存 2000 或 30000 条完整快照。

- 新建收藏夹撤销：移除草稿收藏夹、索引引用和其分类影响。
- 修改规则撤销：恢复旧名称、关键词、索引版本和分类差量，不重新分析。
- 删除收藏夹撤销：清除软删除标记并恢复已有索引影响。
- 推荐收藏夹撤销：恢复采用状态和索引影响。
- DeepSeek 一次完整任务作为一条事务。
- 手动单项或一次批量操作作为一条事务。
- 分析取消不产生事务；只有分析完整成功并原子生效后才产生事务。
- 已保存到收藏库的批次不允许由当前活动批次的 `Ctrl+Z` 跨批回滚。

快捷键与按钮共享同一命令路径：

- `Ctrl+Z`：撤销；
- `Ctrl+Shift+Z` 和 `Ctrl+Y`：恢复；
- 输入框、文本域或可编辑元素拥有焦点时，不拦截其原生文字撤销；
- 分析事务运行或批次已冻结时，按钮与快捷键使用同一禁用条件。

## 多批扫描与本地保存

扫描、整理和远端同步是三个独立阶段：

```text
B 站扫描 -> 已扫描批次可本地整理 -> 保存到收藏库并冻结 -> 等待远端同步
```

- 扫描出一个最多 2000 条的可用批次后，可以开放该批本地整理；后台可继续扫描下一批。
- 已保存的收藏夹规则在后续批次入库时同步建立索引，不需要扫描结束后回头分析全部数据。
- 用户等全部 30000 条扫描结束后才新建或修改收藏夹时，保存分析按已落盘批次顺序执行，可取消并可续算。
- 当前批次保存到收藏库后，冻结分类、规则版本和远端操作计划，然后卸载详细活动状态。
- 用户可继续整理后续批次，也可关闭应用后稍后继续。
- 扫描期间远端写计划只能排队；不得创建、移动或删除 B 站收藏来与扫描请求并发。
- 扫描结束或用户明确暂停扫描并经过调度冷却后，远端计划才可串行、限速执行。

## 持久化与 IPC

主进程是草稿、索引、事务和批次状态的权威来源。

- AID 索引按任务、收藏夹、规则版本和批次分片落盘。
- 分析临时检查点与已生效索引分开存储，防止取消或崩溃污染正式草稿。
- 分类和事务使用追加日志或等价的差量持久化，不为每次操作重写整个任务。
- 渲染器只接收当前批次详情、收藏夹摘要、事务摘要和进度事件。
- 普通勾选、删除、撤销和移动命令只返回变更摘要或新版本号，不回传 30000 条完整快照。
- 任何异步结果都必须校验账号、任务、批次、规则版本和请求 ID。

## 性能约束

- 普通勾选、取消、软删除、撤销、恢复和进入归档预览不得触发规则分析。
- UI 可见反馈应在同一交互帧内发生；持久化在后台完成。
- 规则分析采用受控小批次，并根据实际单批耗时调节，避免长期占用 Electron 主进程事件循环。
- 进度事件按批次或节流后的条目计数发布，禁止每条视频触发一次 React 更新。
- 当前批次列表必须保持分页、虚拟化或等价的有限渲染；禁止挂载数万张卡片。
- 不承诺未经测量的绝对毫秒值。验收重点是窗口控制、鼠标、页签和滚动不被冻结，以及计算量与受影响数据范围相符。

若真实 30000 条数据证明主进程即使分批仍产生可见停顿，再将纯分类与索引生成迁入 Worker；Worker 不是本阶段的默认前提，但数据和任务接口必须允许后续迁移。

## 错误与一致性

- 分析失败：保留旧规则、旧索引和旧分类，显示可重试错误。
- 本地批次保存失败：不得标记为已冻结或已完成。
- 删除仍被人工或 DeepSeek 结果引用的收藏夹：草稿可软删除，但批次保存前必须解决悬空目标，不能静默丢失分类。
- 同步失败：保留收藏库数据和冻结计划，从失败断点恢复。
- 放弃活动任务：只丢弃未保存活动批次和未提交编辑；已保存到收藏库的批次继续保留。
- 规则版本变化、扫描数据变化或索引损坏时，只使相关规则版本和批次失效，不重建无关索引。

## 迁移与现有实现

当前“进入归档预览后调用 `prepare-recommendation-preview` 全量重新分类”的试验实现不符合本设计，不应作为最终方案提交。

迁移需要做到：

- 保留已有人工和 DeepSeek 分类结果；
- 将已有推荐候选补建为带 AID 索引的数据；
- 将推荐采用和自建收藏夹写入从即时账户配置修改迁移为草稿事务；
- 在新的快捷键路径可用前移除或修正当前误导性的快捷键提示；
- 对无法可靠迁移的旧活动草稿提供明确的重新建立索引操作，不静默改变分类。

## 测试与验收

### 数据与协调器测试

- 推荐生成同时保存准确 `matchedAids`，数量等于索引长度。
- 推荐采用、取消、删除和恢复不调用全量分类器。
- 新建/修改规则在保存前不分析，保存后分批分析并原子生效。
- 取消、失败、关闭恢复和同规则续算不污染正式草稿。
- 修改规则只重新裁决旧索引和新索引的并集。
- 人工和 DeepSeek 结果不被系统规则覆盖。
- 30000 条按多个 2000 条以内批次处理，不生成完整快照。
- 后续扫描批次自动应用已保存规则版本。
- 扫描运行时远端同步计划只排队、不执行。

### 撤销测试

- 新建、修改、软删除、推荐采用/取消、手动分类和 DeepSeek 批次均可完整撤销和恢复。
- 撤销与恢复复用索引和差量，不触发规则分析。
- 分析取消不新增历史。
- 快捷键与按钮走同一命令，并避开文本输入焦点。
- 活动批次历史不能跨越已冻结批次边界。

### 渲染器测试

- 普通操作立即更新局部 UI，不等待 IPC 完整快照。
- 分析期间只锁整理动作，窗口和导航相关 DOM 不被遮罩或 `pointer-events` 禁用。
- 进度节流，不随条目数量产生等量重渲染。
- 归档预览打开时不发送分类准备命令。
- 当前批次保持有限渲染，大数据只加载摘要和可见窗口。

### 真实 Electron 验收

- 2000 条下连续勾选、取消、删除、撤销、恢复、手动移动和进入预览无鼠标冻结。
- 新建/修改收藏夹保存时进度可见，取消有效，鼠标、页签、滚动、最小化和关闭正常。
- 使用接近 30000 条的分片数据验证批次切换、断点恢复、规则分析、收藏库冻结和待同步队列。
- 验证扫描期间没有 B 站写请求；扫描结束后同步串行执行。
- 记录 Electron 主进程长任务、IPC 负载和 React 提交耗时；不得以 jsdom 绿灯代替真实输入响应结论。

## 非目标与剩余风险

- 本阶段不优化 B 站接口本身、DeepSeek 网络耗时或远端风控策略，只保证读写不并发并保留安全调度入口。
- 极宽关键词可能命中全部数据；此时仍需处理大量 AID 差量，但不得重新执行无关扫描或渲染全部卡片。
- 数万条索引和事务虽然适合分片持久化，仍需用真实磁盘和低性能设备测量写放大与恢复时间。
- 若用户频繁修改规则，旧检查点和索引版本需要有明确的后台回收策略；回收只能删除已无引用的临时版本，不能破坏撤销或冻结批次。
