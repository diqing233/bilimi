# Bilimi 札记 UI 与全局档案库改版设计

- 日期：2026-06-17
- 状态：设计已确认，等待实现计划
- 范围：札记页布局、文稿入口、转写状态提示、全局档案库、转写历史保存
- 不包含：外部大模型接入、OCR、批量下载队列、云同步、多设备同步

## 1. 背景

现有札记功能已经支持当前视频音频转写、生成札记、时间线文稿、批注、Markdown 导出和本地保存，但 UI 更像若干功能堆叠，用户不容易分清“开始转写”“查看文稿”“进入历史档案”的主次关系。

本次改版以用户提供的参考图为准，保留平铺式结构，不改成复杂工作台。重点是优化按钮层级和提示效果，并把档案库升级为全局所有视频历史，保存每次转写生成的文稿、总结、批注和备注。

## 2. 目标

1. 札记页保留顶部 `批阅 / 札记 / 掌库` 标签，其中 `札记` 为当前页。
2. 札记页顶部展示当前视频详情，包括标题、作者、BV 号和链接。
3. `转写音频` 和 `档案库` 是同级主按钮，放在同一行。
4. 转写中展示明确阶段、段落进度和进度条。
5. 文稿入口顺序为：`无时间线文稿`、`带时间线文稿`、`一图流总结`。
6. `无时间线文稿` 是纯文稿连续阅读，不显示时间码，不显示批注按钮，并提供复制全文。
7. `带时间线文稿` 按时间段展示，可跳转视频时间点，可加批注。
8. `一图流总结` 展示结构化总结，并提供复制。
9. `档案库` 展示全局所有视频历史，而不是当前视频局部历史。
10. 每次转写音频都生成一条历史版本，保存视频信息、纯文稿、时间线文稿、总结、批注和备注。

## 3. 非目标

1. 不在本阶段做云端同步或账户级资料库。
2. 不接入 DeepSeek 或其他外部总结模型。
3. 不做 OCR、截图识别或弹幕整理。
4. 不做批量转写队列。
5. 不做复杂标签体系；第一版仅提供搜索和基础筛选。

## 4. 札记页布局

札记页采用平铺布局，信息顺序如下：

1. 顶部主标签：`批阅 / 札记 / 掌库`。
2. 当前视频详情：标题、作者、BV 号、链接。
3. 主操作区：左侧说明，右侧并列按钮 `转写音频`、`档案库`。
4. 转写状态提示：仅在转写中或失败时展示。
5. 结果入口：`无时间线文稿`、`带时间线文稿`、`一图流总结`。

按钮层级：

1. `转写音频` 使用主按钮样式。
2. `档案库` 使用同级但次强调样式，位置在 `转写音频` 右侧。
3. 三个结果入口使用稳定的大按钮，不再和主动作争抢视觉权重。

状态提示：

1. 尚未转写时，提示用户点击 `转写音频`，并说明可使用纯文稿粘贴兜底。
2. 转写中，显示当前阶段、当前段落、总段落数和进度条。
3. 转写失败时，错误提示需要说明原因和下一步，例如检查视频是否可播放或改用纯文稿。

## 5. 文稿与总结入口

### 5.1 无时间线文稿

`无时间线文稿` 是默认高效阅读入口，展示连续纯文稿。

要求：

1. 面板顶部提供 `复制全文` 按钮。
2. 正文不展示时间码。
3. 正文不展示批注按钮。
4. 文稿应保留段落分隔，避免挤成一整块长文本。
5. 如果无文稿，展示空状态并引导转写或粘贴文稿。

### 5.2 带时间线文稿

`带时间线文稿` 用于复看和批注。

要求：

1. 每段显示时间点和文本。
2. 点击时间点可跳回视频对应时间。
3. 每段提供 `加批注`。
4. 继续复用现有批注保存、编辑和删除能力。

### 5.3 一图流总结

第一版不生成真正图片文件，而是生成可浏览和可复制的结构化总结视图。后续如要生成图片或长图，可在此基础上扩展。

要求：

1. 展示一句话总结、核心要点、值得复看、待查问题。
2. 提供 `复制总结`。
3. 总结内容随每次转写历史版本保存。

## 6. 全局档案库

档案库是全局所有视频历史，采用推荐的双栏结构：

1. 左侧：搜索、筛选、视频列表。
2. 右侧：所选视频详情、文稿、时间线、总结、批注、备注和历史版本。

### 6.1 搜索与筛选

搜索范围：

1. 视频标题。
2. 作者。
3. BV 号。
4. 纯文稿。
5. 总结。

基础筛选：

1. 最近转写。
2. 有批注。
3. 有备注。
4. 按作者筛选可作为后续增强，不作为第一版必须项。

### 6.2 视频列表

每个视频条目展示：

1. 视频标题。
2. 作者和 BV 号。
3. 最近转写时间。
4. 转写版本数量。
5. 批注数量。

点击视频后，右侧展示该视频详情。

### 6.3 详情区

详情区包含：

1. 视频来源信息。
2. 历史版本选择。
3. 纯文稿。
4. 带时间线文稿。
5. 总结。
6. 批注和备注。
7. 操作按钮：复制纯文稿、复制总结、打开来源、删除记录。

删除记录第一版可以删除整个视频档案或某次转写版本，但必须有确认提示。

## 7. 数据模型

现有 `VideoNote` 仍表示某一次生成后的札记。为了保存全局历史，需要在本地 store 中维护视频档案集合。

建议新增类型：

```ts
export type VideoNoteArchiveEntry = {
  id: string
  source: VideoNoteSourceMetadata
  versions: VideoNoteArchiveVersion[]
  createdAt: string
  updatedAt: string
}

export type VideoNoteArchiveVersion = {
  id: string
  note: VideoNote
  plainTranscript: string
  summaryText: string
  createdAt: string
}
```

归档规则：

1. 每次音频转写生成札记后，追加一个 `VideoNoteArchiveVersion`。
2. 同一视频用 BV 号优先合并；没有 BV 号时用 URL 作为稳定键。
3. 纯文稿由 `note.transcript` 拼接生成。
4. 总结文本由 `note.overview` 生成。
5. 批注和备注随版本中的 `note` 保存。

## 8. 数据流

1. 用户打开当前视频。
2. 用户点击 `转写音频`。
3. 系统执行本地音频转写并生成 `VideoNote`。
4. UI 更新当前札记结果。
5. 系统把本次结果写入全局档案库。
6. 用户点击 `无时间线文稿` 查看纯文稿并可复制全文。
7. 用户点击 `带时间线文稿` 查看时间线文稿并可跳转或批注。
8. 用户点击 `一图流总结` 查看和复制结构化总结。
9. 用户点击 `档案库` 进入全局双栏历史视图。

## 9. 错误处理

1. 转写失败：保留当前页面状态，显示失败原因和下一步。
2. 归档保存失败：转写结果仍展示在当前页，并提示用户重试保存。
3. 复制失败：保留文本内容，提示剪贴板不可用。
4. 搜索无结果：展示空状态，不清空搜索输入。
5. 删除失败：保留原记录并提示失败原因。

## 10. 测试策略

### 10.1 单元测试

1. 纯文稿生成函数能从 `TranscriptSegment[]` 生成连续文本。
2. 总结文本生成函数能从 `VideoNoteOverview` 生成可复制文本。
3. 档案库合并逻辑能按 BV 号或 URL 合并版本。
4. 搜索逻辑能匹配标题、作者、BV、文稿和总结。

### 10.2 组件测试

1. 札记页主按钮顺序为 `转写音频`、`档案库`。
2. 结果入口顺序为 `无时间线文稿`、`带时间线文稿`、`一图流总结`。
3. 无时间线文稿面板提供 `复制全文`。
4. 带时间线文稿保留时间跳转和加批注。
5. 一图流总结提供 `复制总结`。
6. 全局档案库渲染搜索、筛选、列表和详情区。
7. 点击历史视频能切换详情。

### 10.3 集成测试

1. 音频转写成功后会写入全局档案库。
2. 同一视频多次转写会追加历史版本。
3. 档案库能在应用重启后加载已保存历史。
4. 删除档案记录后本地 store 同步更新。

## 11. 验收标准

1. 用户能从札记页一眼看到 `转写音频` 和 `档案库` 两个主入口。
2. `无时间线文稿` 在 `带时间线文稿` 左侧。
3. 用户能复制纯文稿。
4. 用户能复制总结。
5. 用户能查看全局所有视频的转写历史。
6. 用户能在档案库搜索标题、作者、BV、文稿和总结。
7. 用户能查看同一视频的多次转写版本。
8. 现有批注、跳转、保存能力不回退。
9. 全量测试通过，构建通过。
