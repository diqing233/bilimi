# 整理收藏本轮执行设计

## 目标

多批整理使用一个统一的查看范围和一个本轮执行意图。用户可以查看单批细节，但 DeepSeek 全轮整理、保存收藏库和同步 B 站都必须等待本轮所有批次完成预处理后再按顺序执行。

## 数据口径

- `等待预处理`：批次仍在扫描、补取标签或尚未产生自动分类结果。
- `已分类`：视频至少有一个归档目标；同一视频可属于多个归档目标，因此各收藏夹条数是关系数，不作为去重视频总数。
- `未匹配`：已完成预处理，但没有归档目标；保存到本地 `bilimi·暂存`，不参与 B 站同步。
- `已失效`：不分类、不保存、不参与同步。

本轮总览只汇总已完成批次。未匹配以 `bilimi·暂存` 单独展示，等待预处理单独展示，不能用“计划总数减已分类数”推断未匹配。

## 统一范围

顶部批次选择是四个步骤的统一范围来源。选择具体批次后，扫描概览、推荐收藏夹、归档预览和确认执行均展示当前批次；选择本轮总览后四步均展示汇总。单批整理保持现有体验。

## 本轮执行

DeepSeek 全轮整理沿用主进程持久检查点：已就绪批次先处理，后续批次完成预处理后自动续跑。用户提前确认时，主进程持久记录本轮执行意图并锁定人工改动；所有批次预处理和 DeepSeek 全轮整理都完成后，才保存整轮到收藏库。选择同步 B 站时，再冻结并执行远端计划。失败或取消 DeepSeek 会停止自动执行，用户可取消等待后返回调整。

## 验证

- 汇总测试覆盖等待、暂存、分类关系和失效视频的互斥口径。
- UI 测试覆盖顶部范围切换驱动四个步骤。
- 主进程测试覆盖确认意图持久化、等待 DeepSeek、完成后本地保存及可选同步。
- Electron 开发版验证两批总览、批次切换和等待提示，不以操作耗时证明性能。
