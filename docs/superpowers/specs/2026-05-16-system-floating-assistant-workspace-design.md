# Bilimi 系统级悬浮助手工作区设计

- 日期：2026-05-16
- 状态：用户已确认设计方向，等待实现计划
- 范围：系统级悬浮按钮、按钮旁完整助手工作区、主窗口自动化桥接、后续工程优化方向
- 替代：`2026-05-16-system-floating-menu-design.md` 中“小菜单触发主窗口面板”的交互方向

## 1. 背景

当前实现已经具备系统级悬浮按钮和一个贴近按钮的小菜单。小菜单可以发起 `赏 / 藏 / 表 / 阅` 等动作，但完整的 `批阅 / 札记 / 掌库` 体验仍留在主窗口里的 `AssistantOverlay`。这会造成两个体验问题：

1. 用户点击桌面悬浮入口后，注意力被拉回主窗口，系统级入口像一个遥控器，而不是助手本体。
2. 投币确认、评论选择、视频札记、收藏库管理和执行反馈分散在不同视觉层级里，操作路径不稳定。

新的目标是让“悬浮按钮旁边”成为完整工作区。主窗口只承载 Bilibili 页面、webview 自动化和本地数据存取，系统级浮窗负责全部助手交互。

## 2. 体验目标

悬浮按钮始终是唯一入口。用户拖动它时，按钮应自然跟随鼠标移动，释放后停在当前位置；拖动过程不应误触打开。点击按钮时，系统级助手工作区在按钮附近展开，默认贴近按钮的一侧，并根据屏幕边缘自动翻转和夹紧，避免出屏或遮挡按钮。

工作区不是小菜单，而是完整、紧凑、可完成任务的助手面板。它默认展示 `批阅` 页签，提供当前视频判断、推荐动作、`赏 / 藏 / 赐 / 表 / 阅` 操作、执行状态和失败原因。`札记` 页签提供视频笔记生成、手动稿件输入、保存。`掌库` 页签提供收藏分库状态、缺失分库创建、旧收藏扫描和迁移。

当动作需要二次确认时，例如投币数量或评论文案选择，确认 UI 必须在同一个系统浮窗内出现，不再打开主窗口内面板。执行自动化时，浮窗保留轻量状态反馈；主窗口可被恢复并聚焦以确保 webview 可执行，但不显示助手 UI。

## 3. 方案选择

### 3.1 推荐方案：系统级完整助手工作区

主进程保留 `floatingSealWindow`，将当前 `floatingMenuWindow` 升级为 `floatingAssistantWindow`。该窗口尺寸约 `360 x 560`，使用透明无边框系统窗口，始终在按钮附近打开。React 入口通过 `window=floating-assistant` 渲染完整助手工作区。

优点：
- 符合“所有功能在悬浮按钮旁边”的要求。
- 用户只在一个空间完成批阅、札记、掌库和二次确认。
- 主窗口职责更清晰，只负责 Bilibili 页面和自动化执行。
- 后续可自然扩展为托盘、快捷键、全局状态机。

代价：
- 需要把当前 `AssistantOverlay` 的 UI 状态和业务依赖拆成可复用的助手表面组件。
- 系统浮窗无法直接访问主窗口 webview，需要通过 IPC 桥接主窗口能力。
- 收藏库状态、偏好、札记保存等操作需要明确区分“系统浮窗 UI”和“主窗口执行器”。

### 3.2 备选方案：保留小菜单，主窗口打开面板

当前实现基本采用这个方案。它改动少，但体验割裂，且不满足用户确认的目标，因此不再继续投入。

### 3.3 备选方案：悬浮按钮周围展开扇形功能区

扇形按钮视觉更活泼，但中文标签和二次确认承载差，边缘适配复杂，且无法自然容纳札记和掌库这类完整工作流。当前阶段不采用。

## 4. 架构设计

### 4.1 Electron 主进程

主进程负责三个窗口：

- `mainWindow`：Bilibili 浏览器、webview 自动化、数据桥接。
- `floatingSealWindow`：系统级悬浮入口，负责点击和拖动。
- `floatingAssistantWindow`：系统级完整助手工作区，负责用户交互。

主进程新增或调整职责：

1. 点击悬浮按钮时切换 `floatingAssistantWindow`。
2. 拖动悬浮按钮开始时关闭或隐藏助手工作区，避免浮窗滞留。
3. 根据按钮位置、工作区尺寸、当前显示器 workArea 计算浮窗位置。
4. 接收系统浮窗发起的助手命令，并转发给主窗口执行。
5. 接收主窗口返回的上下文、执行结果、收藏库状态和札记保存结果，再回传给系统浮窗。

### 4.2 React 渲染层

React 入口根据 URL query 分流：

- 默认：`App`，只渲染浏览器主界面和隐藏的自动化执行桥。
- `window=floating-seal`：渲染 `FloatingSealApp`。
- `window=floating-assistant`：渲染新的系统级助手工作区。

将现有 `AssistantOverlay` 拆成两个层次：

- `AssistantSurface`：纯助手交互组件，包含页签、动作按钮、确认对话、反馈、札记、掌库。它不直接知道自己运行在主窗口还是系统浮窗。
- `AssistantRuntime` 或等价桥接层：负责读取视频上下文、执行动作、读写偏好、保存札记、管理收藏分库状态。

系统浮窗使用 IPC runtime；主窗口保留 webview runtime。主窗口不再显示 `AssistantOverlay` 面板，只提供 webview 和自动化执行能力。

### 4.3 Preload 与 IPC

`window.bilimiDesktop` 扩展为系统浮窗可用的助手 API：

- `toggleFloatingAssistant()`：悬浮按钮点击时切换完整工作区。
- `closeFloatingAssistant()`：浮窗关闭按钮、失焦或 Esc 关闭。
- `requestAssistantSnapshot()`：读取当前视频标题、推荐分类、收藏库状态和偏好。
- `runAssistantAction(action, options)`：执行 `赏 / 藏 / 赐 / 表 / 阅`。
- `generateVideoNote(manualTranscript?)`：请求主窗口从 active webview 提取内容并生成札记。
- `saveVideoNote(note)`：保存视频札记。
- `ensureFavoriteLedgers()`、`scanOldFavorites()`、`executeOldFavoritePlan(items)`：掌库相关操作。

主窗口继续通过 webview 的 `executeJavaScript` 执行页面脚本。系统浮窗不直接访问 webview。

## 5. 布局与交互规则

助手工作区使用固定外部尺寸起步：`360 x 560`。内容较多时内部滚动，不改变窗口外部尺寸，避免打开后跳动。窄屏或小显示器下可以降到最小 `320 x 480`，但必须保证主要动作按钮可见。

布局优先级：

1. 优先在按钮左侧展开，避免覆盖常见右侧停靠按钮。
2. 左侧空间不足时放到右侧。
3. 横向不足时放到按钮上方或下方。
4. 最终结果必须 clamp 到当前显示器 workArea 内。
5. 浮窗与按钮保持 `10-14px` 间距，不压住按钮。

拖动规则：

- pointer down 后记录起点。
- 超过阈值才进入拖动态。
- 拖动中关闭助手工作区。
- pointer up 后结束拖动并抑制一次 click。
- 按钮位置不吸边，先保持用户放置的位置；吸边可以作为后续优化。

视觉规则：

- 不再使用过小的菜单样式。
- 工作区是紧凑工具面板，不做营销式大卡片。
- 页签、动作按钮、确认区和反馈区保持同一视觉系统。
- 状态反馈必须可读，失败时列出缺失目标或执行日志。
- 中文文案必须使用正常 UTF-8，不接受乱码进入新代码和新文档。

## 6. 数据流

### 6.1 打开工作区

1. 用户点击系统悬浮按钮。
2. `FloatingSealApp` 调用 `toggleFloatingAssistant()`。
3. 主进程根据按钮 bounds 创建或显示 `floatingAssistantWindow`。
4. `FloatingAssistantApp` 初始化后调用 `requestAssistantSnapshot()`。
5. 主进程确保主窗口存在，并向主窗口请求 active webview 上下文。
6. 主窗口读取标题、页面上下文、收藏库状态和偏好后返回给系统浮窗。

### 6.2 执行动作

1. 用户在系统浮窗点击动作。
2. 若动作需要确认，系统浮窗内打开确认 UI。
3. 系统浮窗调用 `runAssistantAction(action, options)`。
4. 主进程确保主窗口存在、可见，并把执行请求转发给主窗口。
5. 主窗口使用 active webview 执行现有自动化逻辑。
6. 执行结果回传给系统浮窗，浮窗展示成功、失败、日志和缺失目标。
7. 成功的偏好反馈写入本地存储，并刷新浮窗快照。

### 6.3 札记和掌库

札记生成和掌库操作都从系统浮窗发起，经主进程转发到主窗口执行。主窗口负责 webview 脚本和本地存储，系统浮窗负责进度、结果、错误和用户确认。

## 7. 错误处理

- 主窗口不存在：主进程创建主窗口，等待 ready 后再继续请求。
- 主窗口最小化：执行前恢复并聚焦，保证 webview 可运行。
- active webview 不存在：系统浮窗显示可恢复错误，不吞掉失败。
- 页面脚本失败：返回失败日志和缺失目标，保留在系统浮窗内。
- 收藏分库缺失：在 `掌库` 页签提示创建，不在批阅区反复打断。
- 札记提取失败：允许用户粘贴手动稿件后继续生成。
- 系统浮窗失焦：默认保留打开，避免填写札记或选择评论时意外丢失；关闭按钮和 Esc 显式关闭。

## 8. 测试策略

单元测试：

- 工作区几何函数覆盖左侧、右侧、上下翻转、workArea clamp、小显示器和负坐标显示器。
- `FloatingSealApp` 覆盖点击打开、拖动关闭、拖动后抑制 click。
- `FloatingAssistantApp` 覆盖 `批阅 / 札记 / 掌库` 页签存在且可切换。
- 动作按钮覆盖确认动作和直接动作的 IPC 调用。
- 确认 UI 覆盖投币数量、评论选择和取消。
- 主窗口执行桥覆盖成功、失败、无 webview 和 delayed ready。

集成测试：

- `main.tsx` 根据 `window=floating-assistant` 渲染系统工作区。
- 主窗口默认不显示助手面板。
- 系统浮窗动作经 IPC 到主窗口 runtime，再返回结果。
- 偏好、札记和收藏库状态仍使用现有存储。

人工验证：

- Windows 桌面拖动按钮，移动自然且不误开。
- 屏幕四角点击按钮，工作区不出屏、不遮挡按钮。
- 主窗口最小化时从系统浮窗执行动作，主窗口能恢复并执行。
- 投币、评论、札记、掌库全程不需要主窗口内助手面板。

## 9. 后续优化和改进

1. 抽出 `FloatingAssistantController`，把窗口生命周期、几何和 IPC 路由从 `electron/main/index.ts` 中拆出去。
2. 建立显式状态机：`idle / dragging / workspace-open / confirming / running / error`，减少边界状态散落在组件里。
3. 统一中文文案、编码和领域词表，移除现有乱码文案。
4. 建立设计 token：颜色、间距、字体、按钮尺寸、状态色统一管理。
5. 增加键盘体验：Esc 关闭、Tab 顺序、焦点回环、按钮 tooltip。
6. 增加多显示器与 DPI 测试夹具，覆盖负坐标和缩放比例。
7. 把 Bilibili 自动化拆成 DOM、API、视觉兜底三层，并让每层失败原因可观测。
8. 加入动作队列和取消机制，防止用户连续点击导致自动化重入。
9. 增加悬浮按钮位置持久化，重启后恢复用户放置的位置。
10. 后续评估托盘、全局快捷键、开机自启和权限提示。

## 10. 当前不做

- 不做扇形菜单动画。
- 不重写 Bilibili 自动化脚本整体架构，只补齐系统浮窗所需桥接。
- 不引入新的前端状态管理库。
- 不做安装包、托盘、开机自启。
- 不做复杂吸边动画，先保证拖动自然、位置稳定、边界正确。
