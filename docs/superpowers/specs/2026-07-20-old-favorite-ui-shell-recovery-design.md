# 整理旧藏 UI 外壳恢复设计

最后更新：2026-07-20

## 背景与问题

新主进程核心已经替换旧 session/runtime/scan/workspace 状态机，但正式 UI 在删除旧核心时被替换为约 186 行的开发骨架。该骨架暴露收藏夹文字列表和命令按钮，丢失原有掌库侧栏的信息层级、四步向导、状态反馈、归档预览及完成一轮整理所需的连续交互。

这属于产品验收失败，不是视觉微调。整改必须恢复旧 UI 的成熟外壳与用户路径，同时禁止旧状态机重新进入正式构建。

## 目标

- 恢复替换前的掌库侧栏视觉密度、区域顺序、控件语义和四步向导。
- 新用户可以连续完成：点击整理旧藏 -> 立即看到扫描中 -> 选择来源与推荐 -> 自动分类 -> DeepSeek/人工调整 -> 多步撤销恢复 -> 一次确认 -> 执行/对账 -> 完成。
- 页面切换、组件重挂载、应用重启和账号切换后，从主进程快照恢复原步骤和操作结果。
- 保持收藏库为独立入口和独立三栏窗口，不将其合并为整理旧藏第五步。
- 继续以 Electron 主进程工作区/账号仓库为唯一权威；React 只渲染快照和发送命令。

## 非目标

- 不恢复旧 `FavoriteLedgerPanel.tsx` 的状态机、session、runtime、扫描器、恢复补丁或旧 IPC。
- 不重新形成万行单文件。
- 不大改掌库整体主题、侧栏宽度、蓝白配色或顶部页签。
- 不在此次整改中重新设计收藏库窗口。

## 信息架构

掌库保持三个相互独立的区域：

1. 收藏夹管理：显示现有收藏夹、缺失工作夹提示、新增本地逻辑收藏夹和规则保存。
2. 整理旧藏：独立入口，展开四步向导。
3. 收藏库：与整理旧藏并列的独立按钮，打开三栏窗口。

整理旧藏四步保持：

1. 扫描概览
2. 推荐收藏夹
3. 归档预览
4. 确认执行

步骤只能按主进程快照状态解锁。单分段时不显示分段概念；超过 `segmentSize` 时才显示当前组、总组数和切换控件。

## 组件边界

```text
ControlledFavoriteLedgerPanel
├─ FavoriteLedgerOverview
├─ OldFavoriteGuide
│  ├─ OldFavoriteScanOverviewStep
│  ├─ OldFavoriteRecommendationStep
│  ├─ OldFavoriteArchivePreviewStep
│  └─ OldFavoriteConfirmationStep
└─ FavoriteLibraryEntry
```

- `ControlledFavoriteLedgerPanel` 只负责区域编排、入口和当前步骤。
- 每个步骤只接收快照切片和命令回调，不保存权威业务状态。
- 归档预览仅渲染当前分段，超过阈值使用现有虚拟列表。
- UI 可保存本地展示状态（折叠、当前展开步骤），但步骤可用性、选择、分类、历史、执行状态均来自主进程。

## 视觉与交互恢复

- 复用 `src/renderer/src/styles.css` 中现存的 `favorite-ledger-panel__*` 样式和替换前的 DOM 层级，不新建第二套主题。
- 删除当前裸露的 `bilimi:*` 文字堆叠与开发式按钮布局，恢复卡片、折叠区域、步骤导航、进度区和紧凑预览卡。
- 点击“整理旧藏”后立即显示扫描概览；开始命令未返回时也要显示可理解的启动反馈。
- 扫描中禁用后续步骤；扫描结束后来源选择可操作，推荐、预览和确认按状态逐步开放。
- 归档预览显示标题、UP 主、来源、分类来源/置信、目标收藏夹和未分类状态；人工选择直接发送差量命令。
- DeepSeek 整批操作显示运行中状态，完成后作为单个历史步骤。
- 撤销/恢复按钮根据主进程历史游标禁用或启用。
- 多分段确认显示整体准备度；未完成全部分段时禁止执行。
- 执行中显示进度，结果未知显示对账入口，完成态只读且不出现重复执行按钮。
- “全部重新整理”作为次级危险操作，明确说明会解除既有保护，但仍走受控 `start-scan/full`。

## 收藏库

- 收藏库按钮与整理旧藏入口并列，视觉层级一致。
- 收藏库继续打开独立 Electron 三栏窗口：左侧收藏夹导航、中间虚拟化视频列表、右侧详情。
- 收藏库动作继续使用已实现的窄权限 IPC、账号级远程仲裁和独立任务状态，不回灌整理旧藏 UI。

## 错误与恢复

- 损坏工作镜像显示明确恢复卡片，只允许“重建工作镜像并重新扫描”。
- 扫描失败保留来源概览和失败原因，提供受控重新扫描。
- 远程结果未知只能对账，不提供盲重试。
- 账号切换立即清空上一账号的渲染快照，等待新账号主进程快照。
- UI 组件异常必须由局部错误边界承接，不能让整个 B 站主界面黑屏。

## 验收标准

- UI 与替换前版本的区域顺序、四步向导、视觉密度和主要控件一致，不出现开发骨架式文字/按钮堆叠。
- 正式产物不包含或引用旧状态机与旧 IPC。
- 面板完整流程测试覆盖来源、推荐、自动分类、DeepSeek、人工调整、多步历史、分段、仅本地保存、一次 B 站确认、对账和完成态。
- 覆盖切页/重挂载、重启、账号隔离、损坏恢复、30000 条虚拟化与同步中防重复提交。
- `npm test`、`npm run build`、`git diff --check` 通过。
- 开发版实际窗口完成 UI 对照验收；准备发布时再按 `docs/release-checklist.md` 完成 dev、preview、安装包三形态验收。
