# 批阅入库与所选视频整理设计

## 目标

修复批阅操作到收藏库之间的数据断链，并在此基础上支持只对收藏库中选中的视频复用现有归档预览进行重新整理。整个链路必须保持页面可关闭、鼠标可移动、DeepSeek 二审可后台完成，且不能覆盖全库整理草稿或引入全库重复扫描。

## 范围与不变项

- 先处理批阅成功后的本地收藏库写入、远端归属观察、数量 revision 和元数据同步。
- 批阅使用冻结的 AID、账号和视频上下文；DeepSeek 二审不依赖当前视频页仍然打开。
- API 已确认成功时直接走接口结果；没有可靠远端确认时标记待核对，不伪造已同步。
- 页面兜底不得滚动整个 body、发送无关按键或扰动播放器弹幕层。
- 保留现有 DeepSeek 请求格式、关键词分类、推荐收藏夹、LocalData、转写、模态框、播放器和其它助手 tab 行为。
- 收藏库选中整理只处理选中的 AID，不启动全库扫描。

## 端到端数据流

```text
批阅页面读取冻结上下文
  → B站收藏/API结果确认
  → 本地视频、归属、远端观察、事件与 revision
  → DeepSeek 二审后台按 AID 继续
  → 本地 bilimi 目标更新并进入远端同步队列
  → 收藏库显示最新状态
  → 用户可选中视频进入独立小范围归档预览草稿
```

### 批阅成功入库

成功后按小型本地事务提交：视频标题、UP、简介、标签、AID/BVID/CID，来源收藏夹，当前 bilimi 目标，远端已确认位置和审计事件。发布 revision 让收藏库数量和行详情立即更新。普通用户收藏夹只保留其既有关系，bilimi 归属由整理结果管理。

### 状态语义

- `已同步`：本地期望归属与最近确认的 B 站归属一致。
- `已保护`：已有正式 bilimi 整理记录，后台增量整理默认跳过；用户明确选中重新整理时临时越过。
- `已整理`：存在正式 bilimi 分类记录，不等同于远端同步成功。
- 收藏归属区域分别展示本地期望、B 站观察和位置关系。
- 来源与时间保留批阅、入库、二审、分类、同步、资料补全等事件链，并继续支持查看完整整理记录。

### DeepSeek 二审

二审绑定批阅时的账号和 AID。页面关闭或切换不取消后台任务；结果不回头操作当前页面，而是更新本地目标并排入现有远端同步队列。失败保留本地计划与可重试状态。

## 收藏库所选视频整理

收藏库批量操作区增加“重新整理”。选中视频进入独立小范围草稿：不覆盖全库整理草稿，使用同一归档预览组件、DeepSeek、推荐收藏夹、手动编辑、撤销恢复和保存流程。

进入预览前只补全选中视频缺失的资料。bilimi 管理的收藏夹归属按结果替换；用户其他收藏夹只追加。本次选中明确覆盖保护规则；未选中的视频和后台自动任务仍遵守保护规则。

## 元数据和标签持久化

统一补全入口识别 `Video 具体AID` 与 `Video + ID` 两种占位标题。真实标题、UP、简介、封面或标签一旦确认，后续稀疏扫描不得覆盖；空字段不得清除已有字段。

- 批阅页面已读取的简介和标签直接入库。
- 收藏库“刷新信息”补全后立即持久化，退出重进仍保留。
- 所选视频进入预览时，扫描概览逐项补全并保存，失败项可重试或跳过，不交给 DeepSeek 猜测。
- 三万条场景只补当前整理分段和用户主动选中的视频，不在扫描开始时集中发起三万次标签请求。
- 详情字段显示“简介：”和“标签：”。

## 草稿、撤销与同步

小范围草稿记录选中 AID 的旧 bilimi 归属、用户收藏夹关系和本次新增差异。撤销/恢复只操作草稿，不重新调用 DeepSeek。保存后本地 revision 先提交，远端同步沿用现有队列；已同步后的撤销生成反向同步计划并保持确认语义。

## 错误与性能边界

- 每个 AID 的资料补全和远端同步都可取消、重试，不能阻塞鼠标、窗口控制或视频切换。
- 进度只更新自身状态，不滚动页面、不改变播放器布局、不隐藏弹幕层。
- 不把 jsdom 通过或任务完成时间当成物理输入不卡顿证明；必须在真实 Electron 开发版验证批阅、关闭视频、切换视频、收藏库刷新和所选整理。

## 验收与回归

- 批阅新增视频后收藏库数量、标题、简介、标签和来源事件立即可见，退出重进不回退。
- B 站确认成功与未确认两种路径分别显示已同步和待核对。
- DeepSeek 二审在关闭/切换视频后仍能完成并更新对应 AID。
- 占位标题不会覆盖已刷新标题；资料补全失败可重试。
- 所选整理只处理选中视频，保护覆盖、bilimi 替换、用户收藏夹追加和独立草稿均正确。
- 推荐收藏夹、手动调整、撤销恢复、现有全库整理和其它页面功能回归测试通过。
