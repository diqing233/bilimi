# 备册改名绑定与删除校验修复设计

## 目标

让一次明确的精确 `folderId` 备册确认在 B 站改名成功后，把最终远端标题可靠写入正式物理分册绑定；删除模式据此完成同一 ID 的删除并收敛为“未备册”，同时把改名回执、删除前标题失真和远端删除结果区分为可诊断阶段。整个流程不按名称认领、不创建第二个远端收藏夹、不写视频，并保持主窗口事件循环可响应。

## 现状与根因

`FavoriteRepositoryBindingService` 已按精确 ID执行改名和有限目录复读，但没有检查 `renameFolder` 返回的 `status`。更重要的是，渲染层登记成功绑定时沿用候选的旧 `remoteTitle`，可能把改名前标题再次写回账号偏好。删除服务随后用正式仓库 `physicalShards.remoteTitle` 与当前 B 站目录标题做严格比较；标题不一致会在调用删除接口前抛出通用错误，因此用户看到“删除未成功”，但实际没有执行远端删除或解绑提交。

## 设计

1. **绑定事务以最终远端事实为准**：检查改名桥接的 `status` 和诊断字段；只有同一精确 ID 的目录复读确认目标标题后才提交。返回给渲染层的成功绑定结果从正式快照提取最终 `remoteTitle`，渲染偏好不得用候选旧标题覆盖它。
2. **删除阶段可诊断**：保留精确 ID和标题安全校验；标题过期时抛出稳定的阶段错误，前端显示“绑定账本标题已过期，请先重新备册/刷新后再删除”，不调用 B 站删除、不清理绑定。远端删除成功后继续现有 `remove-physical-shard-binding` 提交和权威快照刷新，页面变为“未备册”。
3. **幂等与并发边界**：改名只发送一次；复读和刷新使用现有非阻塞等待与远端操作仲裁。后置投影失败不能撤销已提交绑定；同 ID 重试只能复用既有绑定或补齐标题，不创建新夹。
4. **错误映射**：改名 `rejected/unknown`、目录复读耗尽、标题过期、删除被拒绝、删除结果未知分别保留内部稳定错误关键字，UI 显示阶段化中文文案；不再依赖“删除未成功，请稍后重试”覆盖所有情况。

## 测试与验收

- 先为改名桥接拒绝、改名最终标题回写、删除前标题过期和成功删除解绑分别增加失败回归测试并观察 RED。
- 运行绑定服务、同步服务、IPC、App 和草稿去重的定向测试，再运行 `npm test` 与 `npm run build`。
- 在真实 Electron 开发版用同一精确 ID验收：改名确认只发一次；弹窗成功关闭；仓库 `remoteTitle` 等于 B 站最终名称；删除成功后页面即时显示“未备册”，失败时显示具体阶段且 B 站与本地绑定均保留。连续鼠标移动、点击、滚动、缩放、最小化、恢复和关闭不得卡顿。
