# 旧藏扫描与归档预览稳定性设计

## 目标

修复旧藏整理中来源收藏夹身份混淆、数量口径不清、标签进度越界，以及标签后台快照破坏推荐收藏夹和归档任务的问题。真实执行仍只追加到 bilimi 收藏夹，不删除、移动或取消原收藏。

## 来源收藏夹

- 来源身份以 B 站收藏夹 ID 为准；标题只用于展示和兼容缺少 ID 的旧快照。
- 同名不同 ID 的收藏夹独立计数、独立勾选。
- 用户收藏夹显示三列：名称、总数、本轮待整理。总数来自 B 站文件夹元数据；本轮待整理按唯一视频去重并排除已整理保护项。
- 表头为“用户收藏夹 / 总数 / 本轮待整理”，数字右对齐，长名称截断但不挤乱数字列。
- 常驻说明：“待整理数会排除已整理视频，并对多个收藏夹中的同一视频去重，因此数量可能较少。”
- bilimi 工作夹是目标和保护判断依据，只读展示“已有”，不显示复选框或待整理数，也不进入来源选择。
- 扫描失败的用户收藏夹保留原始总数，待整理列显示“扫描失败”，不进入执行范围。

## 标签进度与归档快照

- 标签进度满足 `0 <= completed <= total`；同一扫描代次允许合法快照纠正此前的异常高值。
- 标签补取过程中只更新进度和标签缓存，不重建当前推荐或归档计划。
- 标签补取完成后只提示数据已更新，不自动重算。
- 用户点击“刷新归档预览”或离开后重新进入归档预览时，才以最新标签重算。
- 归档预览重算必须从稳定的扫描来源和持久收藏夹配置生成，再迁移来源选择、候选选择和未冲突的人工状态；不能把临时推荐夹当成已持久化收藏夹。
- “确认执行”使用当前可见的固定快照。

## DeepSeek

- 标签未补取完成时点击 DeepSeek 整理，先提示准确性风险。
- 用户可继续等待，或明确选择“使用当前标签整理”。
- 使用当前标签启动后，本次 DeepSeek 使用固定快照；后续标签完成不自动覆盖其结果。

## 扫描失败

- 文件夹列表读取成功但分页内容失败时，记录文件夹 ID、标题、失败页码和可读错误。
- 使用秒级递增退避重试，而不是毫秒级连续请求。
- 已成功读取的页面保留；失败来源保持不可选，并允许只重试失败来源。
- UI 区分成功、部分成功和失败，显示具体原因；失败来源不进入执行。

## 验证

- 单元测试覆盖同名不同 ID、重复来源、bilimi 工作夹只读、列式文案、扫描失败和标签进度纠正。
- 交互测试覆盖标签完成不自动重建、重新进入或主动刷新才重算、DeepSeek 未完成标签提醒、候选与任务不被清空。
- 发布前按 `docs/release-checklist.md` 完成 dev、preview、真实安装包三形态验收。
