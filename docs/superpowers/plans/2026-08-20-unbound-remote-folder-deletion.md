# 未绑定 bilimi 收藏夹知情删除实施计划

**目标：** 修复已进入右侧删除确认流程的默认工作夹，在完成知情确认且 B 站删除成功后，因不存在本地物理绑定而被误报删除失败的问题。

**架构：** 远端删除的候选快照既区分`bound`、`missing-remote`和`unbound-name-match`。只有候选在删除前确有本地物理绑定时，成功后才提交解除绑定；默认工作夹删除确认流程中名称匹配的未绑定候选仅记录远端删除成功，随后走既有右侧规则/收藏库分层流程。自建未正式绑定规则继续只走本地删除路径。

**测试：** 先在 `favoriteRepositorySyncService.test.ts` 构造“未绑定名称匹配 + acknowledge=true + B 站返回成功”的真实服务回归，确认现状失败；以最小改动通过，再运行关联界面和 IPC 测试、全量测试与构建。

## 任务

1. 将未绑定知情删除的最终行为写入项目书和本轮需求账本，并逐项锁定不改边界。
2. 添加失败回归：未绑定名称匹配的远端删除成功时，服务返回`status: succeeded`，且不会提交不存在的`remove-physical-shard-binding`。
3. 在同步服务中仅对删除前确有本地绑定的成功候选解除 physical-shard 绑定；保持已绑定、缺失远端和部分成功行为不变。
4. 运行聚焦回归、相关界面/IPC 测试、全量测试、构建与 diff 检查；更新账本实施记录并进行一次本地提交。
