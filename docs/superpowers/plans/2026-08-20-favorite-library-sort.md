# 收藏库时间排序修复实施计划

## 范围与依据

本计划只覆盖需求账本 `docs/requirement-ledgers/2026-08-20-favorite-library-sort.md` 的已确认条目：R001、R002、R003-S1、R004-S1、R005-S1。R003-D1（是否把“最近更新/最早更新”改名为“最近调整/最早调整”）仍待用户决定，本轮保留现有文案，不改菜单和标题文字。

## 实施顺序

1. **项目书语义（R001、R002、R003-S1、R004-S1、R005-S1）**
   - 允许文件：`docs/项目功能项目书.md`。
   - 结果：明确时间排序使用 `video.lastAdjustment.occurredAt`；同时间正 aid 升序；缺失/无效时间两种方向置底；过滤后排序再分页；默认排序、恢复、缓存和筛选保持同一枚排序值；列出会/不会刷新时间的操作。
   - 风险：不能改写上一主题的本地登记设计或扩大到 B 站收藏时间迁移。
   - 验收：逐项对照 R003-S1、R004-S1、R005-S1 的字段、缺失值和边界文字。

2. **主进程排序契约与测试（R001、R003-S1、R004-S1、R005-S1）**
   - 允许文件：`electron/main/favoriteRepositoryService.test.ts`、`electron/main/favoriteRepositoryService.ts`，必要时仅调整已有共享排序类型/IPC 测试。
   - 结果：`updated-desc`/`updated-asc` 协议值继续保留以避免迁移，但比较 `lastAdjustment.occurredAt`；缺失/无效日期统一置底；同时间 aid 升序；显式和默认读取都经过同一排序路径；完整过滤集排序后再分页；缓存键继续区分排序值。
   - 风险：影响收藏库分页、全选当前页、恢复和已有主进程缓存；不改 B 站动作、持久化结构或调整时间写入逻辑。
   - 测试：补充两种方向、同时间、缺失/无效日期、默认排序、过滤/分页和缓存恢复的单元回归。

3. **渲染器默认值、恢复和交互回归（R001、R004-S1）**
   - 允许文件：`src/renderer/src/features/favorites/FavoriteLibraryApp.tsx` 及其现有测试文件。
   - 结果：默认加载、恢复、待处理跳转和所有分页读取显式传递当前排序；切换排序回第一页；旧请求不能覆盖新排序结果；现有菜单文案保持不变。
   - 风险：账号/范围切换、搜索、筛选和详情状态可能依赖页码与排序 key；不改变列表时间列、选择语义或相邻批量操作。
   - 测试/界面验收：排序切换后首页顺序、关闭重开恢复、搜索/筛选携带排序、翻页边界和列表标题与实际顺序一致。

4. **验证与账本回写（全部已确认条目）**
   - 运行聚焦测试、`npm test`、`npm run build`、`git diff --check`。
   - 在真实 Electron 开发版验证收藏库最近/最早排序、同时间稳定顺序、缺失时间置底、分页和关闭重开；不执行 B 站写操作、扫描、迁移或时间回填。
   - 将代码位置、自动化结果、界面验收结果分别回写需求账本索引；任一条无法验证则在最终报告中单独列出。

## 明确排除

- 不实施 R003-D1 的文案改名。
- 不使用 `updatedAt`、`classificationAt`、`position.updatedAt`或 B 站 `fav_time` 作为本轮排序字段。
- 不新增列表时间列，不补写/迁移历史 `lastAdjustment`，不触发扫描、标签补取、DeepSeek、转写、同步或 B 站远端操作。
