# bilimi 1.1.0

## Highlights

- Favorite Library now uses a compact blue-white three-column workspace: folder navigation, virtualized video rows, and a persistent detail pane are visible together.
- Batch and folder actions distinguish local organization from real Bilibili mutations. Copy is additive; move only changes the active bilimi work-folder membership; local deletion preserves Bilibili favorites and local archives; Bilibili unfavorite removes remote favorite memberships only after preview and explicit confirmation.
- Managed-folder deletion defaults to local-only removal. A remote deletion shows its current baseline, affected count, unmatched fallback, and extra-membership warning before a second danger confirmation. Unknown remote outcomes are recorded for reconciliation and are never automatically retried.
- Local Data & Migration adds UID-scoped export/import preview, merge-or-overwrite choices, validation, rollback staging, and cleanup levels. Migration excludes Bilibili sessions, cookies, DeepSeek keys, device keys, proxy/runtime state, cache, logs, and temporary audio.
- A settled seek can lightly repaint an existing Bilibili danmaku layer without changing playback, fetching danmaku, or changing the user’s danmaku switch.

## Upgrade Notes

Existing local profiles remain in place during a normal installer upgrade. Before using overwrite import or full clear, export data that must be retained. Full clear affects local application data and login/session data only; it does not delete Bilibili server-side favorites or videos.

## Safety Boundary

No release validation should perform a real Bilibili write merely to test this version. Automated tests cover write semantics with mocks. In normal use, inspect every preview and reconcile any result-unknown record before starting another remote action.
