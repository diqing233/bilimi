## 全局不变原则

1. **浏览和本地资料优先可用。** B 站登录、网络、页面结构、DeepSeek 或媒体工具出错，只影响相应远端能力；不应让本地收藏库、札记、档案或设置整体不可用。
2. **真实 B 站写入必须可感知。** 点赞、投币、收藏、弹幕/评论、创建或同步 B 站收藏夹、取消 B 站收藏等操作，必须有进行中、成功、失败或待核对反馈；页面实际结果是最终事实。
3. **本地与远端要分清。** “保存”“仅保存到收藏库”“取消推荐”“从收藏库删除”和“同步到 B 站”不是同一动作，不能因实现方便互相替代。
4. **草稿与已执行方案要分清。** 整理收藏的扫描、推荐、预览、人工调整和 DeepSeek 调整在确认前都是可继续修改的草稿；冻结并开始真实 B 站执行后，分类方案不可再静默改变。
5. **一个业务状态只允许一个权威来源。** 账号级收藏仓库和整理工作区由 Electron 主进程持久化；页面只能显示快照并发送命令，不能另存一份会与其他页面脱节的真相。
6. **失败不伪造成功。** 请求失败、结果未知、保存尚未完成或用户取消时，必须保留真实可重试/可对账状态；不能先关闭对话框、取消勾选或清空草稿再声称成功。
7. **耗时操作不得阻塞界面。** 远端读取、绑定、改名、删除、备册、快照持久化和大列表重算必须分段或排队执行；点击后立即显示准确的进行中状态，鼠标移动、点击、滚动、窗口缩放、最小化、关闭和取消入口始终可响应。不得用同步阻塞、整页重渲染、假进度、静默跳过校验或禁用整个窗口换取表面速度；每个阶段必须保留可恢复的成功、失败、取消或结果未知事实。

`确认并同步到 B 站`的备册状态刷新必须采用单飞/去重的权威读取；同一账号的重复状态读取不得叠加到一次点击上，也不得阻塞无关页面。必要的确认按钮可以防止重复提交，但不得把整个整理区域设置为忙碌光标或以整页重渲染制造卡顿。同步进度只有在备册/绑定完成且权威状态刷新成功后才出现；状态读取失败时保持可读错误和可重试入口。

## 1. 应用窗口与 B 站浏览

### 1.1 首次启动、主窗口与全局反馈

| 控件或状态 | 作用与正常结果 | 不同情况下 | 不会影响 |
| --- | --- | --- | --- |
| 首次启动前权限检查 | 说明桌面能力和外部服务边界；用户确认后记录已完成引导，后续进入主界面。 | 长时间“启动中”时应可完全退出重开；仍失败时使用设置中的诊断。 | 不应要求用户把 B 站密码写入设置。 |
| 主窗口 | 同时承载网页标签栏、中央 B 站浏览区和右侧助手。 | 窄窗口应压缩布局但不能让网页横向溢出、按钮互相遮挡或隐藏主要状态。 | 助手开关不能销毁网页标签、当前页面或本地数据。 |
| 全局提示与状态灯 | 收起时显示最近一次跨页反馈的前两行；展开时按“前两行 → 无标题的第三行续文（仅在确有剩余文字时） → 后台任务 → 最近提示”顺序显示。`DeepSeek`、`转写音频`、`整理`状态灯能跳到相应功能区。 | 长耗时操作必须显示进度或进行中；失败提示应指出登录、网络、页面、工具或配置原因。提示超过两行时，第三行续文必须完整显示后才进入后台任务和最近提示；两行以内不显示空续文。 | 不新增“当前提示”标题、独立提示卡或重复提示；某一个后台任务的错误不应阻塞其他页签。 |
| 最小化、恢复、关闭 | 按设置处理窗口关闭行为；恢复后保留可恢复的窗口和助手状态。 | 整理/转写运行时关闭不应丢弃已经确认的检查点；真实远端执行按冻结计划和恢复规则处理。 | 不能把“关闭窗口”误做成删除草稿、清空本地数据或取消已确认远端操作。 |

**整理界面可见性边界。** 掌库收藏夹卡片与详情的备册/绑定状态以当前账号的权威快照为准。只有“整理收藏”向导实际展开并对用户可见时，卡片级远端生命周期状态才隐藏；工作区已经创建、暂停、恢复、存在快照或后台仍有任务，均不等同于整理界面正在展示。整理界面收起后必须立即恢复卡片状态，详情始终显示真实状态；该可见性投影不能改变规则、勾选、分类、备册或同步资格。

**全局提示滚动边界。** 展开全局提示时，前两行和无标题的完整续文属于固定顶部内容，按既定顺序直接显示，不参与滚动；滚动容器从“后台任务”标题开始，仅包含后台任务和最近提示。续文与第二行之间不绘制分隔线，任务点击、状态灯导航、提示文案和历史持久化保持原有语义。

**启动与窗口响应性。** Electron 首次启动时，代理偏好、可恢复事务、收藏夹快照和诊断初始化必须异步分段执行，不能把主窗口创建或事件循环推迟到所有磁盘/网络步骤完成后。主窗口出现后，鼠标移动、点击、滚动、最小化、恢复和关闭都必须可响应；启动失败只能显示可退出、可重试的局部状态，不得用整页遮罩或忙碌光标掩盖阻塞。B 站首页首次加载是主窗口就绪后的第一项后台网页工作：它必须在独立、可取消的后续任务中挂载/刷新，不得与首帧、偏好恢复或小咪创建同步执行；加载成功、完成或失败收束后才释放小咪自动创建资格，网络未收束不得阻塞主窗口。小咪是非关键伴随窗口：只可在主窗口交互和 B 站首页首次加载阶段收束后，让出事件循环再创建隐藏且透明/点击穿透的小咪；不得以固定短延时猜测首帧，也不得让小咪窗口创建、DWM/标题栏处理或鼠标恢复轮询占用主窗口首帧。小咪后台预热的完整顺序固定为“主窗口交互就绪 → 独立发起 B 站首页首次加载 → 首页加载成功/完成/失败收束 → 可取消空闲任务创建隐藏且透明/点击穿透的小咪窗口 → 小咪 renderer 完成 → 轻量初始化透明、点击穿透和鼠标恢复（不轮询）并 `showInactive()` 显示 → 记录可见状态 → 后台执行白条/DWM 与标题栏修补 → 可见后才允许鼠标恢复轮询”；任何一个前置未完成都不得拦截指针，原生修补不得成为小咪显示前的 awaited 门槛。后台阶段若检测到事件循环或输入响应超出预算，必须让路、延后或取消，小咪不得反向阻塞主窗口。

**安装版启动顺序与鼠标验收。** 主窗口创建、首帧提交和渲染器交互就绪是启动阶段的硬前置；收藏夹状态读取只能在不阻塞首帧的异步任务中进行。小咪窗口、标题栏/白条处理、鼠标恢复轮询和其它伴随控制器必须在交互就绪后再分段调度，每个阶段都要让出主事件循环；不得在窗口出现前启动同步磁盘/网络等待、外部进程或整窗遮罩。开发版和安装版均须验证启动期间鼠标移动、点击、滚动、最小化、恢复和关闭可响应；不能以“最终能打开”替代过程中的响应性证据。

**启动调度回归约束。** “交互就绪”只负责释放主窗口的后台资格，不直接在同一任务中创建小咪；首页 B 站加载 gate 与小咪 gate 必须分离，首页首次加载事件（`dom-ready`、`did-stop-loading` 或 `did-fail-load`）任一收束后才允许安排小咪。调度器必须使用浏览器空闲回调或等价的可取消空闲任务，并在每个网页、原生窗口/renderer、DWM/标题栏和鼠标控制器阶段之间让出事件循环；不能用固定短延时或连续 `setImmediate` 抢占首帧后的输入处理。加载异常或后台阶段超出响应预算时，主窗口继续完整可操作，小咪自动预热可延后/取消，下次显式唤醒再按同一就绪顺序创建。

**小咪原生修补的非阻塞约束。** 小咪 renderer 完成后必须先完成隐藏窗口的轻量交互初始化并以 `showInactive()` 显示，再在独立、可取消的后台阶段执行白条/DWM修补。`installFloatingSealWhiteStripFix` 的重绘不得作为显示前的 awaited 门槛；已验证会造成输入卡顿的 PowerShell/Win32 caption 修补不再进入启动路径。每一步均须让出主事件循环，失败只记录可诊断结果并保留透明、点击穿透和拖动语义。鼠标恢复轮询只能在小咪已可见后启动；修补迟到或失败不得阻塞主窗口、鼠标输入、窗口控制或显式唤醒。

**首页 WebView 的延后挂载。** 首页标签在首屏始终存在且仍是当前标签，但 B 站首页的 guest WebView 不得在主窗口首帧、偏好恢复或小咪窗口初始化的同一任务中同步创建。首屏提交并且主窗口交互就绪后，在让出渲染事件循环的独立后续任务中优先挂载并发起 B 站首页加载；该任务必须报告首次加载成功、完成或失败收束，供小咪后台 gate 使用。首次挂载不得额外显示“正在加载 B 站页面”遮罩、忙碌光标或阻断主窗口；网络长时间未响应不得阻塞主窗口或永久阻止小咪显式唤醒。已打开的网页标签、刷新、网页内跳转、当前页面绑定和助手上下文保持原有语义；这项延后只隔离首页的初始 guest/GPU 负载，不得改变 B 站页面 URL、Cookie、代理、登录或任何远端写入。

**首页收束看门狗边界。** 首页 WebView 的看门狗只用于记录“真实加载事件尚未到达”的诊断，不得把超时伪装成 `dom-ready`、`did-stop-loading` 或 `did-fail-load`，也不得仅因超时释放小咪自动创建 gate。主进程必须从已附加的首页 guest 缓存上述真实事件；若 renderer 在事件发生后才取得 guest id，缓存结果仍须在该首页 id 被可信主窗口认领后释放 gate。不得用其它标签、未知 guest 或超时代替首页的真实收束。网络未收束期间主窗口保持完整可操作，小咪自动预热可延后或取消，显式唤醒不受该自动 gate 限制。小咪被隐藏或关闭后，已经排队的窗口边界、鼠标恢复、白条/DWM 和标题栏阶段必须取消并在回调执行前再次检查窗口仍处于当前可见生命周期；停止鼠标输入后也必须重新经过稳定空闲窗口，不能把多个原生阶段集中到同一轮事件循环。

**Windows 安装向导完成页控制。** NSIS 安装向导完成页只负责收束安装流程，不改变 bilimi 主窗口或小咪窗口。完成页标题栏只保留可用的最小化和关闭两个系统按钮；不显示或启用最大化按钮，关闭只结束安装向导，不回滚已完成安装。底部保留有效的`完成(F)`按钮及`运行 bilimi`复选框行为；完成页不显示无效的`上一步(P)`和`取消(C)`按钮。该定制仅作用于完成页，不能改变安装目录、卸载页、用户数据删除选项或其它安装步骤。

**验收补充。** 全局提示展开时，前两行与无标题续文必须使用同一继承字体、字号、字重和行高；续文与第二行之间不画分隔线，第二行在存在续文时不得保留省略号。续文完整显示后才渲染后台任务和最近提示，不新增“当前提示”标题。所有渲染器可见错误（包括 IPC 远程调用包装和旧收藏工作区未启动）必须先映射为现有中文可读文案，底层错误码、失败状态和重试语义不变。安装完成页必须从顶层窗口样式和系统菜单实际移除最大化能力，`×` 走直接可用的关闭/退出路径；仅置灰或依赖隐藏取消控件均不合格。启动验收以首帧后鼠标在小咪出现前持续可移动、点击、滚动、最小化、恢复和关闭为准，任何原生边界、DWM、鼠标恢复或外部进程步骤不得作为显示前同步等待。

**启动输入优先与性能预算。** “鼠标不卡”是启动期的最高优先级，不是仅让窗口最终出现的结果。主窗口、已附加的 B 站 guest WebView 与小咪窗口必须把鼠标移动、按下/抬起、滚动、键盘、窗口拖动、缩放、最小化、恢复和关闭视为前台响应指标；自动创建小咪、加载其 renderer、DWM/白条/标题栏修补、鼠标恢复轮询和其它非关键初始化均属于后台工作，不能抢占真实交互。自动后台工作须经同一个可取消、输入感知的调度边界：按下/抬起、滚动、键盘、拖动、缩放、最小化、恢复和关闭到来时立即推迟尚未开始的后台阶段；每个阶段结束后必须重新检查输入，不得在同一事件循环轮或连续零延时任务中串联多个原生/GPU/外部进程步骤。连续 `pointermove` 必须始终保持流畅，但不能无限期阻止首页已真实收束后的自动小咪首次显示：自动首次创建只允许最小 hidden/透明/点击穿透窗口创建穿过连续移动；从首页真实收束起最少等待 600ms，并仍须在最近一次真实交互后的连续 600ms 安静窗口开始；自动唤醒已获资格而实际创建尚未开始时，同一 600ms 门槛必须再次核验。guest WebView 的任何按住鼠标移动都属于拖动这一真实交互，不能当作可忽略的普通移动。其 renderer 显示后的边界、置顶、鼠标恢复、白条/DWM 和标题栏修补仍必须在完整安静窗口逐段运行。该例外只用于自动首次显示，不放宽点击、滚动、键盘、窗口控制或用户显式操作的优先级；用户显式唤醒小咪仍可优先创建其必要窗口，但非必要修补和轮询继续遵守输入优先规则。自动预热被取消或延后时不得影响主窗口、B 站页面、Cookie、代理、登录、收藏、转写、DeepSeek、任何本地持久化或 B 站副作用。

**启动模块隔离与可观测性。** 主窗口、悬浮小咪、悬浮菜单和独立助手窗口必须按窗口路由加载各自需要的 renderer 模块；显示小咪或菜单不得同步解析主窗口的 B 站浏览、收藏、转写、DeepSeek 或侧边栏工作区。公共 React/基础样式可共享，但路由分流不得改变任一窗口已有 URL 参数、文案、辅助功能树、点击穿透、拖动、显式唤醒、窗口控制或 IPC 权限边界。开发诊断模式必须记录主窗口首帧、首页 guest 收束、自动后台任务排队/取消/开始以及小咪可见等阶段，并能明确看出是否因前台输入让路；诊断只写本地开发日志，不采集、不持久化和不发送用户输入、账号、Cookie、B 站页面内容或远端数据。自动测试只证明调度/模块边界，不能替代实机体验：开发版必须至少连续验证启动期间的鼠标移动、点击、滚动、窗口拖动/缩放、最小化、恢复、关闭及小咪自动出现前后均可立即响应；任一操作卡住、鼠标移动不连续或已有功能回归，必须停止声称本轮完成并继续定位。

**小咪启动默认开启。** “应用启动时自动唤醒小咪”是设备级、持久化的宠物设置，缺失值和新安装默认 `true`；已有持久化 `false` 必须继续保持关闭，不能被默认值迁移覆盖。首页真实收束后才允许进入自动小咪唤醒与后续创建/原生初始化链；关闭时不得创建小咪窗口、启动小咪 renderer、鼠标恢复或原生修补。设置中的`唤醒宠物`和其它用户显式唤醒入口立即显示小咪并持久写入 `true`；用户点击`关闭宠物`立即隐藏并持久写入 `false`。网页全屏的临时收起只能隐藏进入全屏前实际可见的小咪，并且只有这一次临时隐藏已经成功时才可在退出全屏后恢复；已保存关闭或小咪尚未创建时，进入和退出全屏均不得创建、唤醒或显示小咪。临时收起/恢复和主窗口退出告别不得改写该启动偏好。小咪启动路径永久跳过 `caption-polish`，保留已验证无白条的白条修复阶段，不再启动 PowerShell/C# Win32/DWM caption 剥离。不得借此开关改变主窗口、B 站首页加载、URL、Cookie、登录、风控、收藏、转写、DeepSeek 或任何本地业务数据/远端写入。

**既有能力保护边界。** 本轮发现的备册状态显示、保存后收藏夹投影、删除未绑定收尾和启动阶段鼠标响应均是既有版本已经实现并验证过的能力，不得当作新流程重写。修复时必须以历史正确提交与当前权威数据流逐段对照，只恢复缺失的状态转换、快照回写或调度边界：备册状态从账号权威快照投影到卡片/详情，删除未绑定后无需重启即可收束为真实`未备册`/`未绑定`；保存成功后规则、勾选和整理投影继续保留且使用同一稳定规则 ID；启动保持“主窗口交互就绪 → B 站首页独立加载 → 可取消空闲任务启动小咪”的非阻塞顺序。不得通过整仓回退、改动推荐取消语义、扩大删除范围、改变 B 站副作用或牺牲已修复的提示/安装向导行为来解决回归。每项恢复均须先有失败回归测试，且在开发版中保留真实窗口、鼠标和卡片/详情验收入口。

### 2.3 批阅结果的受保护边界

- 批阅写入 B 站前，必须验证当前标签仍是发起操作时的同一视频。
- 归库和 DeepSeek 二判不能越过收藏夹备册/绑定状态；未能远端写入时可保留本地预分类，但必须明确不是已同步。
- 批阅、整理收藏和收藏库共用同一账号收藏仓库；它们不能各自维护互相矛盾的视频归属。
- 批阅入口读到的目标必须使用第 4.1 节同一身份与数量口径：已保存未备册规则只能成为本地预分类目标，待绑定/待对账不是远端可写目标。
- 批阅失败不能删除札记、档案、转写、已有收藏关系或整理草稿。

**预分类建议与实际写入目标必须分离。** 所有已保存、已启用且非远端草稿的规则都参与本地预分类排序；只有已备册、已绑定并具有真实远端 `folder ID` 的规则才进入本次 B 站写入候选。最佳本地建议不可写时，仍显示并提示其`未备册`或`未绑定`，同时选择评分最高的可写匹配规则写入；账号中无关规则的未备册/未绑定缺口不得阻止该目标。没有可写匹配规则时，只有已启用、已备册且已绑定的`暂存`可作为回退；没有任何可写目标时不得请求 B 站收藏、不得登记已确认远端归属。回退反馈必须同时显示`预分类建议：X（未备册/未绑定）`和`已写入：Y`，绝不把 X 描述为已同步；备册、绑定、创建、移动和删除都不是批阅的隐式副作用。

### 2.4 批阅收藏后的本地登记一致性

批阅收藏是一个跨 B 站与本地收藏仓库的两阶段操作，远端成功和本地登记不得混成多条由页面逐条提交的命令。页面先完成 B 站收藏并取得实际返回的远端 folder ID，再把同一个 `operationId` 和最终目标提交给 Electron 主进程的专用批阅登记入口；主进程重新校验当前账号、目标 bilimi 规则、物理分片绑定、远端 folder ID 与 B 站成功证据，不信任页面自行伪造的保护或历史状态。

| 阶段 / 数据 | 设计要求 | 失败、重试与恢复 | 用户可见状态与边界 |
| --- | --- | --- | --- |
| B 站动作完成 | 只有 B 站接口或页面回读确认实际收藏成功，才进入本地登记；每个目标规则必须有对应的真实远端 folder ID。 | 未确认成功不得写“已同步”；结果未知保留内部操作记录，等待对账，不盲目重复 B 站写入。 | B 站状态只显示`已同步`或`未同步`；不增加“部分同步”“待核对”等第三种状态。 |
| 本地主进程登记 | 由专用主进程协调器在一个仓库事务中写入：视频基础资料、收藏位置、整理保护记录、`entered` 收藏历史事件，并发布一个新的权威 revision。 | 四类记录必须整体成功；失败不能提交半套结果。主进程保存可恢复操作记录，后续按同一 `operationId` 补齐。 | 本地技术故障不覆盖已经确认的 B 站状态，不删除已有视频、档案、札记或远端收藏。 |
| 幂等重试 | `operationId` 是唯一键；相同操作重复调用只返回现有结果或补齐缺失记录，不重复追加历史、不重复移动归属、不调用 B 站。 | 应用重启、重复点击、窗口重新打开均可安全重试；已有完整记录直接返回成功。 | 不显示重复操作提示；仅在内部执行日志记录重试次数和原因。 |
| 多目标与账号校验 | 主进程必须一次校验全部目标规则和 folder ID，目标有一个未绑定或不一致就不写入任何目标的本地登记。 | 校验失败保留 B 站真实结果和内部待补齐任务；修复绑定后可只补本地，不重新收藏。 | 不把页面的旧快照、名称相同规则或数量猜测当作身份依据。 |
| 异常退出与旧半成品 | B 站成功后进程在本地登记前退出时，启动/账号恢复流程读取操作记录，补齐视频、归属、保护和事件；已有视频/归属的旧半成品只补缺失项。 | 补齐不触发 B 站副作用；无法确认账号或目标时暂停内部重试并保留诊断证据。 | 不向用户增加中间状态；收藏库详情和历史以主进程最终快照为准。 |

**一致性顺序：** `B 站确认成功 → 主进程校验 → 本地四类记录原子提交 → 发布权威快照`。远端动作不能由本地补偿逻辑重复执行；通用 `favorite-repository:commit-command` 继续拒绝冻结工作区和保护类命令，页面只能使用专用入口。

## 4. 掌库：收藏夹身份、规则、备册与绑定

掌库管理的是“用户希望如何组织视频”的本地事实；B 站收藏夹是用户拥有的远端收藏夹，bilimi 工作区是本地规则、草稿、整理归属和仓库数据。B 站收藏夹、bilimi 本地工作区、扫描来源、推荐候选、收藏库视频行和整理草稿是不同层级的投影，不能把远端收藏夹再复制成第二份 bilimi 收藏夹列表。逻辑规则归属先由规范化实际名称决定：同一基础名称的 B 站收藏夹可以是同一逻辑规则的多个物理分册；规则类型和规范化关键词用于确认本地规则语义是否一致。远端 `folder ID` 只在用户确认某个具体远端分册后作为该实体的 API 操作句柄保留，不能作为名称匹配、删除后恢复、推荐联动或新规则身份依据。名称规范化只能兼容空格、宽窄字符和既有 bilimi 前缀书写；不得删除 `bilimi·` 后属于用户实际名称的首尾符号，故 `bilimi·-恒某人-` 与 `bilimi·恒某人-` 是不同名称、不同规则和不同候选。页面仍必须通过主进程权威快照读写，不能以候选短 ID、数量为零或远端结果缺失猜测身份。

### 4.1 身份、状态、数量与权威来源

**推荐与远端观察的唯一口径。** 推荐只由扫描事实派生；B 站远端目录不是本地规则来源。没有本地规则的远端 bilimi 收藏夹只在完整复核完成后作为只读发现结果提示，不生成“未保存 · 未绑定”草稿、推荐规则、墓碑或恢复记录。发现提示只在每账号本进程启动的首次快照、用户明确点击备册后最终目录复核、或 B 站实际创建/改名/删除成功且个人空间刷新为 `idle` 后发布；普通刷新、勾选、编辑、普通保存、整理扫描均不触发。每次先完整读取目录，并与本地已保存规则、正式绑定和删除记录复核；只提交最终完全陌生的远端夹，结果未变不重复提示。发现始终只读，不自动保存、绑定、创建、改名或删除。

**数量先说明口径，再显示数字。** `远端成员数`是一次已确认 B 站观察或对账得到的实际成员数；`本地已分配数`是收藏库当前本地归属到该逻辑规则的视频数；`本轮计划数`是当前整理草稿已选择、尚未冻结执行的数量；`—`表示该状态没有远端实体或远端数量未知。数字是事实的度量，**0 和非 0 均不改变身份**，未知不能显示为 0。

**展示层次与行为资格必须分开。** “用户收藏夹（B 站）”展示当前账号的全部远端收藏夹，包括名称含 `bilimi`、历史物理工作夹和已经绑定到 bilimi 规则的收藏夹；“bilimi 工作区”只展示本地草稿、规则和本地已整理/入库归属。一个已绑定的远端夹仍属于用户收藏夹；本地逻辑规则先按规范化名称归属，同名远端夹作为同一规则的多个物理分册，具体 `folder ID` 仅作为已确认分册的 API 操作句柄，不能复制成第二个本地规则。**扫描概览仍显示原有纯远端来源表格和逐夹选择信息；顶部合并标题显示为同一控件文案`全选（N）`，括号数量紧跟在“全选”旁，不删除收藏夹名称、数量、来源关系或数量切换。** 本地规则、已入库数量、备册和绑定操作在掌库管理与收藏库中查看。

| 身份 / 生命周期状态 | 数量与显示 | 可做的本地操作 | B 站与明确禁止 |
| --- | --- | --- | --- |
| B 站收藏夹（用户远端来源，包含名称含 `bilimi` 的夹） | 在掌库和收藏库的“用户收藏夹（B 站）”中显示远端成员数及本地关系短状态；扫描概览保留逐夹来源表格，表头复选框旁显示同一文案`全选（N）`，另保留`总数`和当前来源关系指标；N 为夹数而非视频数，0 或非 0 均保留。 | 全选控件在全选/全不选之间切换本轮来源范围；每个远端夹仍显示名称、数量与来源关系，扫描请求内部使用其 API 句柄。 | 名称只有在与本地规则或 `bilimi` 观察范围进行规范化匹配后才产生绑定候选；前缀、数量或“看起来像 bilimi”不能单独创建规则；扫描概览选择不能隐式创建规则、绑定或同步。 |

**删除与重新备册后的刷新。** 本地规则删除、解绑、备册、确认绑定或对账一旦返回权威结果，掌库、收藏库和当前整理草稿必须同时失效并从新快照重投影。备册或绑定成功后，必须先使当前账号的收藏夹状态缓存失效，再对本地仓库绑定和 B 站清单执行一次强制权威重投影，之后才能广播页面刷新；状态缓存不得在同一账号、规则签名或备册操作完成后的短时间窗口内继续返回旧的`missingLedgerIds`/`unboundLedgerIds`。在`确认并同步到 B 站`链路中，备册/绑定、权威状态刷新和同步启动必须严格按此顺序完成：只有权威刷新确认目标已备册/已绑定后，才允许切换为同步中并显示同步进度；备册失败、账号失效或结果未知时停留在确认窗口，不能启动同步或用乐观状态显示已备册。扫描概览只随下一次 B 站远端观察刷新夹的存在、名称、成员数和本轮统计；它不显示这些本地关系短状态。重新备册成功后掌库/收藏库短状态立即变为`已备册`；失败或结果未知时保留真实短状态与详情原因，不能继续显示旧关系，也不能伪造恢复成功。

远端删除确认成功后，删除事务必须先按精确 `folderId` 完成本地规则/草稿收尾，再使账号状态缓存失效并从同一账号权威仓库与 B 站观察结果重投影，最后只广播一次掌库快照变化事件。收藏库、整理草稿和桌面助手都只能消费这次权威快照；成功收尾时已删除远端夹不再显示，保留的默认规则显示`未备册`。触发删除的渲染器不能只刷新局部工作区：必须在局部刷新后消费同一账号的权威快照，令卡片、详情和未备册提示在当前页面同步收敛。只有本地收尾与权威重读均失败时才显示`本地状态待保存`检查点，不能把旧投影继续当作成功状态。

**远端候选删除也走同一收尾。** 已正式绑定工作夹、未绑定物理分册和历史精确 ID 虽然使用各自的候选预览与知情确认，但远端删除返回后都必须仅按本次**成功确认**的精确 `folderId` 汇总到同一个账号级本地收尾回调。回调负责清理已确认 ID 对应的绑定/账号偏好投影、失效缓存并广播一次新快照；失败、未知、未尝试或未确认的 ID 必须保留原投影。不得让候选删除绕过该回调而只能依赖重启时的 reconcile，更不能把候选删除扩大为规则删除、重分类、备册或视频同步。

**已备册的唯一事实条件与统一显示。** bilimi 逻辑工作夹只有在主进程快照中存在至少一个对应的 `physicalShards`，并且每个实际参与该逻辑工作夹的分册都具有真实远端 `folder ID` 且 `bindingState=bound` 时，才显示`已备册`。逻辑工作夹没有物理分册、物理分册为空、分册处于`pending-reconcile`/失败/未知，规则仍带有用户解除标记，或者快照的 `physicalShardCount` 与已返回的 `physicalShards` 明细数量不一致时，均不得显示`已备册`：已有已绑定明细但仍缺失/未收敛其它分册时显示`部分已备册 · 仍待绑定`，否则按当前生命周期显示`未备册`、`未绑定`或`收藏夹已删除`。主进程必须从同一账号的正式分册、规则删除标记和当前操作结果派生“完整已备册 / 未绑定 / 未备册 / 部分已备册”这一份状态；顶部状态灯、右侧规则卡片、详情和收藏库只能消费这份派生状态，不能各自用旧缓存、`bindingState` 或 `unboundLedgerIds` 另行判断。旧快照中“逻辑状态已绑定但物理分册为 0”的数据只做本地确定性修正，不读取、创建、删除、改名或移动 B 站数据；修正后所有页面以同一新快照显示。

**推荐采用不创建桥接实体。** 推荐候选采用、取消和联动只读扫描投影与普通规则的最新权威快照；不创建推荐专用桥接草稿，不用候选 ID 冒充规则 ID。普通规则一旦保存，后续备册、同步、删除和绑定完全沿用普通规则流程。

**多物理分册的账号投影。** 任一分册创建或绑定成功后，主进程必须以收藏仓库最新权威快照为唯一来源，按 `logicalLedgerId` 找出全部具有真实远端 `folderId` 且 `bindingState=bound` 的物理分册，按 `shardNumber` 稳定排序后一次性回投账号级 `favoriteLedgers`：`bilibiliFolderIds` 包含全部真实 ID，`bilibiliFolderId` 使用排序后的首个 ID，绑定数量和分册详情同步更新。投影必须保留规则 ID、显示名、勾选/启用状态、关键词和其他非绑定字段；完成后失效受影响账号缓存并广播一次最新快照，使右侧卡片与编辑器立即显示真实的“B站绑定：N 个收藏夹”。该过程只读并持久化本地仓库投影，不创建、绑定、删除、移动或同步 B 站，也不触发整轮重分类，不得阻塞按钮事件循环；没有正式 `bound` 分册时不得伪造绑定数量或`已备册`。

**未绑定后的显式重新备册与 ID 切换。** `未绑定`是可继续备册的状态，不是旧 ID 不同即中断的错误。用户从既有`备册`入口发起时，系统只读当前 B 站目录，按规范化名称和分册发现候选并展示每个候选的真实 `folderId`；名称命中本身绝不自动绑定。用户明确选定候选、当前账号与标题/分册校验通过、且该 exact ID 未正式绑定给另一逻辑册后，主进程才将该逻辑册/分册号的**活动**远端 ID替换为用户本次确认的新 ID并提交 `bindingState=bound`。该确认已有候选不创建、改名、移动或写入 B 站视频；无候选时仍须经过“确认创建并绑定”。主进程随后在同一受控本地收尾中从最新正式 `physicalShards` 回投账号规则，解除该逻辑规则的 `managedFolderDeletedByUser`，清除待确认字段，并且只从 `confirmedDeletedRemoteFolderIds` 移除本次确认的新 ID；不同的旧 ID 删除记录必须保留，继续阻止普通启动、扫描、名称发现或旧 ID读取自动复活旧收藏夹。改名、普通投影、远端目录刷新和重试都不得解除该删除标记或改写活动 ID。候选验证失败、账号不一致、新 ID 已正式属于另一逻辑册、用户取消或本地投影无法落盘时，保留可诊断的未绑定/待收敛事实；不得把候选名称、旧 ID或页面乐观状态显示成`已备册`。

**自动分册完成后的统一投影。** `确认并同步到 B 站` 或其他既有备册执行路径自动创建/绑定物理分册成功后，必须立即调用与显式绑定共用的账号级投影函数；该函数重新读取一次仓库最新快照，按本节规则合并同一 `logicalLedgerId` 的全部正式分册，再比较并持久化账号配置，最后只广播一次受影响账号的偏好与助手快照。自动容量分册、普通同步恢复和后台对账只更新正式分册与账号投影，**绝不**解除 `managedFolderDeletedByUser` 或删除历史；只有第 4.1 节中已持久化的用户明确候选/创建确认才能触发这一受控解除。不得只更新当前分册或依赖下次打开账号才补齐，因此同一逻辑收藏夹出现第二分册时，当前右侧卡片必须立即显示完整的“B站绑定：N 个收藏夹”。投影失败只能保留可诊断错误并由后续刷新重试，不得回写部分分册、覆盖勾选/启用字段或触发整轮重分类。

**账号打开时的降级顺序。** 账号打开阶段的远端待绑定检查、恢复和本地权威投影是相互独立的步骤。远端目录读取失败、登录失效或待绑定对账异常时，必须保留本地仓库已有的正式 `physicalShards` 事实，并继续执行本地账号级投影与页面快照广播；仅将远端检查标记为待重试，不得让异常短路投影，不能因此把已绑定分册降级为`未备册`或把绑定数量显示为旧值。该降级路径只读本地仓库并更新本地配置，不执行任何 B 站创建、绑定、删除、移动或视频写入。

**正式分册缺失的历史远端 ID。** 规则偏好中遗留的 `bilibiliFolderId`、`bilibiliFolderIds`、标题、数量或`bindingState=bound`都只是历史线索，不能替代正式 `physicalShards`，也不能继续投影为`已备册`。用户明确选择“同时从 B 站删除整个 bilimi 工作夹”时，删除预览必须对每条正式分册缺失但仍带历史精确 remote ID 的规则重新读取当前账号目录：目录仍含该**精确 ID**时，作为独立的“历史分册未正式绑定”候选列出，并沿用既有“我已确认”与未绑定知情确认后才允许删除；目录已不含该精确 ID时，列出为远端已缺失，仅在本次明确删除流程中收敛本地旧绑定。不得只因名称、`·2`等分册后缀、数量或列表次序猜测并删除其它 ID，也不得自动重新绑定或创建。远端删除成功或本次权威目录确认该精确历史 ID已缺失后，才清除对应历史 ID和旧`bound`投影，使规则回到`未备册`；失败、结果未知或未进入该确认流程时必须保留可诊断线索，不能伪造删除成功。

**未绑定物理分册与同名删除分组。** 规则已经显示`未绑定`时，只要权威仓库或本次新鲜 B 站目录仍能提供该物理分册的真实 `folderId`，该分册也必须进入“同时从 B 站删除”的同一删除预览，并与名称匹配的未绑定候选共用现有未绑定知情同意；不因分册处于`pending-reconcile`、绑定丢失或标题带`·N`后缀而阻止预览。相同规范化逻辑名称的远端夹在界面上放入同一逻辑工作夹分组，但每个物理分册仍单独显示真实标题、分册号、成员数、绑定状态和 `folderId`，用户可逐册取消选择；确认后逐个按精确 ID 删除，不能按名称合并、自动绑定或扩大删除范围。没有可靠远端 ID 的本地规则仍只能本地删除。

**删除、恢复与回收的最终规则。** 视频、收藏库工作夹、本地收藏夹规则和 B 站 bilimi 工作夹是四种不同删除范围。仅从收藏库删除视频只移除本地视频行，不改变备册绑定、工作夹、档案、转写或 B 站来源。选择“仅从收藏库删除 bilimi 工作夹（保留右侧规则和 B 站收藏夹）”时，只移除左侧真实逻辑工作夹及其本地分类/归属投影；必须保留该规则的正式`physicalShards`、对应物理成员和精确 B 站`folder ID`，使右侧规则继续显示`已备册`。此路径不读、不创建、不改名、不移动、不删除 B 站收藏夹或其成员，也不触发重新绑定；被保留的远端镜像只在本地标记为待下次显式备册/恢复流程重新展示，不能自行回到左侧。右侧删除本地收藏夹规则后，左侧保留原工作夹的恢复窗口并显示`收藏夹已删除`，不显示`未备册`或`未绑定`，也不参与批阅、分类、备册和同步。左侧`恢复当前收藏夹`只恢复删除前保存的右侧规则快照，不创建/绑定 B 站收藏夹、不备册、不同步视频；恢复成功后才显示`备册当前收藏夹`。用户明确选择“同时从 B 站删除整个 bilimi 工作夹”时，只有远端真实删除成功，或权威目录确认一个历史精确 ID已不存在且用户正在完成本次明确删除时，才能清除该精确 ID对应的旧绑定并让右侧规则显示`未备册`；删除预览必须同时列出该规则已有正式绑定的真实 ID、正式分册缺失但仍可在目录按精确 ID核验的历史分册，以及目录中同一规范化逻辑名称、但不属于上述 ID的 bilimi 远端 ID。后两者都是未正式绑定候选：历史分册按精确 ID核验，名称候选按名称识别；两类都只有用户完成“我已确认”及未绑定知情确认后才可删除。成功后必须将精确 ID保留为删除证据并跳过不存在的正式绑定清理，不能误报失败。自建未正式绑定规则不提供该 B 站删除路径。失败或结果未知保留真实绑定与待对账状态。右侧同名新建/备册始终是独立新规则；下一次整理收藏的最新权威快照或右侧备册成功快照才对仍未恢复的旧工作夹执行回收，回收只清理失去全部来源的旧投影，不误删新同名规则、档案、转写或札记。

**删除结果回执与本地收尾。** 删除请求的 HTTP/页面响应、远端目录对账和本地绑定/规则持久化是三个独立阶段。响应不可解析、超时、页面导航、账号 Cookie 变化或请求中断时，只能记录为“结果待核对”，不得直接显示“删除未成功”；应按本次锁定的精确 `folderId` 做一次无副作用目录核对：精确 ID 已不存在才确认远端删除成功，仍存在则保留未完成，目录无法读取则继续保留待核对。远端确认成功后，系统必须自动执行一次有界、幂等的本地收尾：按已确认的精确 ID清理绑定、将仍保留的默认规则收敛为`未备册`、持久化并重新读取同一账号权威快照，然后关闭删除确认并同时刷新掌库、收藏库和当前整理草稿。只有该自动收尾及一次权威重读仍无法完成时，才显示“B 站已删除，本地状态待保存”并保留可恢复检查点；不能把已删除绑定或“已删除”临时状态继续留在成功视图，也不能回退成笼统失败或清除未确认的其它 ID。批量删除逐项记录成功、失败、未知和本地收尾结果，不能以总状态吞掉已成功子项，也不能对未知目标盲目重发删除。删除完成后的掌库、收藏库和整理草稿刷新只重投影最新本地权威快照，不触发整轮重分类、DeepSeek、备册、视频同步或来源关系改写；删除、对账、持久化和大列表刷新必须复用有界异步队列，立即归还 Electron 事件循环，保证勾选、滚动、窗口缩放、最小化、关闭和取消入口持续响应。

**删除收尾的异常隔离与安装版验收。** 远端删除结果、本地逐项收尾、账号权威重读和界面投影是相互独立的阶段；远端精确 ID 已确认删除后，任何单个本地删除、绑定释放、偏好保存或 `workspace.refresh()` 回调失败，都不得阻断其它已确认目标从本地投影移除，也不得把已删除的远端事实误报为笼统失败。系统应先依据已确认 ID完成幂等本地收敛，再以同一账号的最新权威快照重投影；仅当本地收尾和权威重读均无法完成时，才保留“B 站已删除，本地状态待保存”检查点。该路径不重发 B 站删除、不触发整轮重分类或其它远端写入，并继续让出 Electron 主事件循环。安装版验收必须确认其构建提交包含本条修复；旧安装包不能作为修复后的行为证据。

**绑定与同步必须分开。** 用户只能从现有`备册收藏夹`、`备册当前收藏夹`或规则详情中的`备册`进入创建/绑定；`确认绑定`只存在于本次发现实际候选的确认页，不是规则卡片上的常驻动作。右侧全量入口在点击瞬间锁定已勾选的本地规则并读取 B 站清单：普通直接备册沿用名称优先的兼容路径，正常已绑定目标由保存操作完成一次新鲜目录读取并在操作后执行一次最终权威投影，不默认重复执行独立远端预检；该首次读取发现陌生 bilimi 收藏夹时，必须在任何创建、绑定、本地保存或最终投影前停在现有单窗口确认，确认后的原目标续跑不再重复弹出同一观察。未绑定候选、创建竞态、改名候选和失败/未知结果仍回到既有确认与精确 ID 登记链路。整理`确认并同步到 B 站`或显式要求预检时，继续使用统一预检和单窗口确认。其余规则不变：本地规则没有规范化同名候选时，只有用户明确备册才创建新的 B 站收藏夹；存在一个或多个同名候选时，按名称确认并将用户选中的全部候选登记为同一逻辑规则的物理分册，用户可调整分册顺序。B 站存在而本地没有同名规则时，只作为只读发现提示，不能创建本地草稿或进入普通规则流程。远端 `folder ID` 仅作为每个已确认分册的 API 操作句柄，删除仍须逐个使用精确 ID；它不参与名称匹配，也不因旧 ID 自动恢复本地规则。直接创建前必须再次读取清单，竞态出现同名候选时停止创建并回到确认页；创建后若暂时无法观察新夹，保留`已创建 · 待正式确认`。备册和绑定成功后才允许`同步到 B 站`，同步不能隐式绑定、创建或改名。

**物理分册身份与绑定顺序。** 一个逻辑工作夹可以对应 0、1 或多个物理分册。是否属于同一规则先由规范化基础名称判断；同名远端夹以及 bilimi 生成的带圆圈数字后缀夹都归入同一规则，再以各自真实 `folder ID` 作为已经确认分册的 API 操作句柄。普通备册、刷新、删除恢复和后台重试不得按数量或列表顺序猜测名称归属；名称不唯一时必须由用户在确认页选择。绑定确认窗口显示实际标题、数量、分册顺序和会发生的远端副作用，用户确认后的分册顺序才写入 `shardNumber`。

**明确确认后的改名。** 改名只存在于两种明确确认的流程：其一是已正式绑定分册的“确认修改 B 站收藏夹名称”；其二是“确认绑定 bilimi 收藏夹”中用户本次勾选的精确候选。前者既覆盖本地规则已改名，也覆盖用户直接在 B 站把该**同一已正式绑定 ID**改为不同名称：任一现有`备册`入口在无副作用预检中发现此标题漂移时，必须先弹出统一的“确认修改 B 站收藏夹名称”窗口，列出分册、当前 B 站名称和本地规则目标名称。用户一次点击`确认改名并继续备册`即只按该原正式绑定的精确 `folder ID`改名，并在同一次动作中继续既有备册收束；不得要求再次点击备册、重新勾选候选或再次确认绑定。取消不写 B 站、不解绑；改名失败或同 ID确认失败时保留正式绑定，不创建、不重绑、不写视频，也不继续本次备册。后者只可改本次弹窗勾选并再次从当前目录读到的精确 `folder ID`。两者都必须将新名称写入 B 站后，按**同一 ID**无缓存回读目录确认名称，再提交/更新本地正式绑定、失效状态缓存并刷新 B 站个人空间、掌库和收藏库快照。不得因为改名前名称的基础名不同而拒绝已确认候选，也不得因名称不同改用另一个同名、相似名或跨规则 ID；取消、未勾选、目录中不存在、已经绑定给其它规则、B 站拒绝或无法按同一 ID确认的结果，都不得提交绑定、创建新夹、写入视频或伪称成功。目录短暂滞后时只在同一精确 ID上有界重读；仍未确认则保留原绑定/未绑定事实和可读重试原因。

**单个备册的范围与确认。** 收藏库左侧`备册当前收藏夹`在点击瞬间锁定当前逻辑工作夹的真实 ID，只向主进程提交这一项；当前分册下拉菜单只改变查看范围，不把备册扩大到其他逻辑工作夹，也不把逻辑工作夹备册缩小成某一物理分册。主进程预检必须先读取该逻辑工作夹的权威快照和当前 B 站清单，再决定是否需要绑定；在预检完成前不得创建、绑定、改名或写入任何 B 站收藏夹。

当目标没有正式物理分册/绑定、仍有用户解除标记、或只剩旧 remote ID 但仓库没有对应正式分册时，单个入口必须打开`确认绑定 bilimi 收藏夹`确认页：按真实远端 folder ID 列出候选、标题、数量、账号、分册顺序和会发生的 B 站副作用；没有可复用候选时也必须先显示“确认创建并绑定当前收藏夹”的确认页，不能静默创建后直接显示成功。用户取消、关闭或未选候选时不写本地绑定、不创建/改名 B 站夹，结果不显示备册成功。用户确认后只为当前逻辑工作夹写入所选绑定/创建结果并刷新共同快照；其它规则、远端夹、视频成员、同步计划和草稿不改变。只有预检确认目标已有真实正式绑定时，才允许跳过绑定确认并复用既有远端 ID。

单个入口的结果摘要只统计当前逻辑工作夹（成功 1/失败 0 或对应失败原因）；右侧助手的全局`一键备册`仍按其原有的全量选择与确认流程执行，不能被单个入口复用或反向影响。任何页面看到的`已备册`都必须由同一权威状态投影，不能因为旧缓存、规则中的历史 remote ID、名称相同或某次状态核验看到了远端夹而替代正式绑定。

**账号打开时的绑定状态投影。** 账号打开返回的首个收藏夹快照必须优先来自本地仓库最新 `physicalShards`：仅具有真实 `remoteFolderId` 且 `bindingState=bound` 的分册才能投影为`已备册`，并一次性合并同一逻辑规则的全部分册。该本地投影不得等待远端网络或其它可选诊断步骤，也不得被旧 `config.json` 中的历史 ID覆盖；投影完成后立即失效账号状态缓存并广播一次权威快照。远端待绑定检查作为独立的异步后续步骤运行，成功或失败都只能补充不同 ID 的候选并再次广播，不能把已有正式绑定降级为`未备册`/`未绑定`。备册/绑定完成也必须沿用同一顺序：先写入仓库正式分册，再从仓库重投影账号规则，确认最新状态后才允许进入同步进度。

**删除预检的当前分册口径。** 删除预检必须同时读取本地正式 `physicalShards` 与当前账号的 B 站目录，并按精确 `remoteFolderId` 对账。界面显示的“`N 个分册`”只统计当前目录中实际存在且属于本次逻辑工作夹候选的远端夹；本地仍保留、但当前目录已确认不存在的历史 ID必须单独标为“历史分册 / 远端已不存在”，不得计入当前分册数量，也不得被当成可再次删除的实际远端夹。历史缺失 ID仍作为本次明确删除流程的本地收敛证据保留：确认删除时跳过远端删除请求，成功收敛后清理对应旧绑定；目录中仍存在的精确历史 ID和同名未绑定候选继续逐项显示并按既有知情同意与精确 ID删除。分组标题、B 站删除数量和候选列表必须使用同一“当前实际存在”口径；不得通过同名、分册后缀、数量或历史登记条数推断分册数。该口径修复不得改变本地规则删除、未绑定候选确认、备册、绑定、整理收藏、归档预览、同步和鼠标响应行为。

**改名确认简化（2026-09-07，R012 后续替代）。** 对已正式绑定分册的改名，弹窗保存该精确远端 ID 的改名前名称和目标名称。用户确认后只向同一 ID发送一次改名请求，并将请求返回的改名结果与弹窗目标名称比较：一致则更新该绑定并继续本次备册，不一致或请求失败则保留原绑定并结束本次动作。删除旧条款中改名后的重复详情读取、页面导航等待、重试循环、权威快照补读和旁路确认；这些步骤被 R012 明确替代。不得按名称寻找其它收藏夹，不得创建、重绑、写视频或要求第二次点击。普通备册、同名候选、分册编号、删除和精确远端 ID 保护不变。

**创建后绑定不得被恢复降级。** 无候选路径返回的精确新 `folderId` 一旦经主进程目录核验写入对应逻辑册和分册的 `physicalShards.bindingState=bound`，它就是该分册的唯一正式绑定事实。账户打开、快照刷新或旧受管收藏夹恢复投影只能补充不同远端 ID 的待确认候选，且必须以最新仓库快照重新编号为另一物理分册；不得以旧快照把同一逻辑册/分册写回 `pending-reconcile`、清空新 ID或在同步前确认窗口把新建夹再次列为“未绑定”。恢复与投影本身只更新本地仓库，不创建、绑定、删除、改名或写入 B 站；旧的不同 ID 同名候选仍必须保留精确 ID和人工确认。

**远端删除回执优先。** 对精确 `folderId` 收到 B 站成功回执后，主进程已经持久化的删除收尾是权威结果；渲染器不得再用一轮重复的全量规则保存去覆盖或否定该结果。页面应立即按已确认回执关闭删除弹窗，并把保留的默认规则投影为`未备册`，随后只发起一次非阻塞的权威快照刷新。只有本地删除收尾和权威重读都失败，才显示`本地状态待保存`并保留可重试现场。`managedFolderDeletedByUser`等删除证据只能在正式新远端 ID完成绑定登记后清除，普通账号打开、状态刷新和仓库投影不得无条件移除。

**删除后的单一权威投影（2026-09-01 回归修复）。** 删除流程无论命中已备册物理分册、未绑定历史候选，还是新鲜目录确认“无精确 ID、无同名候选”的本地规则，都必须由主进程产生同一账号级状态快照；渲染器收尾只能消费该快照，不能用删除前的 `unbound` 草稿再次覆盖。默认规则保留时，远端已确认缺失且无正式 `physicalShards` 的结果统一显示`未备册`，卡片、详情和底部提示在当前页面立即同步；只有本地收尾或权威重读失败才显示`本地状态待保存`。该投影不创建、绑定、删除、移动或同步 B 站，也不改变未绑定候选的知情确认语义。

**无精确 ID 的未绑定删除收束。** 默认规则已因远端清空投影为`未绑定`、且本次删除预检没有可删除的精确 `folderId`时，主进程仍必须以本次新鲜目录决定收尾：存在同名未绑定候选则保留原有候选、知情确认和`未绑定`状态；目录确认既无精确历史 ID、也无同名候选时，视为“远端已确认缺失”，将该规则持久化收束为`未备册`并广播一次同一账号权威快照。这个分支不请求 B 站删除，也不得由渲染器通过普通规则保存与主进程删除收尾竞争；卡片、详情与底部`部分 Bilimi 收藏夹尚未备册。`提示必须在弹窗关闭时同步更新。正常已备册删除、未绑定候选知情同意、历史精确 ID和多分册逐 ID 范围均保持原语义。

| 收藏夹身份状态 | 可见动作 | 状态转换 | 明确禁止 |

**物理分片与容量：** 一个逻辑工作夹可能对应多个受容量限制的 bilimi 物理工作夹。列表显示逻辑工作夹身份和汇总数，详情在需要时展示各物理分片、远端 ID、容量、成员数和绑定状态；创建额外分片必须是明确的计划步骤，不能因本地分配数增加而悄悄创建 B 站收藏夹。

**同步前同窗备册的跨目标闭环：** 当同一个`同步前备册确认`窗口同时列出逻辑册首册缺口、精确未绑定候选和容量分册时，一次确认必须在同一确认范围内完成全部已选目标：首册创建或明确绑定与每个容量分册创建/登记都分别以返回的真实`folderId`写入对应逻辑规则的正式`physicalShards`。不得因某一首册成功就跳过其它已确认分册，也不得让一个逻辑册的绑定替代另一个逻辑册的分册。确认完成后，在进入冻结/视频同步前，主进程必须从仓库的最新`physicalShards`重建本次所有逻辑规则的正式绑定投影并广播同一新快照；上方收藏夹状态和“B站绑定：N 个收藏夹”均只能以该投影显示。只有所有已确认目标都已正式登记为`bound`，且复核不再有同批缺口时才可开始同步；部分失败、结果未知或回读不一致时保留精确失败目标，不得把整批显示为“已备册”或开始视频同步。

**同步状态只显示两值。** 列表、详情状态标签、归属区域、筛选参数和 IPC 公开枚举只允许`已同步`、`未同步`。本轮同步命令成功，或当前可识别的 B 站实际归属与收藏库目标一致时显示`已同步`；从未成功同步、同步失败、当前实际归属不一致或历史资料无法识别时显示`未同步`。写入回执、扫描回读、结果未知和失败原因可作为内部审计事实及重试/对账依据，但不得形成第三种用户状态、黄色提示或额外归属说明。刷新详情只读取和重投影权威状态，不追加 B 站成员、不取消 B 站收藏，也不覆盖用户之后的手动变更。

**备册入口范围。** 右侧助手保留原有`一键备册`，其完成后才按本节发现规则发布只读发现提示；发现结果不改变本次备册目标或确认链。范围数量和候选/创建/跳过结果在确认或完成摘要中显示，不用“已勾选数量”替换主入口。收藏库左侧`备册当前收藏夹`只处理当前选中的**真实**逻辑工作夹，绝不调用全量备册；左侧`备册工作夹`也只列当前仓库真实存在的`bilimi-logical:*`工作夹，并保留其原有顺序。`local:inbox`是扫描/整理的本地未分类安全暂存，绝不伪装为`bilimi-logical:inbox`、左侧工作夹、备册候选、删除候选或远端实体；它只提供后台本地成员，不提供显示名、远端 folder ID或绑定事实。默认`inbox`规则仍是稳定逻辑规则，尚未物化工作夹时可从右侧既有`一键备册`按规则 ID走创建前二次检查和同名候选确认；该操作只创建或绑定其首册，不上传本地暂存成员。空收藏库也可以由右侧已保存规则的一键备册创建数量为 0 的本地逻辑工作夹；左侧没有当前工作夹时不允许按钮伪造目标或隐式创建规则。任何备册只建立/更新规则与物理分册绑定，不自动同步视频。

**收藏库保护边界。** 系统保持已存在的收藏库、同步、整理和礼记能力，优先使用此前验证过的状态机和数据投影，不另造平行页面或大范围重构。收藏库正式形态是主窗口底部抽屉；工作夹备册只绑定当前逻辑工作夹，原有逻辑成员、位置意图与物理分册成员必须保持可追溯的一致投影，绝不能因绑定把当前或其他工作夹清空。绑定确认中的当前账号只显示昵称，昵称不可得时使用非 UID 的中性文案。DeepSeek 明确“改归”与用户的`移动至`都以目标 bilimi 归属替换旧归属，不自动写 B站；复制仍保留原归属。所有改变收藏库事实的动作完成后都从主进程权威快照刷新导航、列表、选择、详情和状态。

### 4.5 跨页面、账号与恢复边界

- 批阅、整理收藏、掌库和收藏库共用同一账号级收藏仓库和真实规则 ID；B 站远端收藏夹与 bilimi 本地工作区是不同实体类型，页面只能显示快照、提交命令并等待结果，不能分别缓存“已参与/已删除/已绑定”的真相。
- 扫描概览按第 5.2 节只显示`B站收藏夹`远端事实、来源选择与本轮统计；本地工作区规则、数量和关系详情在掌库与收藏库中查看。推荐、上方卡片、详情和收藏库导航必须与本节身份状态同步；当前整理草稿不能覆盖详情内真实的未备册、失败、待绑定或待对账状态。
- 账号切换时，规则、物理分片、绑定、收藏库、窗口偏好、扫描工作区和在途任务按 `accountMid` 隔离；不得引用、恢复或写入另一账号实体。
- 账号读取为空、读取失败或收到账号切换事件时，渲染层必须立即清空旧账号的 `accountMid`、收藏夹备册状态和相关缓存，并使旧账号在途读取结果失效；在新账号权威快照加载完成前，不得继续显示旧账号的`已备册`/`未备册`状态。账号变化本身不等同于备册失败，也不得主动执行退出、创建、绑定、删除或视频写入。
- 关闭掌库/收藏库窗口仅关闭视图，保留可恢复的当前账号选择、查询、编辑检查点和在途操作真实状态；恢复时以主进程快照对账，不能拿旧 React 内存覆盖持久化结果。
- 恢复决定指纹失配是“需要重新读取恢复摘要”的可恢复状态，不是草稿损坏、更不是整套整理功能的终态错误。主进程必须仍返回当前账号、当前工作区的恢复摘要；渲染层只能据此展示已有恢复选择，不能把英文内部错误替换为仅有“重试暂停”的死路。真正的工作镜像损坏、账号不匹配和结果未知仍按各自受保护路径处理。
- 本地数据清理、导入、迁移或账号恢复必须先显示影响范围。它们只能操作本地选择范围，不能自动删除 B 站收藏、远端工作夹、登录或其他账号数据。

## 5. 整理收藏：扫描、草稿、推荐、预览与执行

### 5.1 开始、关闭、重开与结束

| 按钮/场景 | 应有结果 | 不会影响 |
| --- | --- | --- |
| `整理收藏` / `整理旧藏`开始入口 | 主进程先读取账号级工作区标记。没有未结束的整理轮次时，恢复入口直接返回正常空值并进入“扫描概览：扫描中”；DeepSeek 恢复检查在没有工作区或检查点时同样返回正常空值。只要存在未结束轮次（扫描、标签补取、DeepSeek、预览、冻结计划、同步中、同步已暂停或结果待核对），在后台完成恢复安全检查，准备好后直接显示恢复弹窗。检查期间不显示居中的“正在暂停并保存进度…”过渡窗。 | 不能自动写 B 站、修改普通收藏夹或把旧页面本地状态当作权威工作区；没有未结束轮次不得弹出空的恢复选择窗、内部错误或“重试暂停”。 |
| 已有未结束轮次后打开 | 后台安全检查完成后统一显示三个用户操作：`恢复草稿`、`重新扫描`、`放弃本轮整理`。`恢复草稿`按当前权威状态恢复：扫描/预览回到对应草稿；冻结、同步中或同步已暂停回到确认执行进度页，保留已完成同步数，继续时只处理剩余项目；结果待核对回到确认执行页并要求先对账。在用户点击其中一个动作前，检查本身绝不启动扫描、标签补取、DeepSeek 或 B 站同步。 | 不让用户在“按原草稿继续”和“合并最新变化”之间二选一；不重新扫描 B 站、不执行远端同步、不丢掉手动分类；不能把“关闭后重开草稿”变成自动合并新分支。 |
| `放弃本轮整理` | 只对未结束且已安全暂停的工作区可用；点击后等待主进程终结当前草稿、恢复标记和仅属于本轮的本地工作区，并以返回的权威快照刷新入口。 | 成功后关闭恢复弹窗；下一次点击`整理收藏`直接新建并开始一轮增量扫描，不再为该草稿显示恢复选择。真正仍在运行、尚未安全暂停的扫描或远端请求不得被静默丢弃，必须先完成安全边界。 | 不写 B 站、不取消或重复同步已经完成的 B 站操作，不删除已完成收藏库、档案、同步记录或此前轮次成果。清理失败时保留恢复弹窗、草稿和准确错误，不能把空返回或旧 UI 快照伪装成放弃成功。 |
| 关闭整理 | 正常关闭时先在后台把扫描、标签补取、DeepSeek 和 B 站同步收束到各自安全边界并持久化检查点；只有成功后才隐藏界面并保留当前草稿。之后再次点整理直接读取已暂停草稿并显示恢复选择。暂停或持久化失败则继续显示原向导和明确错误，不能伪装为已经关闭。 | 不清空草稿、不把新增收藏纳入本轮、不执行 `merge-latest` 替代原草稿；不因重开草稿重复写入已暂停的检查点。 |
| 确认结束整理 | 提供保留草稿或删除草稿结束本轮的明确选择。 | 确认结束后再次开始才允许走受保护的增量扫描；不能影响已保存/已同步成果。 |
| 全部重新整理 | 用户明确选择时解除已有成功分类的增量保护，并启动全量扫描。 | 不能由普通重开、切换批次、DeepSeek 失败或恢复操作隐式触发。 |

**恢复安全屏障：** 正常关闭整理时先在后台完成并持久化该安全屏障；正常重开时只核验已暂停的持久化草稿，因而不得重复发送暂停或重写相同检查点。异常退出（崩溃、强制结束）没有机会执行正常暂停：重开入口仍在后台读取最后持久化检查点，必要时收束可安全判定的本地运行状态，再发布恢复摘要。两种情形下，恢复弹窗、恢复预览和恢复后的确认执行界面只能在主进程完成以下步骤后展示：停止扫描和标签补取领取，等待在途 B 站读取收束并保存扫描/标签检查点；停止 DeepSeek 领取新批次，等待当前请求收束并保存未完成批次检查点；暂停确认执行意图和正在进行的 B 站同步，等待当前远端请求完成并保存逐项同步检查点。DeepSeek 的该动作是“暂停并保留结果”，不是取消；B 站请求未收束、检查点未持久化或结果未知时不得伪装成已暂停。异常退出后最后一次 B 站写入结果未知时，必须保留“结果待核对”并禁止直接继续写入。检查全程不显示居中过渡窗；安全屏障失败时显示具体阻塞原因和可重试入口，不显示普通恢复按钮。

安全屏障只负责为用户打开恢复入口，不会自动恢复、自动扫描、自动调用 DeepSeek、自动保存收藏库或自动写入 B 站。用户选择`恢复草稿`后才恢复当前轮次；用户选择`重新扫描`或`放弃本轮整理`后才分别执行对应的二次确认和边界检查。冻结、同步中、同步已暂停和结果待核对均是**未结束轮次**，必须显示同一组三项按钮，不能借由直接跳至确认执行页隐藏恢复选择。结果待核对在恢复后必须先对账，不能继续写入；重新扫描或放弃均只结束本地本轮计划，**不自动回滚已发生的 B 站操作或已保存收藏库成果**。工作镜像损坏/无法校验仍走重建路径，不得伪装为可恢复草稿。

**工作镜像完整性与关系投影。** 来源关系、备册结果、绑定结果、分册关系和库存统计的刷新仅是元数据投影：它们可以追加来源/本地工作夹/统计信息，但必须原样保留当前工作区的活动分段 ID、扫描状态、分类、历史、标签、推荐和执行意图；元数据刷新不得以空字符串、占位值或旧快照覆盖这些字段。恢复界面只有在 manifest、journal、分段文件或其一致性确实无法校验，或无法从已校验的持久化记录确认活动分段时，才能显示`工作镜像损坏`和`重建工作镜像并重新扫描`。若完整 journal 与扫描分段仍有效，仅是既有元数据投影错误地留下空活动分段，则主进程必须从同一已校验 journal 中最后一个有效且属于该扫描的分段恢复该值，并修复本地 manifest / workspace marker；不得把这类可证明的一致性修复误投影为损坏、要求重扫或改写收藏库、规则、分类、B 站关系和视频。

**恢复决定过期：** 已持久化的恢复决定与当前事实指纹不一致时，打开整理收藏必须先退回同一未结束轮次的恢复摘要，仍显示`恢复草稿`、`重新扫描`、`放弃本轮整理`三项；不得因尚未完整装载草稿而丢失后两项。用户选`恢复草稿`后，主进程以当时权威事实刷新`merge-latest`恢复决定并重建可用工作区；若失配仅来自用户刚刚明确保存的本地规则配置，应已由第 4.3 节的配置基线前移消除。恢复成功的`previewing`草稿按其真实状态重新开放批次、来源、分类、收藏夹规则、预览和 DeepSeek；扫描中、冻结/执行中和结果待核对则分别保留原有暂停、继续、结束或对账限制。上述恢复处理不自动扫描、调用 DeepSeek、创建/绑定/删除远端收藏夹或写入视频。

### 5.2 扫描概览分区、来源选择与扫描生命周期

扫描概览是“本轮工作区目前知道什么”和“接下来能安全做什么”的事实面板，不是普通收藏夹列表的另一份缓存。它先完成视频收藏的基础扫描，再按第 5.3 节补取标签；标签补取一旦开始，基础扫描范围已经完整确定。基础分页只采纳视频身份、标题、UP、封面、收藏时间和失效状态等基础事实；即使响应偶然带有标签、`tname` 或`category`，也不把它们作为标签确认或 B 站分区分类依据。页面只展示当前批/本轮进度和来源选择，不展示 bilimi 本地工作区、本地数量、备册、绑定或关系详情。单批和多批的`本轮总览`保留原有 B 站收藏夹来源表格、顶部`全选（N）`、逐夹名称与选择、总数及可在`待整理`、`已保护`、`失效视频`间切换的最后一列；默认`待整理`标题下显示`（来源计数·重复计数）`。来源计数按已选收藏夹的来源关系相加，同一视频属于多个已选夹时会重复出现；重复计数是该合计相对顶部去重视频数多出的关系计数，悬浮说明必须逐一解释两个数字，并明确本轮实际只整理一次。单批不额外制造“当前批次 / 本轮总览”层级。只有多批的`当前批次`隐藏整个来源区域，不显示“已发现”、全选、逐夹复选框、来源表、总数或来源关系。隐藏只改变观察与可操作位置，不清空、禁用或按批拆分整轮来源选择；上方统计卡、扫描/标签进度和当前批工作内容保持原样。所有当前存在的远端收藏夹一视同仁纳入全选范围，不能以名称、`bilimi` 前缀、数量为 0、备册、绑定或远端 ID 是否暂缺来置灰、隐藏或改变来源资格；内部仍保存远端 folder ID 和来源选择集合供扫描、恢复及其他页面使用。

**扫描与标签进度行：** 扫描概览一旦实际存在标签补取 scope（`running`、`paused`、`accepted`或`complete`），无论工作区是单批、多批当前批次还是多批本轮总览，均在同一“扫描进度”区域显示两行横向进度：第一行为`扫描进度`、横条、扫描计数（仅扫描中或失败时显示）和基础扫描状态；第二行为`标签补取`、横条、范围计数和标签状态。单批不能因没有批次选择器而隐藏第二行；基础扫描尚未完成、标签补取尚未开始时才可以只显示第一行。基础扫描的`已完成`只表示所有本轮基础收藏分页已成功读取，并不表示标签补取、采用、分类、保存或同步已完成。完成引导`本轮扫描与标签补取已完成`只在基础扫描已完成，且标签补取不存在或待补取、读取失败均为 0 且状态为`complete`时显示；标签补取为`running`、`paused`、`accepted`或仍有待补取/失败时，引导必须如实说明“基础扫描已完成”及标签当前状态，不能把整轮提示为结束。当前批与单批第二行必须使用当前批 scope，显示`当前批 已处理 / 总数 条`；本轮总览第二行必须使用整轮 scope，显示`本轮 已处理 / 总数 条`，不得把当前批数字带入总览。本轮总览顶部既有的`标签补取中 N 条 · 已补取 N 条 · 待补取 N 条`文字汇总继续保留，作为整轮明细摘要。来源收藏夹成员数之和与去重后 AID 数是不同口径：两者的差额只能作为来源重叠关系在来源表的`（来源计数·重复计数）`中解释，绝不显示为`尚未扫描 N 条`或其他漏扫暗示。每行优先保持“标签 + 横条 + 数量 + 状态”同一行；侧栏变窄时只收缩横条，数量和状态不得截断，只有剩余空间仍不足时才受控换行。进度条只是快照投影，不附带操作控件，也不改变扫描、补取、采用、保存或同步状态。

### 5.3 标签补取与“采用当前标签”的可逆循环

标签区必须同时显示当前批次和本轮的进度、历史已知标签、本轮获取标签、已确认无标签和读取失败数。标签补取只能在基础扫描完整结束后开始，故本轮完整视频范围在此阶段已经确定。基础分页没有可靠标签能力，独立标签接口是唯一能够把视频标为`标签已确认`（包括确认后为空）的渠道；不得因基础分页的空值、偶发标签字段或 B 站分区字段跳过补取。未补取标签只限制依赖它们的系统判断，不能把视频伪装为“确认无标签”；用户采用当前标签后，系统以当时已取得的标签作为可审计的标签截止版本，在完整本轮范围内重算分类，无法匹配的项进入可见未匹配/暂存路径。

**收藏库整理的历史标签：** 从收藏库选中视频新建整理工作区时，视频记录中的非空历史标签直接作为该视频当前整理周期的已知且已确认标签；已有明确 `tagEvidence=confirmed` 的空标签也作为已确认结果。系统仍可显示这些标签的来源为“沿用历史标签”，但不得再次要求用户采用，也不得显示“新增或变化标签，待采用”。旧的 `scope=selection` 整理草稿恢复时，按同一规则补齐完整历史标签批次的本地采用截止状态（包括 `acceptedSegmentIds` 和对应版本），只修正本地标签状态，不改收藏库视频内容、人工分类、推荐选择、B 站关系或远端数据；缺少标签证据的视频仍按普通补取与采用规则处理。

**批次结果的即时投影：** 任一批的标签补取由“补取中”变为已有最新结果时，系统必须立即以该批和当前已就绪批的真实标签重建推荐、刷新归档预览及相应系统分类；用户不需要点击`采用当前标签`才看见推荐。这个即时刷新只更新可继续修改的草稿投影，不创建标签截止版本、不自动勾选推荐、不写收藏库或 B 站。若此前存在采用版本，用户明确继续补取时必须使该次**整轮采用截止**同时失效：内存中的已采用分段标记、每个属于该截止的分段采用版本和持久化 journal 重放后的同一字段必须一起清除；不得仅清一个标记而遗留旧版本。之后若用户让补取自然完成且全轮待补取、失败均为 0，没有任何有效采用截止时，直接作为自然完成，不凭空制造新的采用动作或“待采用”提示。旧草稿重放时，若状态已经是`complete`且待补取、读取失败均为 0，则孤立、过期或不构成完整本轮截止的历史采用版本不得阻塞这一自然完成投影；只有仍在等待采用且存在有效完整截止版本时，才保留采用语义。若用户在新一轮补取尚未结束时再次采用，则以当时结果建立新的部分截止，并保持“继续补取 → 新结果 → 再采用”的可逆循环。快照中的“当前批有未采用变化”必须与完整本轮截止判定一致：自然完成、没有任何有效已采用版本时为否，不显示“发现新增或变化标签，待采用”，`采用当前标签`保留且置灰；只有当前存在有效采用截止且该批标签版本晚于其采用版本时才为是并恢复采用入口。

**采用成功后的完整结果与执行资格：** `采用当前标签`不是只改变一个标签状态。系统必须先在主进程持久化“停止领取新标签”的安全暂停候选；已经领取且数量有限的读取只允许收束为成功标签或失败记录，收束完成前不得发布标签截止版本、推荐、分类或执行资格。待在途读取归零后，系统在同一主进程权威队列中构造该次标签截止版本，并以这一份快照对**完整本轮范围**完成系统分类重算和推荐重建；成功后一次发布截止版本、推荐、分类和准备度。发布后的已采用截止版本不得被迟到结果静默改写；只有用户明确点击`继续补取标签`，才可解除该截止版本、重新领取待办并使新的标签结果进入下一次采用循环。只有完整结果发布后，当前批和本轮总览才同时展示/刷新推荐收藏夹与归档预览，未匹配项仍须可见。自然完成且没有待补取/失败项或标签增量时，当前结果直接作为权威草稿，不要求点击置灰的采用按钮；标签补取实际运行、仍有待补取/失败项、完整范围重算或 DeepSeek 运行时，`保存本轮到收藏库`和`确认并同步到 B 站`才禁用。任何持久化、收束、重算、推荐或快照投影尚未完成的中间状态，均不得先显示旧推荐/旧预览并放开写入按钮；失败时不得更新采用版本或执行资格，应保留可恢复的旧事实和具体错误。采用、推荐、预览和资格更新仅改变本地工作区，保留人工分类与已勾选推荐，且在用户点击保存或同步前绝不写收藏库或 B 站。

**重启后的多批采用与失败快照：** 完整本轮范围必须以持久化的分段描述符为准。进程重启后，内存中只装载当前批的详细项目是正常的；`采用当前标签`重算时必须按完整描述符顺序逐批读取各自持久化分段，不能以当前内存批是否含有该分段来缩小范围或误报分段不存在。真正无法读取或校验的分段才进入可恢复失败状态，不能把正常草稿要求为重新整理、重新扫描或清空。采用命令一旦已持久化`recomputing`或`failed`终态，主进程 IPC 必须返回该账户的最新权威快照；该返回资格必须由协调器明确标记为“本次调用已持久化失败”，不得仅凭读取到旧的`failed`状态吞掉新的存储、恢复或工作区异常。渲染器以返回快照替换点击前旧快照，按`采用当前标签未完成：本轮分类重算失败，请在当前草稿重试采用。`显示阻塞，不能把失败错投影为“仍有 0 条待补取或读取失败”。内部失败详情可持久化用于诊断，但不得直接作为用户文案。此类失败保留草稿、标签、推荐、人工分类和已有系统分类，不写收藏库或 B 站。

### 5.5 推荐收藏夹、上下联动与归档预览

推荐收藏夹是当前扫描数据的下方投影，不依赖上方收藏夹、账号规则、B 站远端目录或删除记录。推荐只保留两类：`专属 UP 追更`和`高频标签`；其他自动生成收藏夹不显示、不新建。推荐候选的出现、数量和内容只由当前扫描事实决定。

系统在扫描、分页、标签、规则保存、规则编辑、取消勾选、删除、恢复或批次变化后提前重算候选与普通规则的匹配。名称、规则类型和规范化关键词集合完全一致且只有一条匹配时建立联动；名称比较必须保留用户可见标题中的前导、尾随和中间符号，不能因切分符号、空结果回退或历史规范化把`-恒某人-`变成`恒某人-`等不同名称。名称或规则任一改变立即断链，恢复一致后在新的计算结果中重新联动。点击推荐只读取已准备好的匹配，不扫描视频、不遍历全规则、不访问远端目录。

采用推荐只有三种结果：

1. 有唯一匹配：复用该普通规则并勾选；
2. 无匹配：按普通新建收藏夹的方式生成名称、类型和关键词，保存本地规则并勾选；
3. 有多个匹配：关闭本次采用并提示“存在重复收藏夹，请先处理重复项。”，不任意选择、不创建第三条。

采用成功后上方规则和下方候选同时显示本轮已勾选；失败两边回到上一个权威快照。下方取消只取消本轮参与，不删除普通规则；再次点击按最新预计算结果复用或新建。上方改名、改类型或改关键词后下方立即取消联动，点击下方推荐会按新建普通规则处理。删除上方普通规则后下方候选取消勾选；只要扫描事实仍满足条件，下一次扫描仍会出现未勾选候选。推荐不拥有墓碑、黑名单、远端绑定、认领、恢复或独立删除生命周期。

带有旧推荐来源标记的已保存记录按普通规则展示，保留真实本地成员和远端绑定，不因来源标记自动生成推荐或与异名候选联动。历史 `梅林FIT` 规则即使绑定远端 `4065678011`、标题为`bilimi小咪的收藏夹`，也只按其实际名称和规则语义处理，不与名称不同的候选联动，不生成“小咪”推荐。

**改动记录的当前分支显示。** `改动记录`不是跨分支审计日志，只显示当前可恢复分支中位于`historyBaselineCursor`之后的最终一致分类条目：扫描期初始自动分类、零移动规则状态和用户在撤销后以新操作替换掉的旧 redo 分支均不显示。基线之后每一条仍可恢复的分类动作都必须作为独立中文记录呈现，包含当前游标所在条目；当前条目必须以与其他记录相同的列表行显示，并标明`当前`，不能仅作为一段看似没有历史的辅助文字。弹层应明确显示本轮可恢复记录数量；当前条目不可重复选择，其他条目仍可点击恢复，`恢复初始改动`保持独立。记录投影只处理主进程已发布的简短 history 摘要，不能在点击或渲染时扫描视频、重算分类或改变规则、勾选、归档预览、同步预检或任何 B 站状态。

### 5.8 确认执行、保存与 B 站同步

确认执行以当前权威工作区中已经完成的基础扫描、标签结果和完整本轮分类为准。标签补取实际为`running`、仍有待补取/失败项、完整范围重算中或 DeepSeek 整理处于权威活动`running`/`waiting`时，写入按钮必须禁用并说明真实阻塞原因；`completed`、`failed`、`canceled`和恢复`paused`不许被错误文案投影为“整理中”。DeepSeek 失败或用户取消时，未收束视频已保留当前有效分类，故它们不是保存/同步的额外门槛；归档预览保留可选的精确重试入口，确认执行不得要求或显示“沿用原自动分类”确认。暂停只保留恢复语义，不遗留取消按钮或活动轮询。自然完成且待补取/失败均为 0 时不要求额外点击`采用当前标签`，两个标签按钮置灰但保存/同步可按当前结果开放。确认执行在主进程将意图从`waiting`切换为`running`之前，必须在同一权威队列再次校验完整本轮标签截止版本；截止已失效时不得写入`running`、不得保存收藏库、不得冻结或生成 B 站同步计划，而应持久化`blocked/tag-cutoff-changed`并显示“自动执行已停止：标签结果已有新变化，请重新采用当前标签后再保存或同步。”。写入`running`后，`继续补取标签`和失败标签重试必须被主进程拒绝，直到执行结束或取消该执行意图；不能在预检通过后让标签命令推翻截止版本。该原因不得错误投影为目标收藏夹、备册、绑定或 B 站计划故障。用户点击继续补取后，直到任务收束且必要的分类重算完成，写入资格再次按当前工作区状态判断，不因待办自然归零伪造采用动作。

**确认后的响应性边界。** 点击`确认并同步到 B 站`后，主进程必须先持久化可恢复的执行意图和真实准备阶段，再把控制权交还给 Electron 事件循环；本地完整结果提交、分段读取、目标分册容量预检、冻结计划编译、远端草稿/绑定预检、进度快照和 IPC 回传都必须按有界批次或阶段分段执行。一次点击不得重复读取、重复提交同一份完整本地结果，也不得在一个长同步任务中把全部分类、历史、分段成员和执行记录重新复制后才返回。准备阶段和逐项同步阶段都要发布真实状态、失败原因和可恢复检查点；准备尚未完成时不得伪造`同步中`或完成，准备完成后才进入真实逐项 B 站写入。任何阶段必须显式让出 Electron 主事件循环，不能因等待 IPC、磁盘序列化、页面脚本或大快照重算而阻塞鼠标移动、点击、滚动、窗口缩放、最小化、恢复、关闭和取消入口。渲染器只能增量接收权威进度或受控摘要，不得因一次执行状态刷新而整页重渲染全部视频明细；已有确认、幂等、暂停、结束、对账和结果未知语义保持不变。

**同步 marker 的轻量引用。** 已经通过当前进程恢复并持续管理的工作区，在冻结、认领、暂停、对账等状态切换时，marker 只需读取并校验紧凑 manifest 引用（账号、工作区 ID、基线版本、活动分段、overlay revision、journal cursor、checksum）；不得为了重写同一 marker 而重新读取、反序列化和重放整份 journal。完整 journal 校验与重放仍是首次打开、进程重启后的恢复、明确完整性检查或检测到 manifest 引用不一致时的安全屏障，不能被轻量引用替代。每一次日志追加成功后可在同一进程缓存其已校验 cursor/checksum；缓存不得跨进程或跨 manifest 版本信任。这样既不降低真实损坏的重建门槛，也不让 20 MB 级 journal 的恢复落在一次`确认并同步到 B 站`点击、进度刷新或关系投影的关键路径上。

**关系投影与 marker 一致性。** 任何仅刷新远端—本地关系、来源选择、工作夹列表或库存统计的 overlay 写入都必须保留该工作区当前活动 `currentSegmentId`；关系刷新不是切换批次，绝不能把多批工作区写成空批次。内存缓存的 marker 只有在账号、工作区 ID、状态、基线版本、活动分段、overlay revision、journal cursor 和 checksum 全部与当前 manifest 一致时才可复用；任一字段失配均必须放弃缓存并走既有安全恢复/重建路径。冻结前的 marker 持久化失败必须停在真实错误，不得开始视频同步或把旧 marker 伪装为当前计划。

`采用当前标签`是完整本轮写入资格的显式收束命令：先持久化停止领取，等待已认领标签结果收束，再以同一权威快照重建推荐与完整本轮分类，最后一次性持久化完整截止版本并返回该终态快照。命令返回前，不能只留下“已暂停”或仅更新推荐；当标签待补取/失败均为 0 而采用尚未完成时，确认区必须显示“采用当前标签未完成”及真实的重算失败原因，不能错误提示“仍有 0 条待补取或读取失败”。重算失败时保留当前草稿、标签、推荐、人工分类和已有分类结果，写入保持禁用并提供原地重试采用；不得要求重新扫描、重新整理、清空草稿或触发 B 站写入。采用成功后同一快照必须同时满足完整标签截止版本、当前推荐/分类投影和保存/同步资格；已经存在的完整分类不得因为采用流程再次失败而被丢弃或要求用户重做。

**预检投影版本。** 同步前备册预检必须携带其生成时的账号、工作区、规则配置版本和`excludedLedgerIds`版本。规则目录重分类、本轮勾选、推荐采纳、人工转移、标签收束、关系/绑定投影刷新或工作区切换后，渲染器中已打开的预检即刻失效；它可关闭或提示重新读取，但绝不能以旧缺口、旧目标或旧容量继续确认。确认备册、确认同步和冻结计划前，主进程均要重新读取同一最新目标投影并校验上述版本；不一致则回到预检，不创建/绑定/冻结/写入 B 站。此规则只保证本地快照和无副作用预检一致，不改变既有备册候选确认、删除确认或视频同步执行语义。

**确认同步前的统一备册预检。** `确认并同步到 B 站`在冻结计划前必须从当前权威分类与工作区持久化的“本轮排除规则 ID”集合生成两份关联投影：`备册目标`包括本轮仍勾选的全部已保存逻辑收藏夹，**即使归档预览实际归属为 0 条也必须列入**；`B 站视频写入目标`默认与其相同，但`bilimi·暂存`只有在用户于确认窗口明确勾选“同步 bilimi·暂存”后才进入。已勾选的`bilimi·暂存`即使默认不写入视频，未备册/未绑定也必须保留在`备册目标`并列入同一个确认窗口；该首册备册不推导新增容量分册，也不写入暂存视频。除这项暂存例外，本地保存、预检、冻结和最终 B 站写入必须共享同一投影，不能由渲染器或全局`enabled`偏好另行猜测。已保存、已启用但本轮目标数为 0 的规则仍显示并参与备册预检；只有本轮取消勾选的规则才从备册与视频写入目标共同移除，且取消本轮目标不改变其本地规则或启用状态。远端草稿永远不进入任一投影。预检对每个备册目标检查是否已有完整正式物理分册绑定，并只以本轮将写入的去重视频数预估完整物理分册需求：没有正式分册时，窗口同时列出`未备册`的逻辑工作夹及实际需要的“完成首册备册后仍需新增”分册；已有正式分册但容量不足时只列出实际新增分册。**备册资格与视频写入资格分离：0 条目标仍需首册备册，但不得因 0 条目标额外创建容量分册或写入视频。**确认窗口按逻辑工作夹分组；新增分册必须嵌套在所属逻辑工作夹下，不得平铺为无归属末项。不得把无正式分册伪装为已有分册，也不得因先显示`未备册`而跳过首册后的分册缺口。

**单窗口确认与勾选/删除分离。** 若备册目标需要首册或新增物理分册，页面必须只打开**一个**“同步前备册确认”窗口；不得再叠加或跳转到第二个“确认创建并绑定”/“确认绑定”窗口。该一个窗口逐项列出未备册规则、嵌套的新增分册，以及实际发现的同名远端候选（精确 B 站 ID、名称、成员数），同时承载`bilimi·暂存`是否同步的单项选择。候选必须由用户在窗口内明确选择；存在未选择候选时确认按钮禁用。暂存未备册时，窗口仍列出`bilimi·暂存（未备册）`，而复选框只决定它是否进入本次视频写入目标，默认未选不得移除其备册义务。用户一次点击`确认备册并继续`仅授权当前窗口已列出的创建或精确绑定，并在创建前再次读取目录；随后重新读取规则、分类、排除集、正式分册、成员数和暂存选择，只有所有当前备册目标缺口已经消失才可冻结并开始同步。预检在此期间变化时，替换同一个窗口的内容并要求再次确认。无缺口且暂存未选时沿用既有零弹窗直达路径。取消或关闭不创建、绑定、冻结或写入视频。上方已保存规则的勾选/取消勾选只表示**当前整理轮是否参与分类投影、归档预览和同步目标**，并将结果持久化为下一轮默认状态：取消后规则、绑定、分册及 B 站数据必须保留。下方纯推荐本地草稿的取消则按本节表格删除草稿；已映射到上方已保存规则的推荐项只恢复或取消该规则的勾选，不得因名称相同错误删除规则。删除远端或其他本地规则仍只允许通过独立删除模式完成目标选择和确认；勾选操作不得调用任何远端删除事务。

**单窗口内的准备反馈。** 从点击`确认备册并继续`到备册/候选绑定/分册预检/权威刷新/冻结开始的每一个准备状态与错误，必须显示在仍打开的“同步前备册确认”窗口正文中，状态使用可读的进行中语义，错误使用可读的失败语义。被该窗口遮罩的确认执行区不得同时显示同一准备状态或错误；窗口关闭、确认完成、失败或预检变化时要同步清理临时状态。不得为展示进度另开第二个弹窗、关闭当前弹窗后在后台继续无提示准备，或用整个整理区的 loading 覆盖鼠标与其他无关交互。

**包含暂存选择的单窗口同步确认。** 本轮存在未匹配视频或备册目标存在首册、候选绑定或容量分册缺口时，`确认并同步到 B 站`只打开一个最终“同步前备册确认”窗口。窗口在同一正文中显示本次整理数量、`bilimi·暂存`是否同步的复选框、按逻辑册分组的未备册目标/新增分册，以及实际发现的同名远端候选（精确 B 站 ID、名称、成员数）；暂存始终默认不上传，但已勾选且有归档预览成员的未备册暂存仍显示在备册清单。候选未选择时确认按钮禁用。目标清单超过固定可视高度时只有正文内部纵向滚动，标题、暂存勾选、关闭和`确认备册并继续`保持可见；短清单不显示无意义滚动条。一次确认只授权窗口列出的创建或精确绑定，随后仍须重新读取权威预检、创建前二次目录读取并核验全部备册缺口后才冻结；目录或预检变化时更新**同一个**窗口并要求再次确认。关闭或取消不写本地规则、不创建/绑定/删除 B 站收藏夹，也不写入视频。既无未匹配视频、也无任何备册缺口且暂存未选时，不显示窗口，直接走既有冻结和同步路径。

“已分类”与“已扫描”是两个独立事实：本轮已封存/已汇总批的`已分类 N/N`不表示基础扫描已经完整结束。若扫描概览仍记录未扫描数量，确认区必须同时如实显示该数量并继续禁用完整本轮写入；该扫描状态不能覆盖、改写或伪造标签采用失败原因。修复采用失败后，应继续当前草稿的相应安全步骤，而非因这两个独立状态同时出现就要求用户重新整理。

| `从收藏库 bilimi 收藏夹删除` | 当前视频仍属于当前 bilimi 工作夹时可用，并经现有二次确认。 | 只移除当前工作夹的本地归属，保留审计原因；成功后立即从当前范围、选择与详情收敛。 | 保留 B 站收藏、其他工作夹、转写、档案、保护和其他账号数据；再次操作已移除项须提示准确原因，不使用笼统失败。 |
| `从 B 站 bilimi 收藏夹删除` | 仅在当前视频有已观察到、可核验的 bilimi 受管远端归属时显示为可执行，并经二次确认。 | 仅请求移除对应 B 站关系，结果按成功/失败/未知分别显示并刷新权威快照。 | 没有远端证据时禁用并说明不可执行；不从本地归属推断远端归属，不删除本地档案、转写、其他远端来源或整条收藏库记录。 |
| `重试` / `对账` | 单项同步、刷新、绑定或远端删除失败/未知时显示。 | 只重试失败步骤，或先读取远端事实再收束未知状态。 | 不重试已成功项，不清空原错误或半成功明细。 |

### 6.5 批量操作、进度、部分成功与恢复

| 阶段 / 控件 | 显示与正常结果 | 失败、暂停与边界 |
| --- | --- | --- |
| 批量操作入口 | 仅在有选择时显示；先分析每条视频、来源、目标、绑定、容量和权限，列出可执行项与跳过原因。 | 混合普通来源、未备册目标、待对账、无权限或虚拟范围不得静默计为成功。 |
| 批量操作文字与菜单 | `复制至`、`刷新信息`、`重新整理`、`转写操作`、`更多批量操作`在同一批量操作行使用同一字体族、字号、字重和行高；`转写操作`的下拉项目保持原有菜单内容。 | 选择状态、禁用状态、打开/关闭下拉和操作回调不变；文字不因组件来源不同而大小不一致。 | 只统一批量操作行的字体继承，不修改详情页转写按钮、转写队列、档案或任何远端操作。 |
| 批量确认 | 用户看到操作类型、作用范围、远端副作用、预计跳过项和不可恢复性后确认。 | 取消确认不改变选择、归属或远端；不能把“当前页选择”扩大为全库。 |
| 批量删除逻辑工作夹 | 候选和确认命令只包含真实`bilimi-logical:*`工作夹；选择多个正式工作夹时沿用同一修订的原子本地删除。 | `local:inbox`绝不混入候选、全选结果或`delete-local-managed-folders`命令；本地扫描暂存不因此清空。执行失败保留选项和具体中文错误，不能只显示“收藏库操作未完成”。 |
| 批量复制 / 移动 / 仅本地删除 | 执行时逐项显示已完成、进行中、跳过和失败计数；成功项立即刷新列表/详情投影。 | 一项失败不回滚无关已成功本地/远端事实；本地删除和远端取消仍是不同计划。 |
| 批量`同步到 B 站` | 有选择时先沿用既有同步预分析与确认；确认后直接进入同步阶段，不重新分类、不生成新的整理草稿。 | 同步阶段沿用整理收藏已有的进度形态：显示当前项/总进度、成功/跳过/失败/未知；可`暂停同步`，暂停等待当前请求安全收束并持久化进度；继续只执行未完成项；可`结束整理`放弃剩余本次同步计划但保留已经确认的 B站成果与检查点。 | 只在正式绑定及远端目标可核验时发送 B站写入；登录失效、冷却、网络和未知结果分别处理，不能静默跳过或伪造成功。 |
| 其它批量远端操作 / 关闭窗口 | 真实远端阶段显示当前项、总进度、成功/失败/未知和可操作原因。关闭或结束时按安全规则等待、暂停或保留可恢复检查点。 | 不把关闭窗口当取消，不回滚已经确认的 B 站动作，不丢本地审计和可重试状态。 |
| 完成摘要与权威刷新 | 所有项收束后显示成功、跳过、失败、待对账及下一步入口；同步、移动、复制、删除和采用远端归属的每个收束均刷新主进程权威快照。 | 导航数量、当前列表、失效选择、详情和状态标签及时按新快照收敛；不以渲染器乐观猜测替代实际副作用。 | 不以总成功数掩盖失败/未知；不全库阻塞刷新，重新打开抽屉可读取主进程最新事实。 |

### 6.6 收藏库性能、账号和数据恢复保护

- 查询、排序、筛选、聚合数字和详情读取优先走当前账号本地仓库；远端刷新只由明确动作触发，并且不能阻塞已有本地浏览。
- 账号切换、窗口重开、本地清理、导入/迁移、规则保存、备册/绑定和整理草稿变化均应精确失效受影响缓存；不全库重渲染、不使用旧账号快照覆盖新账号，也不把远端用户夹缓存恢复成本地 bilimi 工作区实体。
- 大量视频、多个物理分片或长处理记录时，鼠标、滚动、窗口缩放、最小化和关闭必须保持响应。

### 6.7 收藏库操作反馈、备册闭环与跨页面投影

1. **单一操作反馈位置。** 收藏库由用户动作触发的进行中、成功、部分成功、失败、跳过、暂停、结束和可重试反馈，统一显示在当前工作夹标题栏的中部反馈槽；该槽没有反馈时不占位。不得同时在顶部错误条、工作夹标题旁、批量菜单下方或列表底部重复同一条操作结果。删除/备册确认弹窗正文内的范围、风险和逐项预览仍保留；行内转写状态和详情内固有状态标签仍保留，但不得复制为第二条收藏库操作提示。反馈更新只替换该槽的轻量文本，不重建列表、不抢焦点、不改变滚动或选择。
2. **备册当前范围。** `备册当前收藏夹`只锁定当前逻辑工作夹，`备册工作夹`只锁定菜单中用户勾选的逻辑工作夹；二者都复用同一个既有“预检 → 候选明确确认或创建并绑定 → 主进程权威刷新”的备册链。无候选时在同一确认闭环创建并绑定；有候选时只按用户勾选的精确 B站 folder ID绑定。备册成功只建立/更新规则与物理分册，不上传视频、不移动成员、不清空当前工作夹成员；失败、取消或未知均保留原成员和可重试事实。
3. **批量同步与单项同步。** 批量`同步到 B站`复用已有逐项同步执行/检查点模型，在确认后直接进入同步状态，显示当前项、总数、成功、跳过、失败和待对账；`queued`是排队/暂停前置，不得计为失败。批量同步可暂停、继续和结束剩余计划，已确认的 B站结果及检查点保留。单视频同步只按既有单项处理并在收束后刷新当前列表与详情。两种同步都不得重新整理、生成新草稿或在没有正式绑定目标时伪造执行。
4. **按钮与远端删除边界。** 批量/单项“从收藏库 bilimi 收藏夹删除”在存在本地 bilimi 归属时必须走既有本地删除确认；“从 B站 bilimi 收藏夹删除”只在有可核验受管远端归属时可执行，否则明确禁用原因。按钮的可执行性不能由“归属状态”的显示文案决定；每个动作收束后均刷新同一权威快照。
5. **掌库—收藏库同一状态投影。** 掌库删除、解绑、备册、绑定、改名和恢复任一完成后，必须由主进程发布包含新 revision 的同一收藏仓库快照，并由同一条已持久化规则状态投影收藏库标题。右侧规则为`未绑定`时，左侧对应逻辑工作夹也必须显示`未绑定`，不得因物理分册暂缺降级为`未备册`；右侧为`未备册`时左侧同样为`未备册`。收藏库标题不提供“去掌库收藏夹设置保存后绑定”入口，右侧既有“备册当前收藏夹”入口保留。收藏库收到 revision 时，若当前范围、摘要、当前页或详情可能受影响，必须有界重读而不能只替换摘要；因此右侧掌库变为`未备册`后，收藏库标题、导航、可用入口和详情在同一次收束中变为`未备册`。仅更新摘要的通知不得让旧列表或详情继续代表已备册事实。
6. **交互性能。** 上述反馈、同步进度和 revision 更新必须通过现有帧调度/有界刷新路径合并；不得在每个鼠标事件、每条进度或每次局部状态变化同步扫描仓库、等待 B站、重建全部虚拟行或阻塞 Electron 主事件循环。开发版验收必须覆盖批量同步进行中以及备册、移动、删除/解绑后的鼠标移动、点击、滚动、缩放、最小化、恢复和关闭持续响应。
7. **确认弹窗的轻量选择。** 工作夹删除和备册候选的勾选、取消勾选、全选只同步读取当前复选框布尔值并更新本地选择状态；在用户点击最终确认前不得删除、备册、同步、刷新目录、重算全库或发起 B 站请求。事件对象不得跨 React 状态回调延后读取，任何本地选择异常都必须留在弹窗内，不得使主窗口进入载入失败兜底。
8. **仅从收藏库删除后的恢复时机。** “仅从收藏库删除 bilimi 工作夹”必须真实移除对应逻辑工作夹和本地成员；删除命令自身及其紧随的技术性摘要刷新不得重建空壳，界面应保持删除结果。后续由用户发起的独立刷新、备册、扫描、批阅或整理保存，才可在右侧规则仍启用时重建空工作夹。恢复只创建本地空壳、不得回填旧成员，也不得读取、创建、改名、移动、同步或删除 B 站数据。选择“同时从 B 站删除收藏夹（保留右侧规则）”时，只有远端删除成功才清除对应规则的正式绑定并投影为`未备册`；失败、未知和纯本地删除均不得误改右侧规则状态。

**绑定确认弹窗布局。** `确认绑定 bilimi 收藏夹`在候选超出视口时固定标题/关闭区、说明和底部取消/确认操作区；只有候选条目在中部独立纵向滚动。短内容不显示无意义滚动条；滚动条使用浅蓝轨道与有对比度的蓝色圆角滑块。该布局不改变候选范围、默认选择、精确 ID确认、键盘语义或任何 B 站写入条件。

| 重试和取消 | 临时失败按安全重试规则处理；用户取消时停止对应请求并保留已确认的本地结果/检查点。 |
| 数据边界 | 发送给 DeepSeek 的内容必须由当前功能说明，例如整理收藏可发送标题、UP、标签、简介、来源、当前建议与 bilimi 册目信息；不得发送不相关凭据或隐私数据。 |

| 数据迁移/导入恢复 | 兼容旧本地数据时先检查范围和版本；导入预览不触发远端动作。 | 不导出设备绑定的敏感远端实体 ID，不用迁移覆盖另一账号。 |

## 9. 小咪桌面伴随窗口

### 9.1 最终行为

小咪是可拖动的桌面伴随入口，支持唤醒主窗口、打开助手、触发`赞 / 赐 / 表 / 转`快捷动作和显示空闲、工作、提示、成功、错误状态。启动默认开启；用户关闭后持久保持关闭，显式唤醒立即显示并保存开启。网页全屏可按设置临时收起，不能借临时收起改写启动偏好。

小咪位置和助手展开方向按屏幕工作区计算，避免越界；透明区域可点击穿透，交互区域支持拖动和点击。主窗口、B 站页面、收藏、转写、DeepSeek、登录、Cookie 和任何远端写入不依赖小咪。小咪加载、修补和鼠标恢复失败只记录诊断，不阻塞主窗口。
## 10. 质量门禁、测试隔离与发布

最终版本在开发版、生产预览版和 Windows 安装版验证：冷启动、网页标签、四个助手页签、批阅、札记、单 P/多 P 转写、档案导出、普通规则新建/编辑/保存/勾选/删除、备册、绑定、同步、远端删除、整理扫描/标签/分批、推荐上下联动、取消后复用、改名断链、删除后重现、DeepSeek 失败降级、收藏库批量操作、重启恢复和小咪窗口。

所有长操作都有准确的进行中、成功、失败、取消或待核对状态；失败可重试或对账。真实 B 站副作用只由明确用户动作触发。鼠标移动、点击、键盘、滚动、窗口缩放、拖动、最小化、恢复和关闭在启动、扫描、备册、同步、删除、转写和小咪后台任务期间持续响应。
