## 全局不变原则

1. **浏览和本地资料优先可用。** B 站登录、网络、页面结构、DeepSeek 或媒体工具出错，只影响相应远端能力；不应让本地收藏库、札记、档案或设置整体不可用。
2. **真实 B 站写入必须可感知。** 点赞、投币、收藏、弹幕/评论、创建或同步 B 站收藏夹、取消 B 站收藏等操作，必须有进行中、成功、失败或待核对反馈；页面实际结果是最终事实。
3. **本地与远端要分清。** “保存”“仅保存到收藏库”“取消推荐”“从收藏库删除”和“同步到 B 站”不是同一动作，不能因实现方便互相替代。
4. **草稿与已执行方案要分清。** 整理收藏的扫描、推荐、预览、人工调整和 DeepSeek 调整在确认前都是可继续修改的草稿；冻结并开始真实 B 站执行后，分类方案不可再静默改变。
5. **一个业务状态只允许一个权威来源。** 账号级收藏仓库和整理工作区由 Electron 主进程持久化；页面只能显示快照并发送命令，不能另存一份会与其他页面脱节的真相。
6. **失败不伪造成功。** 请求失败、结果未知、保存尚未完成或用户取消时，必须保留真实可重试/可对账状态；不能先关闭对话框、取消勾选或清空草稿再声称成功。
7. **耗时操作不得阻塞界面。** 远端读取、绑定、改名、删除、备册、快照持久化和大列表重算必须分段或排队执行；点击后立即显示准确的进行中状态，鼠标移动、点击、滚动、窗口缩放、最小化、关闭和取消入口始终可响应。不得用同步阻塞、整页重渲染、假进度、静默跳过校验或禁用整个窗口换取表面速度；每个阶段必须保留可恢复的成功、失败、取消或结果未知事实。

## 1. 应用窗口与 B 站浏览

### 1.1 首次启动、主窗口与全局反馈

| 控件或状态 | 作用与正常结果 | 不同情况下 | 不会影响 |
| --- | --- | --- | --- |
| 首次启动前权限检查 | 说明桌面能力和外部服务边界；用户确认后记录已完成引导，后续进入主界面。 | 长时间“启动中”时应可完全退出重开；仍失败时使用设置中的诊断。 | 不应要求用户把 B 站密码写入设置。 |
| 主窗口 | 同时承载网页标签栏、中央 B 站浏览区和右侧助手。 | 窄窗口应压缩布局但不能让网页横向溢出、按钮互相遮挡或隐藏主要状态。 | 助手开关不能销毁网页标签、当前页面或本地数据。 |
| 全局提示与状态灯 | 显示最近一次跨页反馈；`DeepSeek`、`转写音频`、`整理`状态灯能跳到相应功能区。 | 长耗时操作必须显示进度或进行中；失败提示应指出登录、网络、页面、工具或配置原因。 | 某一个后台任务的错误不应阻塞其他页签。 |
| 最小化、恢复、关闭 | 按设置处理窗口关闭行为；恢复后保留可恢复的窗口和助手状态。 | 整理/转写运行时关闭不应丢弃已经确认的检查点；真实远端执行按冻结计划和恢复规则处理。 | 不能把“关闭窗口”误做成删除草稿、清空本地数据或取消已确认远端操作。 |

### 1.2 网页标签栏

| 按钮/操作 | 何时显示或可用 | 点击或操作后的结果 | 失败与边界 |
| --- | --- | --- | --- |
| 首页标签 | 始终存在。 | 切回 B 站首页。 | 不能关闭。 |
| 普通网页标签 | 在应用内打开视频或其他 B 站链接后显示。 | 点击切换当前页面；助手跟随更新标题、UP、链接、BV/AV视频上下文。 | 非视频页或仍加载时，助手显示待识别，不得把旧视频上下文当成新页面。 |
| 关闭标签 | 非首页标签在选中或悬停时显示关闭入口。 | 关闭该标签并切换到相邻可用标签。 | 不能关闭首页；关闭标签不能删除任何收藏、札记或档案。 |
| 刷新 | 始终针对当前激活网页标签。 | 只刷新当前 WebView 页面。 | 不能刷新所有标签或清空助手本地状态。 |
| 视频网页全屏 | B 站页面进入/退出全屏时触发。 | 若设置开启“网页全屏时隐藏小咪”，小咪随全屏隐藏并在退出后恢复。 | 不应关闭助手、终止转写或改变收藏草稿。 |

**页面不可用时：** 网络中断、未登录/登录过期、视频无权限、B 站页面结构变化或网页仍加载，都应限制依赖该页面的动作并显示原因；用户仍可浏览其他标签、查看本地档案和设置。

### 2.3 批阅结果的受保护边界

- 批阅写入 B 站前，必须验证当前标签仍是发起操作时的同一视频。
- 归库和 DeepSeek 二判不能越过收藏夹备册/绑定状态；未能远端写入时可保留本地预分类，但必须明确不是已同步。
- 批阅、整理收藏和收藏库共用同一账号收藏仓库；它们不能各自维护互相矛盾的视频归属。
- 批阅入口读到的目标必须使用第 4.1 节同一身份与数量口径：已保存未备册规则只能成为本地预分类目标，待绑定/待对账不是远端可写目标。
- 批阅失败不能删除札记、档案、转写、已有收藏关系或整理草稿。

**预分类建议与实际写入目标必须分离。** 所有已保存、已启用且非远端草稿的规则都参与本地预分类排序；只有已备册、已绑定并具有真实远端 `folder ID` 的规则才进入本次 B 站写入候选。最佳本地建议不可写时，仍显示并提示其`未备册`或`未绑定`，同时选择评分最高的可写匹配规则写入；账号中无关规则的未备册/未绑定缺口不得阻止该目标。没有可写匹配规则时，只有已启用、已备册且已绑定的`暂存`可作为回退；没有任何可写目标时不得请求 B 站收藏、不得登记已确认远端归属。回退反馈必须同时显示`预分类建议：X（未备册/未绑定）`和`已写入：Y`，绝不把 X 描述为已同步；备册、绑定、创建、移动和删除都不是批阅的隐式副作用。

### 2.4 批阅收藏后的本地登记一致性

批阅收藏是一个跨 B 站与本地收藏仓库的两阶段操作，远端成功和本地登记不得混成多条由页面逐条提交的命令。页面先完成 B 站收藏并取得实际返回的远端 folder ID，再把同一个 `operationId` 和最终目标提交给 Electron 主进程的专用批阅登记入口；主进程重新校验当前账号、目标 bilimi 规则、物理分片绑定、远端 folder ID 与 B 站成功证据，不信任页面自行伪造的保护或历史状态。

| 阶段 / 数据 | 设计要求 | 失败、重试与恢复 | 用户可见状态与边界 |
| --- | --- | --- | --- |
| B 站动作完成 | 只有 B 站接口或页面回读确认实际收藏成功，才进入本地登记；每个目标规则必须有对应的真实远端 folder ID。 | 未确认成功不得写“已同步”；结果未知保留内部操作记录，等待对账，不盲目重复 B 站写入。 | B 站状态只显示`已同步`或`未同步`；不增加“部分同步”“待核对”等第三种状态。 |
| 本地主进程登记 | 由专用主进程协调器在一个仓库事务中写入：视频基础资料、收藏位置、整理保护记录、`entered` 收藏历史事件，并发布一个新的权威 revision。 | 四类记录必须整体成功；失败不能提交半套结果。主进程保存可恢复操作记录，后续按同一 `operationId` 补齐。 | 本地技术故障不覆盖已经确认的 B 站状态，不删除已有视频、档案、札记或远端收藏。 |
| 幂等重试 | `operationId` 是唯一键；相同操作重复调用只返回现有结果或补齐缺失记录，不重复追加历史、不重复移动归属、不调用 B 站。 | 应用重启、重复点击、窗口重新打开均可安全重试；已有完整记录直接返回成功。 | 不显示重复操作提示；仅在内部执行日志记录重试次数和原因。 |
| 多目标与账号校验 | 主进程必须一次校验全部目标规则和 folder ID，目标有一个未绑定或不一致就不写入任何目标的本地登记。 | 校验失败保留 B 站真实结果和内部待补齐任务；修复绑定后可只补本地，不重新收藏。 | 不把页面的旧快照、名称相同规则或数量猜测当作身份依据。 |
| 异常退出与旧半成品 | B 站成功后进程在本地登记前退出时，启动/账号恢复流程读取操作记录，补齐视频、归属、保护和事件；已有视频/归属的旧半成品只补缺失项。 | 补齐不触发 B 站副作用；无法确认账号或目标时暂停内部重试并保留诊断证据。 | 不向用户增加中间状态；收藏库详情和历史以主进程最终快照为准。 |

**一致性顺序：** `B 站确认成功 → 主进程校验 → 本地四类记录原子提交 → 发布权威快照`。远端动作不能由本地补偿逻辑重复执行；通用 `favorite-repository:commit-command` 继续拒绝冻结工作区和保护类命令，页面只能使用专用入口。

## 4. 掌库：收藏夹身份、规则、备册与绑定

掌库管理的是“用户希望如何组织视频”的本地事实；B 站收藏夹是用户拥有的远端收藏夹，bilimi 工作区是本地规则、草稿、整理归属和仓库数据。B 站收藏夹、bilimi 本地工作区、扫描来源、推荐候选、收藏库视频行和整理草稿是不同层级的投影，不能把远端收藏夹再复制成第二份 bilimi 收藏夹列表。任何页面都必须用真实规则 ID、远端 folder ID 和主进程快照读写，不能以名称、候选短 ID、数量为零或远端 ID 暂缺来猜测身份。

### 4.1 身份、状态、数量与权威来源

**数量先说明口径，再显示数字。** `远端成员数`是一次已确认 B 站观察或对账得到的实际成员数；`本地已分配数`是收藏库当前本地归属到该逻辑规则的视频数；`本轮计划数`是当前整理草稿已选择、尚未冻结执行的数量；`—`表示该状态没有远端实体或远端数量未知。数字是事实的度量，**0 和非 0 均不改变身份**，未知不能显示为 0。

**展示层次与行为资格必须分开。** “用户收藏夹（B 站）”展示当前账号的全部远端收藏夹，包括名称含 `bilimi`、历史物理工作夹和已经绑定到 bilimi 规则的收藏夹；“bilimi 工作区”只展示本地草稿、规则和本地已整理/入库归属。一个已绑定的远端夹仍属于用户收藏夹，本地规则通过真实规则 ID 与远端 folder ID 关联，不能复制成第二个远端实体。**扫描概览仍显示原有纯远端来源表格和逐夹选择信息；顶部合并标题显示为同一控件文案`全选（N）`，括号数量紧跟在“全选”旁，不删除收藏夹名称、数量、来源关系或数量切换。** 本地规则、已入库数量、备册和绑定操作在掌库管理与收藏库中查看。

| 删除中、部分成功、删除失败或远端结果未知 | 保留原身份、正在处理/失败原因和成功子项；不提前从所有投影移除。 | 重试、对账、返回详情或按明确确认结束。 | 不吞掉部分成功，不对未知远端结果盲重试，不把本地删除扩大为远端删除。 |

**删除与重新备册后的刷新。** 本地规则删除、解绑、备册、确认绑定或对账一旦返回权威结果，掌库、收藏库和当前整理草稿必须同时失效并从新快照重投影。扫描概览只随下一次 B 站远端观察刷新夹的存在、名称、成员数和本轮统计；它不显示这些本地关系短状态。重新备册成功后掌库/收藏库短状态立即变为`已备册`；失败或结果未知时保留真实短状态与详情原因，不能继续显示旧关系，也不能伪造恢复成功。

**已备册的唯一事实条件。** bilimi 逻辑工作夹只有在主进程快照中存在至少一个对应的 `physicalShards`，并且每个实际参与该逻辑工作夹的分册都具有真实远端 `folder ID` 且 `bindingState=bound` 时，才显示`已备册`。逻辑工作夹没有物理分册、物理分册为空、分册处于`pending-reconcile`/失败/未知，或规则仍带有用户解除标记时，均不得显示`已备册`，而应按当前生命周期显示`未备册`、`未绑定`或`收藏夹已删除`。旧快照中“逻辑状态已绑定但物理分册为 0”的数据只做本地确定性修正，不读取、创建、删除、改名或移动 B 站数据；修正后所有页面以同一新快照显示。

**删除、恢复与回收的最终规则。** 视频、收藏库工作夹、本地收藏夹规则和 B 站 bilimi 工作夹是四种不同删除范围。仅从收藏库删除视频只移除本地视频行，不改变备册绑定、工作夹、档案、转写或 B 站来源；删除本地工作夹只处理本地工作夹投影；右侧删除本地收藏夹规则后，左侧保留原工作夹的恢复窗口并显示`收藏夹已删除`，不显示`未备册`或`未绑定`，也不参与批阅、分类、备册和同步。左侧`恢复当前收藏夹`只恢复删除前保存的右侧规则快照，不创建/绑定 B 站收藏夹、不备册、不同步视频；恢复成功后才显示`备册当前收藏夹`。用户明确选择“同时从 B 站删除整个 bilimi 工作夹”时，只有远端真实删除成功才清除已存在的绑定并让右侧规则显示`未备册`；仅已进入右侧删除确认流程的默认工作夹，名称识别但未绑定的候选才可在用户完成“我已确认”及未绑定知情确认后删除其预览到的真实远端 folder ID，成功后必须跳过不存在的本地绑定清理，不能误报失败。自建未正式绑定规则不提供该 B 站删除路径。失败或结果未知保留真实绑定与待对账状态。右侧同名新建/备册始终是独立新规则；下一次整理收藏的最新权威快照或右侧备册成功快照才对仍未恢复的旧工作夹执行回收，回收只清理失去全部来源的旧投影，不误删新同名规则、档案、转写或札记。

**绑定与同步必须分开。** 用户只能从现有`备册收藏夹`、`备册当前收藏夹`或规则详情中的`备册`进入创建/绑定；`确认绑定`只存在于本次发现实际未绑定远端候选的确认页，不是规则卡片、详情或菜单上的独立常驻按钮。右侧全量入口在点击瞬间锁定当前已勾选的已保存本地工作夹，并在这一动作中读取 B 站清单：对无实际候选的锁定目标直接创建并保存绑定，不显示创建确认；对有实际未绑定远端候选的目标才显示现有的绑定确认页，按每个逻辑工作夹默认全选全部候选分册，用户可取消或调整分册顺序。若用户刚在既有双确认路径中收到 B 站成功删除某个精确旧`folderId`的回执，系统只把该精确 ID保留为待重新备册期间的删除证据：首次读取和创建前二次读取都忽略它，也不把它重投影为远端草稿；因此该旧 ID的最终一致性残留不能把规则误变为`未绑定`。这绝不等于按名称认领：同轮出现任何**不同 ID**的同名远端夹仍是实际未绑定候选，必须回到确认页；删除证据不能自动绑定、不能掩盖不同 ID、不能创建重复夹。直接创建前必须重新读取当前 B 站清单；若竞态下出现实际候选，停止创建并回到该候选的确认页，不能重复创建或自动绑定。创建响应返回精确 ID后，正式登记必须以无缓存清单对该 ID立即、短暂间隔后有界重读；若仍不可见，保留`已创建 · 待正式确认`而非普通候选，下次右侧备册只重试这个 ID。新建 ID正式绑定成功后才清除上述旧 ID删除证据。每次成功读取清单后，都必须把未被本地规则占用的疑似 bilimi 收藏夹更新为独立的`未保存 · 未绑定`远端草稿；该同轮草稿投影必须随直接创建成功、候选确认早退或创建失败一并返回并刷新，不能只依赖后续偶然的状态读取。真实 B 站远端草稿不属于本次全量备册范围，不能改变全选范围，也不得被创建、绑定、改名、移动或同步。候选确认页必须同时显示本地规则 ID、B 站远端 folder ID、当前账号、容量、将改变的本地状态和潜在 B 站副作用。确认成功后才进入已绑定/可同步状态；`同步到 B 站`不能承担隐式绑定职责。

**物理分册身份与绑定顺序。** 一个逻辑工作夹可以对应 0、1 或多个物理分册。每个分册以当前账号、逻辑工作夹 ID、远端 folder ID 和 `shardNumber` 共同确定身份；名称、数量、清单顺序和暂时缺失的远端结果都不能替代真实 ID。普通备册、刷新、删除恢复和后台重试只按已保存远端 ID 复用绑定，绝不自动认领、合并或改名已有远端收藏夹。绑定确认窗口显示每个具体远端 ID、实际标题和数量；默认顺序优先使用已有 ID→分册号记录，其次使用标题中的明确`·N`，都没有时只作为可调整建议使用远端清单顺序并以数量降序展示。用户可在确认前上移/下移调整，确认后的最终顺序才写入`shardNumber`；只有这次明确确认允许按指定 ID 修复`·2`等名称，取消、失败、结果未知和普通备册不产生改名副作用。同名候选缺少可靠历史编号时必须要求用户按具体远端 ID 选择，不得按数量或列表位置猜测。

**单个备册的范围与确认。** 收藏库左侧`备册当前收藏夹`在点击瞬间锁定当前逻辑工作夹的真实 ID，只向主进程提交这一项；当前分册下拉菜单只改变查看范围，不把备册扩大到其他逻辑工作夹，也不把逻辑工作夹备册缩小成某一物理分册。主进程预检必须先读取该逻辑工作夹的权威快照和当前 B 站清单，再决定是否需要绑定；在预检完成前不得创建、绑定、改名或写入任何 B 站收藏夹。

当目标没有正式物理分册/绑定、仍有用户解除标记、或只剩旧 remote ID 但仓库没有对应正式分册时，单个入口必须打开`确认绑定 bilimi 收藏夹`确认页：按真实远端 folder ID 列出候选、标题、数量、账号、分册顺序和会发生的 B 站副作用；没有可复用候选时也必须先显示“确认创建并绑定当前收藏夹”的确认页，不能静默创建后直接显示成功。用户取消、关闭或未选候选时不写本地绑定、不创建/改名 B 站夹，结果不显示备册成功。用户确认后只为当前逻辑工作夹写入所选绑定/创建结果并刷新共同快照；其它规则、远端夹、视频成员、同步计划和草稿不改变。只有预检确认目标已有真实正式绑定时，才允许跳过绑定确认并复用既有远端 ID。

单个入口的结果摘要只统计当前逻辑工作夹（成功 1/失败 0 或对应失败原因）；右侧助手的全局`一键备册`仍按其原有的全量选择与确认流程执行，不能被单个入口复用或反向影响。任何页面看到的`已备册`都必须由同一权威状态投影，不能因为旧缓存、规则中的历史 remote ID、名称相同或某次状态核验看到了远端夹而替代正式绑定。

### 4.6 跨页面、账号与恢复边界

- 账号切换时，规则、物理分片、绑定、收藏库、窗口偏好、扫描工作区和在途任务按 `accountMid` 隔离；不得引用、恢复或写入另一账号实体。
- 关闭掌库/收藏库窗口仅关闭视图，保留可恢复的当前账号选择、查询、编辑检查点和在途操作真实状态；恢复时以主进程快照对账，不能拿旧 React 内存覆盖持久化结果。
- 本地数据清理、导入、迁移或账号恢复必须先显示影响范围。它们只能操作本地选择范围，不能自动删除 B 站收藏、远端工作夹、登录或其他账号数据。

**恢复安全屏障：** 正常关闭整理时先在后台完成并持久化该安全屏障；正常重开时只核验已暂停的持久化草稿，因而不得重复发送暂停或重写相同检查点。异常退出（崩溃、强制结束）没有机会执行正常暂停：重开入口仍在后台读取最后持久化检查点，必要时收束可安全判定的本地运行状态，再发布恢复摘要。两种情形下，恢复弹窗、恢复预览和恢复后的确认执行界面只能在主进程完成以下步骤后展示：停止扫描和标签补取领取，等待在途 B 站读取收束并保存扫描/标签检查点；停止 DeepSeek 领取新批次，等待当前请求收束并保存未完成批次检查点；暂停确认执行意图和正在进行的 B 站同步，等待当前远端请求完成并保存逐项同步检查点。DeepSeek 的该动作是“暂停并保留结果”，不是取消；B 站请求未收束、检查点未持久化或结果未知时不得伪装成已暂停。异常退出后最后一次 B 站写入结果未知时，必须保留“结果待核对”并禁止直接继续写入。检查全程不显示居中过渡窗；安全屏障失败时显示具体阻塞原因和可重试入口，不显示普通恢复按钮。

安全屏障只负责为用户打开恢复入口，不会自动恢复、自动扫描、自动调用 DeepSeek、自动保存收藏库或自动写入 B 站。用户选择`恢复草稿`后才恢复当前轮次；用户选择`重新扫描`或`放弃本轮整理`后才分别执行对应的二次确认和边界检查。冻结、同步中、同步已暂停和结果待核对均是**未结束轮次**，必须显示同一组三项按钮，不能借由直接跳至确认执行页隐藏恢复选择。结果待核对在恢复后必须先对账，不能继续写入；重新扫描或放弃均只结束本地本轮计划，**不自动回滚已发生的 B 站操作或已保存收藏库成果**。工作镜像损坏/无法校验仍走重建路径，不得伪装为可恢复草稿。

### 5.2 扫描概览分区、来源选择与扫描生命周期

扫描概览是“本轮工作区目前知道什么”和“接下来能安全做什么”的事实面板，不是普通收藏夹列表的另一份缓存。它先完成视频收藏的基础扫描，再按第 5.3 节补取标签；标签补取一旦开始，基础扫描范围已经完整确定。基础分页只采纳视频身份、标题、UP、封面、收藏时间和失效状态等基础事实；即使响应偶然带有标签、`tname` 或`category`，也不把它们作为标签确认或 B 站分区分类依据。页面只展示当前批/本轮进度和来源选择，不展示 bilimi 本地工作区、本地数量、备册、绑定或关系详情。来源区域保留原有 B 站收藏夹来源表格、顶部全选、逐夹名称与选择、总数、本批来源关系和已有数量切换；顶部合并控件显示为同一文案`全选（N）`，数量括号必须紧邻“全选”文字。所有当前存在的远端收藏夹一视同仁纳入全选范围，不能以名称、`bilimi` 前缀、数量为 0、备册、绑定或远端 ID 是否暂缺来置灰、隐藏或改变来源资格；内部仍保存远端 folder ID 和来源选择集合供扫描、恢复及其他页面使用。

**扫描与标签进度行：** 多批工作区的“当前批次”和“本轮总览”均在同一“扫描进度”区域显示两行横向进度：第一行为`扫描进度`、横条、扫描计数（仅扫描中或失败时显示）和扫描状态；第二行为`标签补取`、横条、范围计数和标签状态。当前批第二行必须使用当前批 scope，显示`当前批 已处理 / 总数 条`；本轮总览第二行必须使用整轮 scope，显示`本轮 已处理 / 总数 条`，不得把当前批数字带入总览。本轮总览顶部既有的`标签补取中 N 条 · 已补取 N 条 · 待补取 N 条`文字汇总继续保留，作为整轮明细摘要。每行优先保持“标签 + 横条 + 数量 + 状态”同一行；侧栏变窄时只收缩横条，数量和状态不得截断，只有剩余空间仍不足时才受控换行。进度条只是快照投影，不附带操作控件，也不改变扫描、补取、采用、保存或同步状态。

### 5.3 标签补取与“采用当前标签”的可逆循环

标签区必须同时显示当前批次和本轮的进度、历史已知标签、本轮获取标签、已确认无标签和读取失败数。标签补取只能在基础扫描完整结束后开始，故本轮完整视频范围在此阶段已经确定。基础分页没有可靠标签能力，独立标签接口是唯一能够把视频标为`标签已确认`（包括确认后为空）的渠道；不得因基础分页的空值、偶发标签字段或 B 站分区字段跳过补取。未补取标签只限制依赖它们的系统判断，不能把视频伪装为“确认无标签”；用户采用当前标签后，系统以当时已取得的标签作为可审计的标签截止版本，在完整本轮范围内重算分类，无法匹配的项进入可见未匹配/暂存路径。

**收藏库整理的历史标签：** 从收藏库选中视频新建整理工作区时，视频记录中的非空历史标签直接作为该视频当前整理周期的已知且已确认标签；已有明确 `tagEvidence=confirmed` 的空标签也作为已确认结果。系统仍可显示这些标签的来源为“沿用历史标签”，但不得再次要求用户采用，也不得显示“新增或变化标签，待采用”。旧的 `scope=selection` 整理草稿恢复时，按同一规则补齐完整历史标签批次的本地采用截止状态（包括 `acceptedSegmentIds` 和对应版本），只修正本地标签状态，不改收藏库视频内容、人工分类、推荐选择、B 站关系或远端数据；缺少标签证据的视频仍按普通补取与采用规则处理。

**批次结果的即时投影：** 任一批的标签补取由“补取中”变为已有最新结果时，系统必须立即以该批和当前已就绪批的真实标签重建推荐、刷新归档预览及相应系统分类；用户不需要点击`采用当前标签`才看见推荐。这个即时刷新只更新可继续修改的草稿投影，不创建标签截止版本、不自动勾选推荐、不写收藏库或 B 站。若此前存在采用版本，继续补取产生的新结果会使该版本失效；若补取自然完成且待补取、失败均为 0，也不凭空制造新的采用动作。

**采用成功后的完整结果与执行资格：** `采用当前标签`不是只改变一个标签状态。系统必须先在主进程持久化“停止领取新标签”的安全暂停候选；已经领取且数量有限的读取只允许收束为成功标签或失败记录，收束完成前不得发布标签截止版本、推荐、分类或执行资格。待在途读取归零后，系统在同一主进程权威队列中构造该次标签截止版本，并以这一份快照对**完整本轮范围**完成系统分类重算和推荐重建；成功后一次发布截止版本、推荐、分类和准备度。发布后的已采用截止版本不得被迟到结果静默改写；只有用户明确点击`继续补取标签`，才可解除该截止版本、重新领取待办并使新的标签结果进入下一次采用循环。只有完整结果发布后，当前批和本轮总览才同时展示/刷新推荐收藏夹与归档预览，未匹配项仍须可见。自然完成且没有待补取/失败项或标签增量时，当前结果直接作为权威草稿，不要求点击置灰的采用按钮；标签补取实际运行、仍有待补取/失败项、完整范围重算或 DeepSeek 运行时，`保存本轮到收藏库`和`确认并同步到 B 站`才禁用。任何持久化、收束、重算、推荐或快照投影尚未完成的中间状态，均不得先显示旧推荐/旧预览并放开写入按钮；失败时不得更新采用版本或执行资格，应保留可恢复的旧事实和具体错误。采用、推荐、预览和资格更新仅改变本地工作区，保留人工分类与已勾选推荐，且在用户点击保存或同步前绝不写收藏库或 B 站。

**重启后的多批采用与失败快照：** 完整本轮范围必须以持久化的分段描述符为准。进程重启后，内存中只装载当前批的详细项目是正常的；`采用当前标签`重算时必须按完整描述符顺序逐批读取各自持久化分段，不能以当前内存批是否含有该分段来缩小范围或误报分段不存在。真正无法读取或校验的分段才进入可恢复失败状态，不能把正常草稿要求为重新整理、重新扫描或清空。采用命令一旦已持久化`recomputing`或`failed`终态，主进程 IPC 必须返回该账户的最新权威快照；该返回资格必须由协调器明确标记为“本次调用已持久化失败”，不得仅凭读取到旧的`failed`状态吞掉新的存储、恢复或工作区异常。渲染器以返回快照替换点击前旧快照，按`采用当前标签未完成：本轮分类重算失败，请在当前草稿重试采用。`显示阻塞，不能把失败错投影为“仍有 0 条待补取或读取失败”。内部失败详情可持久化用于诊断，但不得直接作为用户文案。此类失败保留草稿、标签、推荐、人工分类和已有系统分类，不写收藏库或 B 站。

| 标签状态 / 控件 | 显示与禁用条件 | 点击后的状态与结果 | 持久化、失败与不会影响 |
| --- | --- | --- | --- |
| `暂停补取标签` | 全局标签补取实际处于 `running` 且仍有未采用批的待办时显示且可用。 | 请求安全暂停；当前在途读取按后台最终状态落库，之后不再启动下一条补取，并保存检查点。 | 保存各批已取得的标签、失败信息和采用版本；不删除已读标签，不暂停扫描、DeepSeek 或同步。 |
| `继续补取标签` | 统一处理手动暂停后仍待补取的标签和读取失败标签的再次补取；存在 `pendingItemCount > 0` 或 `failedItemCount > 0` 且任务未运行时可用；两者均为 0 时仍保留按钮但置灰，不以隐藏代替状态。 | 从同一工作区保存的检查点恢复待补取，并把失败项一并重新入队；开始继续后当前标签截止/执行资格按草稿变化处理，直到任务结束或再次采用。 | 不重切批、不丢人工分类或已勾选推荐；不把失败改写为无标签；不写 B 站。 |
| `采用当前标签` | 标签操作区始终保留。只有存在尚未采用的新/变化标签版本且本轮未冻结时可用；安全暂停候选正在等待已领取读取收束、或完整范围重算正在进行时保持处理中且禁止重复点击；自然完成且待补取、失败均为 0 时没有新的采用动作，按钮保留但置灰。 | 可用时依照本节“采用成功后的完整结果与执行资格”先收束已领取读取，再完成完整范围重算并刷新推荐、归档预览；置灰时不触发命令、不显示“当前标签尚未采用”阻塞提示。 | 只重算系统结果；保留人工分类和已勾选推荐；不写 B 站。命令失败时不更新采用版本或执行资格，保留具体错误和可恢复的暂停检查点。 |
| 标签结果已完整 | 待补取与读取失败均为 0 且没有新标签增量时显示两个置灰按钮；不再显示“当前标签尚未采用”提示。 | 标签结果只作为当前权威工作区事实，推荐/预览可直接使用，不要求用户再点击采用。 | 不重复启动补取、不重复标记采用版本、不改变扫描总数和真实标签统计。 |
| 其他批标签任务 | 非当前批仍在补取、暂停或失败时在本轮进度中如实标记。当前批采用成功会把全部未采用批的补取安全暂停；切换批次或进入本轮总览本身不改变该暂停状态。 | 只由`继续补取标签`从未采用批检查点恢复；其新结果会使本轮标签截止版本过期，等待用户再次采用。 | 不能用全局 `running` 遮住当前已采用或其他 ready/saved 批的可见结果；不得因继续而重读已采用版本。 |

**状态序列：** 基础扫描完整结束后才可进入标签补取。手动控制为 `running` → `暂停补取标签` → `paused` → `继续补取标签` → `running`；继续动作同时覆盖待补取和失败项。采用为 `awaiting-adoption(version=N)` → 持久化暂停领取 → 已领取读取收束 → 构造候选并完成全范围重算 → 一次发布 `accepted(version=N)` + 全局`paused`；自然完成且没有待补取/失败或标签增量时直接以当前权威结果进入可保存/同步状态，两个按钮仍保留但置灰。收束、重算未完成或失败时不发布新采用版本。若明确继续补取产生新结果，截止版本随即失效，只有存在新的标签增量时采用按钮才恢复可用；不再提供独立的失败重试按钮。

### 5.5 推荐取消、上方收藏夹投影与归档预览

推荐区、扫描概览上方的收藏夹卡片、详情/删除入口和持久化收藏夹规则必须解析到同一个真实规则 ID。它们只是同一工作区事实的不同投影，页面不得各自保存一份会脱节的“已推荐/已删除”状态。打开整理收藏、切换当前批或进入归档预览时，必须从主进程读取当前权威工作区快照再投影，不得优先复用旧渲染快照；只读刷新不自动重新扫描 B 站，也不丢失已保存的人工调整。

| 控件 / 场景 | 显示与操作规则 | 权威状态、失败与明确边界 |
| --- | --- | --- |
| 推荐生成 | 根据已扫描 UP 主和达到规则阈值的高频标签生成；推荐属于当前整理草稿，不等于已自动创建远端收藏夹。 | 推荐候选与上方卡片均从工作区权威快照投影；生成本身不写 B 站。 |
| 勾选推荐 / 上方卡片勾选 | 两处任何一方改变时，另一方同步为同一规则的“本轮参与整理”状态；已勾选目标参与预览和确认执行。 | 不得用候选短 ID 代替真实保存 ID；保存尚未完成时显示进行中，不能让第二个入口对未知实体操作。 |
| 取消未备册的本地候选推荐 | 该候选由本轮推荐生成，尚未备册且无绑定、无实际远端实体时可点击取消。 | 必须先等待权威本地取消推荐与删除成功；成功后下方推荐候选保留为未勾选，上方由该候选投影的本地收藏夹卡片移除。失败时两处维持原状并显示可重试错误。不得留下“幽灵卡片”，也不得对已不存在的 ID 再发第二次删除。 |
| 取消已备册、已绑定或有实际远端实体的推荐 | 该推荐对应真实远端/绑定实体时可点击取消。 | 只取消本轮推荐勾选；真实收藏夹上方卡片保留。取消推荐本身不删除远端实体，也不把未对账状态伪造成删除成功。 |
| 详情删除 / 删除模式删除未备册候选 | 该项是可删除的本轮推荐本地候选时显示并允许选择。 | 与下方取消推荐共用同一笔权威本地事务；成功后下方候选、上方卡片、详情和删除模式同时刷新。 | 不能因入口不同留下一处旧投影；不删除 B 站远端收藏夹。 |
| 新建 / 保存推荐工作夹 | 保存成功后，推荐、上方卡片、详情和后续取消统一改用权威保存结果中的真实 ID。 | 保存失败或尚未完成时不提前移除/新增投影；不能打开伪草稿、误删同名规则或吞掉错误。 |
| 保存推荐到收藏库 | 点击本批/本轮保存时，先等待推荐选择与分类队列完成，再按最新主进程分类提交本地成员关系。 | 已勾选且实际有成员的视频目标立即出现在收藏库对应工作夹；无远端分册的工作夹显示`未备册`，普通新建规则也显示`未备册`。 | 不依赖旧渲染快照，不写 B 站，不创建无成员空夹；保存失败保留草稿并允许重试。 |
| 归档预览联动 | 推荐勾选、上方卡片编辑/新增、标签结果自然完成或采用标签和人工转移后，预览按同一权威工作区状态重算；打开卡片时先刷新当前快照。 | 不从独立页面缓存取旧结果；不删除收藏库视频、档案、转写或普通来源成员关系；不因旧渲染草稿存在而阻止查看当前事实。 |

### 5.7 DeepSeek 辅助整理

| 整理范围 | 默认“整理不确定项和【未分类】（推荐）”；可选只整理未匹配项或重新检查全部。用户这一次的临时选择不应改变下次默认值。 |
| 批次范围 | 从当前批次页打开时默认当前批次；从本轮总览打开时默认本轮所有批次；单批次不额外显示批次范围。 |
| 开始、取消、进度 | 确认后才请求 DeepSeek；运行时显示可读进度与`取消整理`。第一次点击`取消整理`立即进入禁用的`正在取消`，同一次请求必须停止当前在途工作并阻止后续批次开始，不能要求第二次点击；已创建本轮检查点时，取消命令只能在已完成结果收束、`已取消`检查点已持久化且其返回快照已是终态后完成。若请求尚处于启动阶段、尚未写入首个检查点且尚未发起 provider 请求，取消必须直接收束为无运行记录的终态，不得为了标记取消而创建空草稿。前端不得用陈旧的“运行中”快照覆盖取消状态。最终恢复`开始整理`，已完成分类与可恢复检查点保留。 |
| 规则变化后的草稿 | 规则变化不能使 DeepSeek 永久不可点。整理入口先恢复当前草稿、按当前规则重算系统分类并保留手动分类，DeepSeek 只处理恢复后的工作区。 |
| 结果合并 | 请求开始时记录每个视频的事实指纹（当前分类、来源选择、人工调整和推荐选择）；返回后逐视频与主进程最新快照比较。来源选择必须是当前已勾选的完整 B 站收藏夹集合，包含普通收藏夹和已绑定的 bilimi 工作夹；全轮计划、每次请求和回写比较必须使用同一集合。未变化的视频应用 DeepSeek 结果，已被用户或后台更新的视频保留当前分类并标记为冲突。 | 勾选状态在请求后真实改变时才是来源冲突；不得因来源集合在不同层被不同过滤而制造整组失败。冲突只影响对应视频，不让整批因普通工作区变化失败；不得覆盖人工调整、来源选择或推荐选择。 |

### 5.8 确认执行、保存与 B 站同步

确认执行以当前权威工作区中已经完成的基础扫描、标签结果和完整本轮分类为准。标签补取实际为`running`、仍有待补取/失败项、完整范围重算中或 DeepSeek 整理为`running`时，写入按钮必须禁用并说明真实阻塞原因；自然完成且待补取/失败均为 0 时不要求额外点击`采用当前标签`，两个标签按钮置灰但保存/同步可按当前结果开放。确认执行在主进程将意图从`waiting`切换为`running`之前，必须在同一权威队列再次校验完整本轮标签截止版本；截止已失效时不得写入`running`、不得保存收藏库、不得冻结或生成 B 站同步计划，而应持久化`blocked/tag-cutoff-changed`并显示“自动执行已停止：标签结果已有新变化，请重新采用当前标签后再保存或同步。”。写入`running`后，`继续补取标签`和失败标签重试必须被主进程拒绝，直到执行结束或取消该执行意图；不能在预检通过后让标签命令推翻截止版本。该原因不得错误投影为目标收藏夹、备册、绑定或 B 站计划故障。用户点击继续补取后，直到任务收束且必要的分类重算完成，写入资格再次按当前工作区状态判断，不因待办自然归零伪造采用动作。

`采用当前标签`是完整本轮写入资格的显式收束命令：先持久化停止领取，等待已认领标签结果收束，再以同一权威快照重建推荐与完整本轮分类，最后一次性持久化完整截止版本并返回该终态快照。命令返回前，不能只留下“已暂停”或仅更新推荐；当标签待补取/失败均为 0 而采用尚未完成时，确认区必须显示“采用当前标签未完成”及真实的重算失败原因，不能错误提示“仍有 0 条待补取或读取失败”。重算失败时保留当前草稿、标签、推荐、人工分类和已有分类结果，写入保持禁用并提供原地重试采用；不得要求重新扫描、重新整理、清空草稿或触发 B 站写入。采用成功后同一快照必须同时满足完整标签截止版本、当前推荐/分类投影和保存/同步资格；已经存在的完整分类不得因为采用流程再次失败而被丢弃或要求用户重做。

“已分类”与“已扫描”是两个独立事实：本轮已封存/已汇总批的`已分类 N/N`不表示基础扫描已经完整结束。若扫描概览仍记录未扫描数量，确认区必须同时如实显示该数量并继续禁用完整本轮写入；该扫描状态不能覆盖、改写或伪造标签采用失败原因。修复采用失败后，应继续当前草稿的相应安全步骤，而非因这两个独立状态同时出现就要求用户重新整理。

| 按钮/状态 | 应有行为 | 远端与恢复边界 |
| --- | --- | --- |

| 执行中的`暂停同步` / `继续同步` | 只在真实逐项 B 站写入阶段显示。状态机固定为`同步中 -> 请求暂停 -> 已暂停 -> 请求继续 -> 同步中`，可反复循环，直到完成、失败、待对账或结束本轮。点击暂停后，仅在当前远端请求或暂停命令尚未收束时显示并禁用`正在暂停…`；主进程持久化为`sync-paused`后显示`B 站同步已暂停`与可点击的`继续同步`。继续后必须恢复可点击的`暂停同步`，不得保留旧的`正在暂停…`本地状态。暂停等待当前请求完成并持久化进度，继续只执行未完成项。 | 同步的权威状态只来自主进程工作区快照；渲染器临时请求态必须在收到`已暂停`、重新`同步中`、完成、失败、待对账、结束或请求失败时复位。不得重复已确认写入，不取消收藏库已保存结果，不影响 DeepSeek 或扫描。 |

### 6.4 单条归属、同步与删除操作

| `确认绑定` | bilimi 工作区存在待绑定/待对账关系，用户选定一个真实 B 站收藏夹且登录、账号、folder ID和容量信息可读取时显示。 | 展示本地规则、远端收藏夹、账号、容量和副作用；用户确认后只建立本地规则与远端 folder ID 关系，逐项记录成功/失败/未知。 | 不能按名称或同步选择自动绑定；失败/未知保留待绑定/待对账，不写入视频成员关系。 |

### 6.5 批量操作、进度、部分成功与恢复

| 阶段 / 控件 | 显示与正常结果 | 失败、暂停与边界 |
| --- | --- | --- |
| 批量操作入口 | 仅在有选择时显示；先分析每条视频、来源、目标、绑定、容量和权限，列出可执行项与跳过原因。 | 混合普通来源、未备册目标、待对账、无权限或虚拟范围不得静默计为成功。 |

### 6.6 收藏库性能、账号和数据恢复保护

- 查询、排序、筛选、聚合数字和详情读取优先走当前账号本地仓库；远端刷新只由明确动作触发，并且不能阻塞已有本地浏览。
- 账号切换、窗口重开、本地清理、导入/迁移、规则保存、备册/绑定和整理草稿变化均应精确失效受影响缓存；不全库重渲染、不使用旧账号快照覆盖新账号，也不把远端用户夹缓存恢复成本地 bilimi 工作区实体。
- 大量视频、多个物理分片或长处理记录时，鼠标、滚动、窗口缩放、最小化和关闭必须保持响应。

## 7. DeepSeek：全局设置、调用与故障隔离

| 功能/控件 | 设计行为 |
| --- | --- |
| DeepSeek 总开关 | 从关闭变为开启时，一次性启用趣味评论、自动总结和小咪聊天三个子功能；之后用户可独立关闭任一子项，除非总开关再次关闭后重新开启才重置该次默认。旧偏好缺失子项时按兼容规则继承。 |
| 连接测试/保存 | 保存后只显示保存/可用/失败状态，不能回显 API 密钥。密钥不可读、URL/模型无效或连接失败必须区分提示。 |
| 功能开关 | 趣味评论、札记总结、批阅二判、整理收藏辅助整理、小咪聊天按各自开关与前置条件独立控制。 |
| DeepSeek 总结完成后的当前札记刷新 | 队列项的`summaryStatus`从`queued`/`generating`进入成功保存，且对应档案版本的总结文本从空变为非空时，当前札记静默重新读取该视频档案快照。 | 当前札记立即显示总结，按钮由`生成总结`变为`重新总结`；从档案库返回与直接留在札记的结果一致。 | 只刷新本地快照，不重复转写或调用 DeepSeek；失败/取消保留文稿和真实状态，不显示虚假总结。 |
| 调用中的全局状态 | DeepSeek 状态灯显示进行中、完成或错误，可跳到设置；任何实际 DeepSeek 工作都必须接入同一工作态汇总，包括连接测试、批阅二判、收藏整理、札记总结以及转写队列中 `summaryStatus=queued/generating` 的独立总结阶段。工作态悬浮提示显示具体任务内容（例如“正在生成 DeepSeek 总结：视频标题”），不得只显示静态“DeepSeek 已连接”；任务完成、失败或取消后及时切换到对应终态。一个功能的请求不应锁住其他本地工作。 |
| 重试和取消 | 临时失败按安全重试规则处理；用户取消时停止对应请求并保留已确认的本地结果/检查点。 |
| 数据边界 | 发送给 DeepSeek 的内容必须由当前功能说明，例如整理收藏可发送标题、UP、标签、简介、来源、当前建议与 bilimi 册目信息；不得发送不相关凭据或隐私数据。 |

## 8. 设置、账号、本地数据与诊断

### 8.1 设置项

| 设置或按钮 | 应有行为 | 边界 |
| --- | --- | --- |

| 收藏策略 | 每视频最多 1/2/3 个 bilimi 目标等策略影响批阅与整理预览。 | 改策略不应隐式重写已经冻结或已执行的旧轮计划。 |
| 整理收藏批次 | 选择 500、1000、2000（推荐）、自定义 500–5000 或无限制（实验）；见第 5.4 节。 | 保存后只影响下一轮新建工作区每批最多加载的详细视频数；当前草稿不重切分、不重算，既有标签进度、人工分类、推荐选择和冻结计划不变。 |
| 转写线程与模型 | 可选择 1/2/4/无限制等线程策略和已验证模型；说明性能、硬件、下载/许可证和当前设备限制。 | 变更影响新任务；队列中任务使用入队时保存的模型，不能被静默改写。 |
| 网页全屏时隐藏小咪 | 打开时网页视频全屏隐藏小咪，退出全屏恢复。 | 不关闭小咪功能或主窗口。 |
| 助手宽度、动效与界面偏好 | 用户调整后按账号/偏好规则持久化，重启恢复；窄窗口仍保持主要控件可用。 | 不应反复触发昂贵数据刷新或造成网页树重渲染。 |
| 小咪悬浮快捷键 | 默认顺序为 `赞 / 赐 / 表 / 转`，最多四项；用户可独立增删。 | 旧的已废弃快捷项须按兼容规则清理，不生成不可用按钮。 |

### 8.2 本地数据与账号边界

| 操作 | 应有行为 | 明确禁止 |
| --- | --- | --- |
| 启动与功能诊断 | 检查网络、本地媒体工具、存储、当前页面和关键功能依赖，给出中文可操作结果。 | 不应因诊断发起真实收藏、扫描或写入。 |
| 账号切换 | 账号级收藏库、工作区、缓存、任务和偏好按 `accountMid` 隔离。 | 禁止读取、恢复或写入另一账号的工作区和收藏。 |
| 掌库 / 收藏库视图恢复 | 当前账号的用户收藏夹范围、本地 bilimi 工作区范围、查询、排序、筛选、页码、滚动、选择、详情和菜单开关按第 4.6、6.1 节分别保存/恢复；恢复后用主进程快照校正。 | 不把视图偏好当作规则、绑定或远端状态；不能拿旧窗口内存覆盖新持久化事实，也不能把远端夹恢复成另一条本地工作区记录。 |
| 清理本地数据 | 显示清理范围和不可恢复性；用户确认后只清理选择的本地数据。 | 不得因“清理本地数据”自动删除 B 站收藏、账号登录或远端文件夹。 |
| 数据迁移/导入恢复 | 兼容旧本地数据时先检查范围和版本；导入预览不触发远端动作。 | 不导出设备绑定的敏感远端实体 ID，不用迁移覆盖另一账号。 |

## 9. 小咪桌面伴随窗口

| 操作/状态 | 设计行为 |
| --- | --- |
| 显示与隐藏 | 小咪可独立显示于桌面；与主窗口、助手共享状态。网页全屏隐藏设置生效时按第 8 节处理。 |
| 点击小咪 | 可唤醒主窗口或打开助手，并给出与当前功能区相符的提示。 |
| 拖动 | 仅主鼠标按钮开始拖动；拖动不能误触唤醒、关闭或右键菜单。指针捕获取消时安全结束拖动。 |
| 右键与快捷菜单 | 显示小咪菜单与快捷入口；失焦或按规则点击外部后关闭。 |
| 悬浮说明 | 悬停当前快捷操作时给出简短、与实际功能一致的说明；点击反馈优先于闲置问候。 |
| 连续点击/情绪状态 | 快速重复点击、靠近关闭动作等交互按已设计情绪反馈呈现，但不能阻塞主窗口恢复和正常菜单操作。 |
| 大小调整 | 只改变小咪显示尺寸，不改变主窗口、助手或数据设置；控制按钮不应被小咪主体遮挡。 |
| 透明窗口点击穿透 | 非控件透明区域允许按平台规则点击穿透；鼠标在小咪控件上时保持可操作。 |
