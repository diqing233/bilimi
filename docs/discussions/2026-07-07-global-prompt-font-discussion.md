# 2026-07-07 全局提示视觉讨论

## 状态

- 当前模式：已进入实现。
- 用户已在 2026-07-08 明确说出“开始”，允许修改相关样式和测试。
- 本文档记录全局提示区域的视觉优化讨论。
- 之前尝试使用可视化浏览器辅助时，浏览器出现闪退 / 崩溃；本轮先继续使用文字讨论，除非用户明确要求，否则不在此线程调试浏览器。
- 本轮讨论、讨论文档、记忆同步类更新要求使用中文。

## 当前观察

- 全局提示位于 `src/renderer/src/features/assistant/FloatingAssistantApp.tsx` 中的 `.floating-assistant-global-status` 区域。
- 当前布局是两行紧凑信息：第一行是全局反馈句子，第二行是三个后台状态灯。
- 反馈文字目前约为 `13px`、常规字重、单行省略，并放在淡蓝色背景上。
- 状态灯文字约为 `12px`，颜色偏弱；整体更像次要元信息，而不是“当前系统状态”的主提示。
- 2026-07-07 追加截图观察：提示条是淡蓝色，而上方标签栏和下方内容卡片区域都接近白色。这会让提示条像被插在两个白色块之间，缺少和整体助手面板的归属感。
- 当前问题不再只是“字体不够明显”；容器颜色关系也不协调。淡蓝提示条需要二选一：要么更柔和地融入周围白色表面，要么更明确地成为一个有语义的状态带。

## 待办计划

- 确认优化范围：只调整全局反馈句子，还是同时调整反馈句子、状态灯和提示条背景。
- 明确视觉层级：当前反馈为主，后台状态为辅。
- 比较 2-3 个低风险视觉方案。
- 判断提示条应该融入周围白色表面，还是强化为有意设计的状态带。
- 进入实现前确认验收标准。

## 方案选项

### 方案 A：强化文字层级

- 将主反馈文字提升到约 `14px`。
- 增加字重，例如 `font-weight: 700`。
- 使用更深的文字颜色，例如 `var(--porcelain-deep)`。
- 状态灯保持更小、更弱，避免抢主提示的层级。

取舍：改动最小、风险最低，但如果整个提示条容器本身缺少强调，可能仍然显得不够协调。

### 方案 B：强化主提示区容器

- 保持提示区域紧凑，但让第一行明确成为主状态。
- 增加细微的左侧强调线，或更明确的上 / 下边界。
- 主反馈文字加粗、加深，必要时可以考虑小标签，例如“提示”或“状态”，但默认不额外增加可见文案。
- 状态灯保持为次级信息。

取舍：提示层级更清楚，也更容易被一眼看到；但会增加助手面板顶部的视觉重量。

### 方案 C：将反馈和状态灯分区

- 将主反馈句子作为独立的浅底提示条。
- 三个状态灯放到下方独立一行。
- 通过间距、底色和边界把“最新反馈”和“后台状态”区分开。

取舍：信息架构最清楚，但会增加垂直空间占用，可能影响紧凑侧边栏布局。

### 方案 D：让提示条融入周围白色表面

- 保留两行结构，但减弱蓝色填充，让它成为极轻的表面色，而不是单独的蓝色块。
- 主要依靠边框、间距、文字层级来表达状态，而不是依赖较明显的背景色。
- 让提示区和下方内容区域属于同一套表面语言，状态圆点负责提供颜色强调。

取舍：最符合当前截图暴露的问题；但如果底色太弱，提示可能再次显得安静，因此需要配合文字加粗、颜色加深和边界强化。

### 方案 E：把提示条强化为明确的状态带

- 保留或略微加深淡蓝色，但通过更清晰的边框、左侧强调线和内部间距，让它看起来是有意设计的系统状态带。
- 减少“白色 - 蓝色 - 白色”的偶然拼接感，让提示区承担明确的状态展示职责。
- 下方内容卡片继续保持白色，使状态区和内容区各有职责。

取舍：功能感更强，信息更明确；但如果蓝色过重，顶部会显得压迫或抢内容焦点。

## 推荐方向

优先采用“方案 D + 方案 B”的组合：先让背景和整体面板更协调，再强化主提示文字。根据截图，单纯放大字体无法解决根因，因为提示条仍然会作为一个淡蓝色横块夹在两个白色区域中间。更稳的第一步是让提示条像助手面板的一部分，同时用更深、更粗的主提示文字和更弱的状态灯恢复信息层级。

## 已确认事项

- 用户认为全局提示字体目前不够突出。
- 相关区域已定位到浮动助手的全局状态块。
- 用户进一步指出视觉不和谐：上方是白色、下方是白色，但全局提示条是淡蓝色，导致颜色过渡尴尬。
- 当前已进入实现阶段。
- 讨论文档、记忆同步类说明和后续整理要求使用中文。

## 实现记录

- 采用“方案 D + 方案 B”的组合：提示区背景从明显淡蓝改为更接近面板的近白色 `rgba(247, 251, 255, 0.82)`，边框对比从 `0.18` 降到 `0.14`，减少“白色 - 蓝色 - 白色”的割裂感。
- 主反馈文字改为 `var(--porcelain-deep)`、`14px`、`font-weight: 700`，让当前反馈比后台状态灯更容易被一眼看到。
- 后台状态灯保留原有 12px 和 muted 色，继续作为次级状态信息。
- 新增样式测试覆盖全局提示区背景、边框、主文字层级和状态灯层级，避免回退成突兀的淡蓝横条。

## 反对意见

- 不应只靠“把所有字都变大”解决问题，否则三个后台状态灯会和主反馈争夺注意力。
- 不应把全局提示做成很响亮的警告横幅；它是常驻区域，不能在正常浏览时持续抢焦点。
- 不应在两个白色区域之间保留一个中等对比的蓝色矩形，除非它有明确语义；否则会像临时贴上的色块。
- 不应为了适配这条提示区而大改标签栏和内容卡片；优先在提示区局部解决层级和融合问题。

## 验收标准

- 最新全局反馈句子能一眼读到。
- 后台状态灯仍然可见，但明显是次级信息。
- 提示区域高度稳定，不引发布局跳动。
- 文本省略正常，不与按钮、状态灯或内容卡片重叠。
- 当前紧凑助手 / 侧栏宽度下仍然可用。
- 顶部标签、全局提示条和第一张内容卡片看起来属于同一个完整面板，而不是三个无关横条。
- 提示条要么自然融入周围表面，要么清楚表达为有意设计的状态带。
