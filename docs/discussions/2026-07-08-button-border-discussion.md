# 2026-07-08 按钮边框视觉讨论

## 状态

- 当前模式：实现已开始。
- 用户已在 2026-07-08 明确说出“开始”，本轮允许修改相关样式和测试。
- 本文档记录截图中按钮边框去除的视觉需求。
- 讨论文档和记忆同步类更新使用中文。

## 当前观察

- 截图中黄色框标出的按钮位于“收藏夹”和“整理旧藏”等分组标题旁。
- 这些按钮看起来像窄小的上下 / 折叠控制按钮。
- 当前按钮存在明显的默认边框或控件边框，视觉上偏硬，和页面内其他浅蓝色、轻量化按钮风格不统一。
- 标题文字本身是较强的深蓝色，旁边的小按钮如果带边框，会抢到不必要的注意力。

## 待办计划

- 确认目标按钮范围：只处理标题旁的上下 / 折叠小按钮，还是包含其他操作按钮。
- 确认去边框后的可点击性表达方式。
- 保持按钮尺寸稳定，避免去边框后标题排版跳动。
- 进入实现前确认 hover、focus、disabled 等状态的表现。

## 方案选项

### 方案 A：只去掉静态边框

- 默认状态下移除按钮边框。
- 保留按钮内部图标和点击区域。
- hover / focus 时仍显示浅蓝背景或细边界，保证可发现性和键盘可访问性。

取舍：最稳，视觉立刻干净；但需要确保用户仍能看出这是可点击控件。

### 方案 B：改成纯图标按钮

- 去掉边框和默认按钮底色。
- 使用统一尺寸的图标按钮区域。
- hover 时只出现浅蓝底色，不出现描边。

取舍：最轻盈，适合标题旁的小控件；但如果图标本身不够清楚，可能需要统一图标样式。

### 方案 C：保留边框但弱化到几乎不可见

- 不完全去边框，而是把边框改成极浅色。
- 默认状态更柔和，hover / focus 时略微增强。

取舍：可点击性最稳，但没有完全满足“边框去掉”的直观诉求。

## 推荐方向

优先采用方案 B：标题旁的小按钮应当像辅助图标控件，而不是一个完整的矩形按钮。默认状态去掉边框和明显底色，保留稳定点击区域；hover / focus 时用浅蓝底色表达可交互状态。这样能减少截图中黄色框位置的突兀感，也不会影响标题区层级。

## 已确认事项

- 用户希望去掉截图中按钮的边框。
- 截图重点指向分组标题旁的小型上下 / 折叠控制按钮。
- 已选择局部处理 `favorite-ledger-panel__help-toggle`，不影响“重置”“取消全选”“同步”“新建收藏夹”等文字按钮。

## 实现记录

- 采用方案 B 的最小实现：将标题旁小说明按钮保留为纯图标按钮。
- CSS 中为 `.favorite-ledger-panel__help-toggle` 增加 `appearance: none`，清除浏览器原生按钮外观，配合既有 `border: 0`、`background: transparent`、`box-shadow: none` 去掉默认矩形边框感。
- 未扩大按钮范围，未改动主要文字操作按钮。
- 新增样式测试断言，锁定该按钮默认状态关闭原生外观、无边框、透明底、无阴影，并保留 hover / focus 的颜色反馈。

## 待确认问题

- 本次“按钮边框去掉”是否只针对黄色框标出的标题旁小按钮？
- 去边框后，hover / focus 是否可以保留浅蓝底色来提示可点击？

## 反对意见

- 不建议把所有按钮边框都统一去掉；例如“重置”“取消全选”“同步”“新建收藏夹”等文字按钮仍需要边界来表达操作区域。
- 不建议去掉 focus 可见状态；键盘操作时仍应能看出当前焦点。
- 不建议通过缩小按钮来解决边框突兀，否则可能影响点击热区。

## 验收标准

- 标题旁的小按钮默认状态不再出现明显矩形边框或原生按钮外观。
- 标题区域视觉更安静，按钮不抢标题文字的注意力。
- 按钮点击区域尺寸不变或不明显变小。
- hover / focus 状态仍能看出按钮可交互。
- 其他主要文字按钮不被误伤。
