## 实施前核对与计划

### 已确认

1. I001（R001、R002、R003）：推荐候选的勾选、上方收藏夹勾选、分类归属、归档预览和同步预检必须来自同一稳定规则 ID 与同一版权威快照。
2. I002（R002、R003）：快速采用与完整重分类必须结果一致，首次采用不能显示 0 条旧结果。
3. I003（R003）：只做有界异步状态修复，保持已有功能和交互响应。

### 待用户决定

无。

### 被明确替代 / 明确不做

无。本轮明确不做 DeepSeek、转写、删除确认、视频同步、单个备册入口和任何真实 B 站写入。

### 实施步骤

1. 先在项目书第 5.5 节补充本轮“采用态—规则卡—归档预览—同步预检”同版约束。
2. 在主进程协调器测试中使用真实分类器建立首次采用 RED，证明推荐草稿运输状态不能直接作为本地分类能力判断。
3. 以最小范围构造仅供本地分类的推荐规则投影，保持持久化草稿远端生命周期不变，并验证快速路径与完整重分类一致。
4. 运行协调器、分类能力、工作区、归档预览和同步预检回归；只读 Electron 验收首次采用和响应性，不执行任何 B 站写入。
5. 回写本表证据，运行 `git diff --check`，只提交本轮项目书、账本、生产代码与测试文件。
