## 原文需求

### R001

时间：2026-09-02

> 本轮尚未改业务代码，待处理问题如下。
>
> 1. **新建与删除**
>    - 未开始整理收藏时，新建的纯本地收藏夹不能从详情页删除；整理期间、存在草稿、删除模式中却可以。
>    - 补取标签期间新建收藏夹点击保存会消失；扫描基本信息、采用结束、补取结束时正常，不能破坏这些路径。
>    - 详情页“取消”混入了丢弃/删除语义，应改为纯粹的“收起”。
> 2. **整理收藏工作区**
>    - 扫描中点击“结束整理”应放弃本轮并清理恢复标记，下次不能弹出恢复草稿。
>    - 推荐收藏夹在不同草稿状态下取消勾选不一致。最终要求是：已备册、未备册、结束后都能按已有稳定规则 ID 取消；纯推荐草稿按既有语义删除采用草稿，已保存规则只取消勾选；下一轮仍能重新关联。
>    - 改动不能影响整理期间已有的采用、分类和上下联动。
> 3. **启动性能**
>    - 安装版冷启动仍会短暂卡住鼠标，需要继续分离首帧、B 站页面加载和小咪后台启动。这个只能由真实 Electron 三种形态验收，不能只看测试。
> 4. **删除分册数据**
>    - `honker233` 删除预检显示 3 个分册，详情却显示 1 个。仓库快照确有 3 个不同远端 ID，不能直接当 UI 重复删掉；要先与当前 B 站清单对账，区分真实三夹、重复登记或旧数据残留。
> 5. **B 站改名后的绑定**
>    - “音乐舞台”已经证明按正式 ID `4065561111` 找到了改名后的 `bilimi·音乐舞台哈哈`，不是名称误匹配。
>    - 但旧逻辑把“找到同一 ID”错误等同于“仍已备册”，显示“下次备册自动改名”，导致不能正常删除、不能参与预分类。
>    - 最终方案：原规则保留，不建第二张草稿卡；改为特殊“未绑定”候选，保留勾选和本地分类，精确 ID 可进入现有删除流程。
>    - 用户点击现有“备册”并在既有确认中确认后，才恢复 B 站名称并重新登记正式绑定。检测本身不自动改名、绑定或同步。
>    - 账号配置还留有历史 ID `4085267611`，不能再被当作正式绑定依据。
> 6. **跨设备边界**
>    - 有本地正式 ID 的设备可以识别远端改名。
>    - 新设备没有这份本地映射时，不能把改名后的夹自动认回旧规则，只能作为明确候选让用户确认。
>
> 你确定这些都改了吗，我怎么测了一下没有一个完成
