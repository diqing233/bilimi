## 排查记录（讨论阶段）

### 2026-08-20：R001-S1

1. 渲染层的四个选项与状态映射完整：`updated-desc`、`updated-asc`、`title-asc`、`title-desc`。点击非默认项会重置到第 1 页，并调用分页读取；菜单本身不是未接线状态。
2. 渲染层 `load()` 仅在排序不是 `updated-desc` 时传送 `sort`。因此默认“最近更新”向 IPC 省略该参数。
3. 服务层虽然将缺省排序概念上设为 `updated-desc`，但在无搜索、无筛选、无显式排序时，特意走旧的“直接返回原 aid 列表”分支。因此默认“最近更新”实际不会比较时间。
4. 服务层在有显式 `updated-asc` / `updated-desc` 时会比较 `video.updatedAt`；缓存键包含 `sort`，分页在排序后再切页，因此缓存、IPC 校验和分页不是本次根因。
5. 实际开发数据（`bilimi-dev`，账号 `32922854`）中，截图的 `bilimi-logical:game` 有 1307 条：1305 条 `updatedAt` 为同一个初次整理写入时刻，仅两条是后续批阅新增。故“最早更新”即使走到排序也只能使用 aid 作为同时间兜底，视觉上会像按 aid 排序；当前成员持久化顺序正是该 aid 升序。
6. 该同时间戳由整理收藏落库路径造成：`oldFavoriteWorkspaceCoordinator.ts` 在保存一个分段时，对所有视频使用同一次 `this.now()` 写入 `updatedAt`。后续元数据合并还会保留旧的 `updatedAt`。
7. 基础扫描实际可取得 B 站分页字段 `fav_time`，页面桥已把它保存为 `addedAt`，当前工作区片段也保留该字段；但保存本批到收藏库时未将 `addedAt` 写为 `favoriteAt`，所以最终收藏库缺少可用于历史收藏时间排序的字段。现有测试只用不同的人工 `updatedAt` 验证服务排序，并未覆盖“实际扫描的同批数据 + 默认最近更新 + 历史 B 站收藏时间传递”这一组合。

结论：截图标注的两个时间排序都存在真实缺陷，但原因不同：最近更新是请求参数省略导致根本未排序；最早更新有排序代码却因历史数据写入同一个批次时间而失去业务区分度。是否以 B 站 `fav_time` 作为用户可见时间语义，仍需用户明确决定，不能在讨论阶段自行改名或迁移历史数据。

### 2026-08-20：R003-S1 补充核对

用户指出收藏库已有“最近调整”时间。核对后确认该字段是本轮最合适的时间排序来源：`lastAdjustment.occurredAt` 表示一次明确的整理/分类调整，当前截图范围内全量存在；`classificationAt` 只表示可用的分类投影且有缺失；`position.updatedAt` 会被普通扫描的远端观察批量刷新，不代表用户调整。此前关于以 B 站 `fav_time` 迁移排序的建议不作为本轮需求，保留为未来若新增“按收藏时间”功能时的独立设计边界。

### 2026-08-20：R004-S1 边界核对

1. `lastAdjustment` 的写入覆盖明确的本地归属改变：系统高/低规则、DeepSeek、手动调整、复制、移动、采用 B 站归属、移除 bilimi 归属、删除受管工作夹和放弃/清除本轮整理都会更新；这与“最近调整”的名称相符。普通扫描观察、标签补取、刷新资料、转写进度和单纯同步回执不应刷新它，否则后台任务会扰乱排序。
2. 当前字段为视频级最后调整，不是“某一收藏夹中的最后调整”。同一视频出现在多个收藏夹/工作夹时，在任一处调整都会影响它在所有范围中的位置。这是当前模型的既有含义；本轮不新建“收藏夹—视频”级时间模型。
3. 同一批保存或批量移动会合法地产生完全相同的调整时刻；排序必须提供稳定第二关键字。本轮推荐以正 aid 作为第二关键字，升降序均保持该方向，保证分页、重开和缓存后顺序不跳变；不能伪造批内微秒时间制造假先后。
4. `lastAdjustment` 是可选旧字段。当前截图范围 1307 条均有值，但其他账号、迁移或局部清理后的旧数据可能没有；必须明确定义“未知”的固定位置，且日期解析失败不能悄悄降级为当前时间。
5. 排序变化必须先过滤完整查询集、再按最近调整排序、最后分页；第 2 页的结果不能建立在未排序原数组上。全选范围、导出和批量命令必须继续使用同一查询条件，不能因选择了某种排序而扩大或缩小作用对象。
6. 排序项、前端视图缓存、IPC 默认参数和主进程缓存键必须使用同一枚显式排序值；当前默认项省略参数的漏洞不能只在点击菜单时修复。窗口关闭重开、账号切换、范围切换、搜索和所有状态筛选都需保持/携带该值。
7. 一次调整写入后，订阅会刷新当前列表。若该视频因“最近调整”移动到首页，当前非首页不应出现旧数据覆盖新数据；当前页变得越界时才安全回退到最后一个有效页。已选视频的详情可继续保持，但其批量选择不能因普通排序或刷新而被静默清空。
8. 本轮只改变本地读取顺序和文案/测试，不触发 B 站读取、扫描、标签补取、DeepSeek、转写、同步、迁移或回写已有时间。项目书第 6.1 节已有“完整查询集先排序再分页”的总原则；实施前需补全本项的时间语义、同时间规则、未知规则和回归验收。
