- **未变化**：本轮 2562 条视频的 `aid-revisions`（位置修订、镜像元数据修订与视频更新时间）、这些视频的 B 站物理/逻辑收藏夹镜像 `mirror`、bilimi/B 站绑定 `bindings`，以及“默认收藏夹体系”开关 `default-settings`。

- 调用链已核实：界面点击 DeepSeek -> `oldFavoriteWorkspaceDeepSeekService.organize*` -> `OldFavoriteWorkspaceCoordinator.getSnapshot()` -> `openUnsafe()`；在真正调用 DeepSeek API 前，`openUnsafe()` 比对恢复决策的 `evidenceFingerprint`，发现配置指纹不一致后抛出截图中的英文错误。因此本次没有向 DeepSeek 发送分类请求，也没有产生 B 站副作用。

## 讨论中确认的恢复语义（实现采用）

- “按当前规则恢复”（现有内部选项 `merge-latest`）会以当前事实和当前分类规则更新恢复基线，并重新计算受规则变化影响的系统分类；手动分类保持优先，不会扫描 B 站，也不会写入 B 站。
- “保持原方案”（现有内部选项 `continue-original`）会承认当前指纹而不按新增规则重算，因此语义上可能继续使用已过时的系统分类。
- 原有界面会把这类恢复保护错误显示在 DeepSeek 区域，且文案为英文，并要求用户选择恢复方式；本轮不改错误文案或主进程保护，而是在“整理收藏”入口自动采用上述恢复语义。

## R003 已确认的目标语义（已实现待实机验收）

- 用户点击“整理收藏”时，如存在可恢复草稿，系统应在该入口**自动按当前事实、当前分类规则恢复草稿并重算系统分类**；不再显示“按原草稿继续 / 合并最新变化 / 重新扫描”的恢复选择弹窗。
- 恢复必须完成在 DeepSeek 前。DeepSeek 只读取已恢复的当前草稿与当前分类结果执行原有范围的整理；不再因历史恢复决策而不可点击，也不显示第二个恢复弹窗。
- 自动恢复保留人工分类；本次规则变化不扫描 B 站、不写入 B 站。若恢复过程需要时间，允许使用“整理收藏”本身的正常加载/恢复状态，但不要求用户做额外选择。
- 实现位置：`ControlledFavoriteLedgerPanel.requestOldFavoriteOrganization()`（403-445 行）对含 `merge-latest` 的摘要自动调用既有决策命令；无事实/规则变化的 `continue-original` 草稿直接刷新权威快照。DeepSeek 入口保持原有调用链，因此读取的是恢复后的草稿；`merge-latest` 的按当前规则重算、保留人工分类能力未被修改。
