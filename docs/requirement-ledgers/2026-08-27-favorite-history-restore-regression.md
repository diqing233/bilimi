## 诊断证据（2026-08-27）

### I001：截图中的泛化回退不是旧字面，但仍是错误的无语义记录

- 截图的`收藏夹规则变更：已恢复本地规则与本轮勾选`来自 `OldFavoriteArchivePreviewStep.tsx` 对 `source === 'favorite-rules'`、却没有 `summary.favoriteRule` 的兼容回退。它不是项目书要求的“动作、规则、分类效果”文案。
- 已只读解析当前账号 `32922854` 的活动工作区 `old-favorite-workspace-32922854-20260827035550760-63c299b0-9442-4c09-bf90-31b9ea91d769` 的 journal：其中有两条 `changes=[]` 的 `favorite-rules` 记录，`honker233` 的规则字段、`enabled`、采用集合和排除集合在前后均语义相同；它们只因 `recordFavoriteLedgerHistoryChangeUnsafe` 使用 `JSON.stringify(before) !== JSON.stringify(after)`、而对象属性写入顺序不同被误判为变化。
- 这类记录没有分类移动、没有规则/勾选/采用/排除的语义变化，不能算可恢复用户操作；修复不能只换一段前端文字。应先在主进程用稳定的语义比较阻止新增，并把已有“无移动 + 语义相等”的纯空检查点从可见历史投影中排除；任何实际存在 `favoriteRuleState` 差异的旧条目仍保留、可恢复、并由同一 `before/after` 推导中文动作。

### I002：用户澄清后，根因是历史检查点的事务边界，不是正常上下联动

- R002 明确确认当前普通上下联动功能正常。因此，先前将现象归结为 `createRecommendationProjection` 映射的初步判断已被该用户澄清和 journal 证据否定；该链路不得在本轮为此重构或修复。
- 截图当前的 `bilimi·honker233` 真实稳定 ID 为 `custom-author-honker233-小王爱马枪~9.2d`；本地规则仍存在，状态为 `enabled=true`、`ruleOrigin=recommendation-draft`、`bindingState=unbacked`。历史里先创建该规则，之后发生多次采用/取消；没有“删除规则”的记录。因此截图所选“取消”并没有恢复一个被删除的规则，也没有删除该规则。
- 对同一次“取消”操作，活动工作区 journal 暴露了多个连续、可选择的中间检查点：第一个仅将 `adoptedCandidateIds` 中该 ID 从有变无，第二个再将该 ID 加入 `excludedLedgerIds`，最终检查点才将该规则 `enabled` 从 `true` 写为 `false`。每个条目都有 24 条分类移动。截图选择的是第一个中间态，所以恢复后下方未采用、上方仍勾选；这不是缓存幻觉，也不是正常入口的联动失败。
- 历史记录必须以一次用户的勾选/取消操作为事务边界，只向改动记录暴露包含最终一致状态的可恢复位置。恢复该位置时，`enabled`、采用集合、排除集合、规则集合与分类投影必须同时按同一快照写回。
- 对既有历史，只能在不丢失真实状态差异和恢复意义的前提下，压缩或隐藏纯中间/语义空检查点；不得伪造新操作、按同名推断规则，也不得触发任何 B 站动作。
