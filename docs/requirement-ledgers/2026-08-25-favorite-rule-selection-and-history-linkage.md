### R005

```text
1. 上方已保存收藏夹
   - 勾选后必须触发整轮重新分类；归档预览的预计归档、确认执行的同步目标都要用新结果。
   - 同步目标有未备册收藏夹时，只显示一次覆盖全部目标的备册确认；确认完成后才开始同步。
   - 取消勾选只是不参与分类，规则仍保存；删除必须走独立删除功能。
2. 下方推荐收藏夹
   - 勾选：生成并采用对应推荐草稿，进入本轮分类。
   - 取消勾选：删除这个推荐草稿及其采用状态。
   - 这套“取消即删草稿”只属于下方推荐项，不能误套到上方已保存规则。
3. 上下联动
   - 上方取消某个已保存规则的勾选，下方对应项也必须变为未勾选。
   - 之后从下方重新勾选，应让上方对应的已保存规则恢复勾选；不能产生同名重复规则。
   - 实现必须以稳定规则 ID 对应，不以同名猜测。
4. 改动记录恢复
   - 恢复历史时，收藏夹规则、上方勾选状态、下方推荐项的采用状态要一起恢复。
   - 恢复后必须重新分类，并更新归档预览和同步预检。
   - 恢复不自动创建、绑定、删除 B 站收藏夹，也不写入视频。
5. 统一弹窗的行为是：

   确认并同步到 B 站
   → 必要时只开一个总确认弹窗
   → 在同一窗口汇总未备册、同名未绑定候选、需创建/绑定分册、未分类暂存选项
   → 一次确认
   → 保存到收藏库 → 按确认范围备册 → 开始同步进度
   → 中途预检变化时更新同一窗口，绝不再开第二个窗口。

   顶部取消勾选也已确定为账号级持久状态，下一次开整理收藏默认仍不参与。

要保证上一轮的要求都能正常实现并且鼠标不卡
```

## 已识别的现有实现 / 契约缺陷（无需用户再决定）

1. `docs/contracts/favorites.md` §3.3 当前把整理页面上方已保存规则的勾选定义为工作区“仅本轮选择”；R002 已明确要求顶部取消跨下一轮保持不勾选。本轮实施前必须先更新项目书和契约，再把顶部入口与持久化规则对齐；下方推荐草稿仍保留 I002 的独立取消即删除语义。
2. 同一契约当前保留“同步选项（未分类暂存）”与“同步前备册确认”两个窗口；R002 已明确要求合为单一执行前总确认。无缺口且未选择暂存时保留零弹窗直接执行。
3. 当前工作区历史主要记录分类 journal、推荐采用状态与本轮排除状态；账号级收藏夹规则及其顶部勾选不是同一可恢复历史对象。I004 需要把规则目录快照与推荐采用 / 顶部勾选的变更一起纳入可逆历史，并在恢复后完成受版本保护的重分类，不能只移动分类游标。
4. 规则保存与重分类目前是异步链路；在其完成前，归档预览、本地保存和同步冻结必须锁定，且必须以同一版本的权威快照解除锁定。否则旧目标仍可能被先冻结，造成新增规则显示为`0 条`或遗漏备册。
5. 改动记录当前还需核对英文来源文案及多行布局；实现必须只做中文投影、单行省略和悬浮全文，不触碰历史记录的实际恢复数据。
6. 删除模式对纯本地规则/草稿走 `executeLocalOnlyDeletionPlan` 直执行，绕过了项目书要求的删除确认；本轮必须改为与远端删除共用一个确认弹窗，且不得因此扩大 B 站副作用。
7. 推荐采纳失败目前在 `useOldFavoriteWorkspace.ts` 被统一显示为“推荐收藏夹未能保存，请重试”，缺少真实可操作原因；本轮必须保留权威回滚并传递安全的底层失败信息。
