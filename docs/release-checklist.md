# 打包前体验验收清单

这份清单用于每次打包或发布 bilimi Windows 安装包前验收体验。目标不是让开发版和用户安装版在实现细节上完全一致，而是确认同一批关键操作在开发版、生产预览版和真实安装包中都能正常运行，并且响应感没有明显退化。

## 核心原则

- 用户最终使用的是安装包，最终验收以真实安装后的应用为准。
- 不要只用 `npm run dev` 的结果判断发布质量。
- Codex 的 in-app browser/browser 插件在本机可能导致 Codex 闪退；发布验收不要依赖它，按 `docs/codex-browser-bypass.md` 使用应用窗口、外部工具或人工核验完成。
- 每个超过 100ms 的操作都应该有可感知反馈；超过 500ms 的操作必须有状态提示；超过 2s 的操作不能阻塞用户继续使用其他区域。
- 开发版不卡、安装包卡是高风险信号，必须优先排查资源路径、外部工具、首次初始化、权限和杀软扫描。
- 开发版卡、安装包不卡可以记录原因，但不要把开发环境开销误判为用户问题。

## 必跑命令

```bash
npm test
npm run build
npm run preview
npm run dist:win
```

`npm run dist:win` 完成后，必须安装 `dist/` 中生成的安装包，并用安装后的应用完成下面的关键路径验收。

## 三种形态都要验收

- 开发版：`npm run dev`
- 生产预览版：`npm run build` 后运行 `npm run preview`
- 用户安装版：安装 `dist/` 中生成的 Windows 安装包后运行

同一套操作要在三种形态中各跑一遍。若三者行为不同，需要记录差异并判断是否影响用户。

## 关键路径

- 冷启动到主界面。
- 打开 B站首页和视频页。
- 多标签新建、切换、关闭和刷新。
- 右侧助手打开、关闭、切换 `批阅`、`札记`、`掌库`、`设置`。
- 小咪悬浮窗唤醒主窗口、拖动、打开助手、触发快捷入口。
- 当前视频的点赞、投币、收藏、短评草稿等批阅动作。
- 创建视频笔记、复制笔记、保存笔记、查看归档。
- 收藏夹创建、保存草稿、同步、旧收藏扫描预览。
- 设置项保存和重启后恢复。
- DeepSeek 未配置、配置错误、配置正确三种状态。
- DeepSeek 密钥显示“系统加密保护”或“本地明文保存”的真实状态；确认自定义服务地址的信任边界和 HTTP 明文传输风险符合本次发布预期。
- 音频下载和本地转写的开始、进度、取消、失败、重试、完成，以及重启后未完成队列恢复。
- webview 首次崩溃自动恢复、短时间重复崩溃停止循环并显示手动重新加载入口。
- 网络慢、未登录、登录过期、B站页面结构异常时的降级反馈。

## Electron 重点风险

- `window.bilimiDesktop` 暴露的 preload API 在安装包中不能变成 `undefined`。
- 每个按钮背后的 IPC 调用都要有成功反馈或失败提示。
- 打包后的 `yt-dlp.exe`、`ffmpeg.exe`、`ffprobe.exe`、`whisper.cpp`、`ggml-small.bin` 必须存在且路径正确。
- 外部工具失败不能拖死主窗口、webview、侧边栏或小咪悬浮窗。
- webview 切换、页面注入脚本、窗口拖动和视频播放不能出现明显卡顿。

## 干净环境验收

每次重要发布至少做一次干净环境测试：

- 清空旧配置和缓存，或使用新的 Windows 用户。
- 首次启动应用。
- 首次打开设置。
- 首次登录 B站后刷新当前状态。
- 首次保存 DeepSeek API key。
- 首次执行音频转写。

干净环境中发现的问题优先级高于开发机复测结果。

## 录屏基线

每次发包前录制一段固定流程，建议 3 到 5 分钟：

- 启动应用。
- 打开一个视频。
- 打开助手并切换功能区。
- 执行一次批阅动作。
- 创建或复制一条笔记。
- 打开小咪并触发快捷入口。
- 开始一次转写任务。
- 关闭并重开应用。

后续版本对比这段流程，用来发现新增卡顿、反馈丢失、状态恢复异常和安装包特有问题。

## 发布判定

只有满足以下条件，才可以认为打包体验通过：

- 测试、构建、预览和 Windows 打包命令都成功。
- 三种形态的关键路径都完成验收。
- 安装包中外部媒体工具和模型文件可用。
- 长操作都有明确状态反馈，失败路径能恢复。
- 干净环境没有首启、设置、登录、转写相关阻断问题。
- 已记录或修复开发版与安装包之间的所有用户可感知差异。
